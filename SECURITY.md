# Security Policy

## Supported versions

Security fixes are provided for the current production service and the latest
published `codex-usage-profile` npm release. Older package versions and
unreleased forks are not supported.

| Surface | Supported |
|---|---|
| Current production service | Yes |
| Latest published npm release | Yes |
| Older releases and forks | No |

## Report a vulnerability

Please do not disclose a suspected vulnerability in a public issue, discussion,
pull request, or social post.

Use [GitHub Private Vulnerability Reporting](https://github.com/postmelee/codex-usage-profile/security/advisories/new) to submit a private report to the maintainer.

Include as much of the following as you can:

- The affected component, route, package version, or commit
- The security impact and who could be affected
- Reproduction steps or a minimal proof of concept
- Relevant logs or screenshots with secrets and personal data removed
- Any workaround or mitigation you have identified

Please test only with accounts, profiles, and data you own or are authorized to
use. Do not access, modify, or retain another person's data while investigating.

## What to expect

The maintainer will review the report, may ask for more information, and will
coordinate remediation and disclosure when appropriate. Response and fix times
depend on the report's impact, complexity, and reproducibility; this policy does
not promise a specific service-level deadline.

Please keep vulnerability details private until the maintainer confirms that
coordinated disclosure is appropriate.
