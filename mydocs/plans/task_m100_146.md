# Task #146 수행계획서 — 라이트 카드 Border Beam 테마 대비 보정

GitHub Issue: [#146](https://github.com/postmelee/codex-usage-profile/issues/146)
마일스톤: M100

## 목적

라이브 프로필 미리보기의 라이트 카드에서 Border Beam 애니메이션이 흰색 배경과 섞여 약하게 보이는 문제를 해결한다. 라이트 카드에는 라이브러리의 라이트 테마 대비를 적용하되, 다크 카드의 색상·동작과 카드 크기 및 전체 이미지 비율은 그대로 유지한다.

Task #146을 병합한 뒤 보류 중인 릴리스 Task #144가 새 exact-main 후보를 다시 고정하고 Stage5 검증과 production 배포를 이어갈 수 있도록 검증 근거와 인계 조건도 남긴다.

## 배경

Task #144의 Stage5 합성 스모크 중 라이트 카드의 애니메이션 대비가 약하다는 문제가 발견되었다. 현재 `CardImageFrame`은 정규화된 카드 테마를 `data-card-theme`에 반영하지만, 이를 감싸는 `BorderBeam`은 `theme` 속성을 받지 않아 컴포넌트 기본값인 다크 테마를 사용한다. 그 결과 라이트 카드에도 흰색 계열 Beam이 그려져 카드 배경과 구분하기 어렵다.

Task #39에서 웹과 GIF가 공유하는 애니메이션 프리셋은 `4.8초 / ocean / brightness 1.05 / md / strength 0.82`로 고정되었다. 이번 문제는 프리셋 값 자체가 아니라 라이브 웹 컴포넌트의 테마 소유권 전달 누락으로 판단한다. 따라서 공유 프리셋이나 GIF 렌더러를 변경하지 않고, 라이브 미리보기에서 카드와 Beam이 같은 정규화 테마를 사용하도록 보정하는 것이 우선이다.

## 범위

### 포함

- `MarketingCardPreview`에서 카드 테마를 한 번 정규화하고 `BorderBeam`과 `CardImageFrame`에 동일한 값으로 전달
- 라이트 카드가 라이브러리의 라이트 테마 Beam 색상·그림자 대비를 사용한다는 소스/브라우저 계약 검증
- 다크 카드의 Beam 프리셋, 계산 스타일과 동작이 기존과 동일하다는 회귀 검증
- 라이트·다크 카드 모두 이미지 원본 크기 `1497×918`, 표시 비율 `499:306`, 프레임 크기·곡률이 동일하다는 검증
- 카드 테마 전환 중 기존 노드 유지, 로딩 handoff, reduced-motion 비활성화 계약 회귀 검증
- Task #144 재개 시 새 병합 커밋을 exact-main 후보로 다시 고정해야 한다는 인계 기록

### 제외

- Animated GIF golden asset, GIF 캡처·합성 렌더러 및 공유 애니메이션 프리셋 변경
- 카드 PNG/SVG 또는 소셜 미리보기 렌더러 변경
- `4.8초 / ocean / brightness 1.05 / md / strength 0.82` 기본값과 카드 기하·레이아웃 변경
- 카드 설정 스키마, 저장 API, 공개/비공개 정책 변경
- Task #146 브랜치에서 Stage5 원격 환경 또는 production 배포 변경
- npm 패키지 릴리스

## 설계 방향

- `MarketingCardPreview`에서 `normalizeCardTheme(cardTheme)` 결과를 단일 지역 값으로 만들고 `BorderBeam.theme`과 `CardImageFrame.cardTheme` 양쪽에 전달한다. 표시 카드와 효과가 서로 다른 테마를 해석할 수 없게 한다.
- 1차 수정은 `BorderBeam`의 내장 라이트/다크 테마를 정확히 선택하는 데 한정한다. 공유 `PROFILE_CARD_BORDER_BEAM_PRESET`은 변경하지 않는다.
- 라이트 테마만 추가 강화해야 하는지는 로컬 production build 시각 검증 결과로 판단한다. 테마 전달만으로 수용 기준을 충족하지 못하면 임의 조정하지 않고 작업을 중지한 뒤, 공유 프리셋과 분리된 라이트 전용 보정 범위를 작업지시자에게 다시 승인받는다.
- 다크 테마는 기존 기본 다크 프리셋과 동일한 속성 및 계산 스타일을 유지해야 한다. 라이트 수정의 부수 효과로 다크 Beam의 색상, 밝기, 채도, 속도, 크기, 강도를 바꾸지 않는다.
- 카드 이미지와 외곽 프레임의 DOM 구조 및 CSS 기하는 변경하지 않는다. 자동화 검증에서 라이트·다크의 원본 크기, 종횡비, 외곽 프레임 치수를 직접 비교한다.
- Task #146에서는 로컬 production build로 시각 QA를 완료한다. #144가 이미 고정한 exact-main 후보를 벗어난 원격 Stage5 변경은 하지 않으며, #146 PR 병합 뒤 #144에서 후보 재고정·main 승격·Stage5 재배포·원격 QA를 다시 수행한다.

## 잠정 단계

- **Stage 1 — Beam 테마 소유권 연결과 계약 고정**
  - 카드 테마를 한 번 정규화해 `BorderBeam`과 `CardImageFrame`에 함께 전달한다.
  - 소스 계약 테스트로 명시적 테마 전달, 공유 프리셋·기하 비변경을 고정한다.
- **Stage 2 — 라이트·다크 시각 및 상호작용 동등성 검증**
  - 로컬 production build에서 라이트 Beam 대비와 다크 회귀를 비교한다.
  - 양쪽 카드의 `1497×918`, `499:306`, 프레임 치수·곡률 동등성과 테마 전환 handoff, reduced-motion을 검증한다.
  - 라이트 대비가 여전히 부족하면 추가 튜닝을 진행하지 않고 작업지시자 승인 지점으로 되돌아간다.
- **Stage 3 — 전체 회귀 검증과 릴리스 인계**
  - 전체 단위·E2E·production build 검증을 수행한다.
  - GIF·카드·소셜 출력 범위 비변경과 #144의 exact-main 후보 재고정 필요를 최종 보고서에 기록하고 PR을 준비한다.

## 검증 계획

### 단계별 검증

- Stage 1
  - `node --test src/profile-ui/__tests__/themeSurfaceContract.test.js`
  - `git diff -- src/profile-card/gif-animation.js`
  - 소스 검사로 `BorderBeam`과 `CardImageFrame`이 같은 정규화 테마를 전달받는지 확인
- Stage 2
  - `npx playwright test tests/profile-ui.spec.js --grep "card|theme|motion|appearance"`
  - 로컬 production build 브라우저에서 라이트·다크 Beam의 의사 요소 계산 스타일과 캡처 비교
  - 라이트·다크 각각 이미지 원본 `1497×918`, CSS `aspect-ratio: 499 / 306`, 프레임 bounding box·곡률 비교
  - `prefers-reduced-motion: reduce`와 최신 draft 이미지 handoff 시 Beam 노드·비활성 상태 확인
- Stage 3
  - `npm test`
  - `npm run test:e2e`
  - `npm run build:production`
  - `npm run verify:sites-production`

### 통합 검증

- 라이트 카드에서 Beam이 흰색 배경과 시각적으로 구분되며, 다크 카드의 기존 표현은 변하지 않는다.
- 라이트·다크 카드의 이미지 크기, 종횡비, 프레임 크기와 나머지 레이아웃이 동일하다.
- 애니메이션의 `4.8초 / ocean / brightness 1.05 / md / strength 0.82` 공유 프리셋과 GIF golden 경로가 변경되지 않는다.
- 테마 전환 handoff와 reduced-motion 접근성 계약이 유지된다.
- #146에서는 원격 Stage5를 변경하지 않으며, 병합 후 #144가 새 exact-main을 기준으로 Stage5 및 production 절차를 재개한다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **라이트 내장 테마만으로 대비가 부족할 가능성**: Stage 2에서 실제 계산 스타일과 캡처로 판단한다. 부족하면 공유 프리셋을 건드리지 않고 라이트 전용 보정안을 별도 승인받는다.
- **다크 표현 회귀**: 수정 전후 다크 속성과 의사 요소 계산 스타일을 비교하고, 다크/라이트 동일 기하 검증을 자동화한다.
- **테마 전환 중 효과와 이미지 불일치**: 정규화 값을 단일 소유권으로 묶고 기존 decoded-preview handoff 테스트에 Beam 테마 검증을 추가한다.
- **Task #144 후보 드리프트**: #146 브랜치에서 원격 Stage5를 변경하지 않는다. 병합 뒤 #144가 exact-main 후보를 새로 고정하고 main 승격 및 배포 검증을 다시 수행한다.
- **선택자 또는 계산 스타일 테스트의 취약성**: 라이브러리 내부 구현 전체를 복제하지 않고 공개 속성, 핵심 색상 계열, 애니메이션 활성 상태와 기하 계약만 검증한다.

## 승인 요청 사항

- 라이브 미리보기에서 카드와 Border Beam이 동일한 정규화 테마를 사용하도록 하는 설계
- 공유 GIF 프리셋, GIF 렌더러, 카드·소셜 렌더러, 카드 크기·비율을 변경하지 않는 범위
- 내장 라이트 테마만으로 부족할 때 임의 보정하지 않고 라이트 전용 추가 튜닝을 별도 승인받는 결정 게이트
- Task #146에서는 로컬 production build QA까지만 수행하고, 원격 Stage5·production 검증은 병합 후 Task #144에서 새 exact-main 기준으로 재개하는 인계 순서

승인되면 `task_m100_146_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지를 구체화한다.
