# Task #96 수행계획서 — 테마 전환 텍스트와 Skeleton 팔레트 정합성 보정

GitHub Issue: [#96](https://github.com/postmelee/codex-usage-profile/issues/96)
마일스톤: M100

## 목적

Profile 이름과 Home Quickstart·step heading처럼 상위 요소의 inherited color에 의존하는 텍스트가
dark/light 전환 종료 뒤 늦게 snap하거나 깜빡이는 회귀를 제거한다. 관련 text surface에 semantic
color ownership을 명시해 같은 theme transition window 안에서 자연스럽게 전환되도록 한다.

page/profile loading Skeleton은 현재 site theme의 light/dark palette를 따르고, 실제 카드 이미지를
대체하는 내부 Skeleton은 선택된 card theme를 따르도록 책임을 분리한다. 기존 theme preference,
system theme, card appearance 독립성과 reduced-motion·loading geometry 계약은 유지한다.

## 배경

- 실제 모바일 Safari에서 Profile의 이름, Home의 `Quickstart`, `Approve your device` 등이 다른
  surface 전환 뒤 별도로 색을 바꾸는 현상이 측정됐다.
- 현재 `data-theme-animating`은 모든 요소에 transition을 강제하지만 일부 heading은 명시적
  `color` 없이 부모의 색을 상속한다. inherited computed color가 부모·자식에서 다른 시점에
  교체되는지 Chromium·WebKit에서 재현해야 한다.
- `ProfileLoadingSkeleton`의 page placeholder가 `--card-preview-placeholder-subtle`을 사용해 light
  site theme에서도 dark-card용 검정 계열 shimmer를 표시한다.
- 공용 `.home-card-skeleton`은 Home·Profile·public card intro·Share Studio·설정 preview에서
  재사용되므로 page theme와 card theme의 소유권을 selector/token 기준으로 전수 점검해야 한다.
- 이 이슈는 #84 Gate C와 공개 마케팅을 차단하는 M100 release blocker다. 선행 #95 PR과 독립된
  최신 devel 브랜치에서 작업하며, 작업지시자 요청대로 실제 배포 없이 별도 PR을 게시한다.

## 설계 방향

- 문제 text surface는 의미에 맞는 `--text-primary`·`--text-secondary`·`--text-tertiary`를 직접
  소유한다. 전역 강제 transition에 예외를 계속 추가하지 않고, inherited color 경계를 source
  contract로 목록화한 뒤 필요한 selector만 최소 보정한다.
- site theme Skeleton token과 card theme Skeleton token을 분리한다. page placeholder는 `:root`와
  `:root[data-theme="dark"]`의 site token을 사용하고, card placeholder는 card media가 전달하는
  light/dark context를 사용한다.
- Home의 기본 owner/operator preview와 설정/Share Studio가 명시하는 card theme를 DOM attribute
  또는 기존 variant selector로 연결한다. 새 API·storage·renderer state는 만들지 않는다.
- Skeleton geometry, readiness, crossfade와 shimmer duration은 변경하지 않는다. reduced-motion에서는
  기존처럼 shimmer와 불필요 transition이 제거되어야 한다.
- 실제 모바일 확인은 PR 게시 뒤 작업지시자 merge Gate로 남긴다. #95와 #96 모두 merge 전 배포하지
  않고, 두 PR merge 뒤 별도 동시 배포 요청을 기다린다.

## 잠정 단계

- **Stage 1 — text·Skeleton ownership audit와 회귀 재현**
  - inherited text와 page/card Skeleton selector·token matrix를 고정한다.
  - Chromium·WebKit computed style 이력과 light Skeleton known failure를 재현한다.
- **Stage 2 — semantic text color ownership 보정**
  - Profile·Home 및 audit에서 확인한 related text에 semantic color를 직접 부여한다.
  - system/light/dark와 reduced-motion transition timing을 검증한다.
- **Stage 3 — site/card Skeleton palette 분리**
  - page Skeleton은 site theme, card Skeleton은 card theme를 따르게 token/context를 분리한다.
  - light/dark 조합별 placeholder·sheen·geometry·readiness 회귀를 검증한다.
- **Stage 4 — 통합 검증과 비배포 로컬 확인 handoff**
  - 전체 Node·Playwright·production build·artifact·local smoke를 실행한다.
  - 실제 모바일 Safari·Chrome merge Gate와 배포 미수행 상태를 최종 보고서·PR에 기록한다.

## 검증 계획

### 단계별 검증

- Stage 1
  - CSS/source ownership contract 테스트
  - Chromium·WebKit theme transition computed color 이력
  - page light/dark × card light/dark Skeleton baseline
- Stage 2
  - Profile 이름, Home Quickstart·전체 step heading transition duration/property와 중간색 측정
  - system/light/dark·reduced-motion Chromium·WebKit
- Stage 3
  - owner/public Profile, Home, public card intro, Share Studio, settings preview Skeleton palette matrix
  - 기존 loading→ready geometry·readiness·shimmer/reduced-motion E2E
- Stage 4
  - `npm test -- --test-concurrency=1`
  - `npm run test:e2e`
  - `npm run build:production`
  - `npm run verify:sites-fullstack`
  - `npm run smoke:sites-fullstack:local`
  - `git diff --check`

### 통합 검증

- 관련 텍스트가 theme transition 종료 뒤 별도로 snap하거나 깜빡이지 않는다.
- page light/dark와 card light/dark가 독립적으로 올바른 Skeleton palette를 선택한다.
- Home·owner/public Profile·public card intro·Share Studio의 geometry·readiness 계약이 유지된다.
- system preference와 reduced-motion 계약이 유지된다.
- 실제 배포 명령을 실행하지 않고 PR 게시 뒤 실제 모바일 merge Gate를 제공한다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **전역 transition 과보정**: 모든 heading에 포괄 selector를 추가하면 의도하지 않은 상태색까지
  transition될 수 있다. audit된 semantic selector만 직접 소유시키고 computed property로 검증한다.
- **site/card theme 혼선**: 같은 Skeleton 컴포넌트가 page와 card 안에서 중첩된다. page token과 card
  variant token을 이름·selector로 분리하고 light/dark 교차 matrix로 증명한다.
- **WebKit timing 차이**: 매우 짧은 snap은 일반 screenshot이 놓칠 수 있다. transitionrun/end와
  requestAnimationFrame sampling을 page init script에서 수집한다.
- **#95 독립성**: #96은 현재 origin/devel에서 시작하므로 #95 source를 포함하지 않는다. 두 PR의
  동일 test/orders 파일 변경은 merge 순서에서 conflict 가능성을 확인하되 제품 로직을 섞지 않는다.
