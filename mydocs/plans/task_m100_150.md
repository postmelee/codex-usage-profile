# Task #150 수행계획서 — PNG·GIF 첨부 내보내기의 투명 모서리 제거 및 998×612 규격 통일

GitHub Issue: [#150](https://github.com/postmelee/codex-usage-profile/issues/150)
마일스톤: M100

## 목적

Share Studio에서 저장한 PNG와 GIF를 X에 직접 첨부할 때 카드의 투명한 둥근 모서리와 플랫폼 자체 이미지 반경 사이에 흰 여백이 나타나는 문제를 해결한다. Codex App 공식 저장 PNG에서 확인한 `998×612 / 499:306 / 전 픽셀 alpha 255` 계약을 첨부용 출력에 적용한다.

첨부 출력만 불투명하게 바꾸고 카드의 논리 좌표, 내부 배치, 종횡비와 GIF 모션은 그대로 유지한다. 기존 README stable PNG와 Open Graph 소셜 PNG는 서로 다른 소비 목적과 캐시 계약을 가지므로 변경하지 않는다.

## 배경

Task #39는 데스크톱 Share Studio의 브라우저 전용 GIF를 `998×612`, 20fps, 96프레임, 4.8초, 무한 반복으로 만들면서 카드 바깥을 투명하게 고정했다. PNG 저장은 별도 첨부 파일을 생성하지 않고 `/u/{handle}/card.png`의 `1497×918` stable 이미지를 직접 내려받는다. 두 출력 모두 원본 둥근 모서리 밖에 투명 픽셀이 있으므로 X의 자체 클리핑 반경이 카드 반경보다 작을 때 그 차이가 흰색 초승달 형태로 노출된다.

작업지시자가 제공한 Codex App 저장 PNG를 픽셀 단위로 확인한 결과, 파일은 `998×612`이고 종횡비가 현재 카드와 같은 `499:306`이었다. PNG 형식은 alpha 채널을 포함하지만 alpha 최솟값과 최댓값이 모두 255이고, 네 모서리는 `rgba(24, 24, 24, 255)`였다. X는 이 불투명 사각 이미지를 표시 단계에서 자체 border radius로 잘라 흰 모서리가 생기지 않는다.

Task #141은 `2400×1260` Open Graph 라이트 소셜 이미지에만 `#F3F5F7` 배경과 `#D0D7DE` 경계를 적용했고, Task #146은 다크·라이트가 동일한 Border Beam geometry와 모션을 사용하면서 라이트 색상·대비만 강화했다. Stage 1~3에서는 이 surface와 motion 계약을 첨부용 PNG/GIF에도 연결했지만, 실제 X·Reddit 첨부 검수에서 플랫폼 자체 clipping과 파일 내부 outline·radius가 중첩되어 부자연스럽게 보이는 문제가 확인되었다. 2026-09-02 작업지시자 승인에 따라 Stage 4에서 첨부 PNG와 GIF의 소비 목적을 다시 분리한다.

## 범위

### 포함

- 첨부용 공통 canvas를 `499×306` logical, 2배 출력인 `998×612`로 정의
- 원본 카드가 첨부 canvas 전체를 차지하게 하여 추가 padding, crop 또는 content transform 없이 합성
- 다크 첨부 canvas의 투명 영역을 카드 배경과 같은 `#181818`로 채워 전 픽셀을 불투명하게 생성
- 라이트 저장 PNG의 투명 영역을 카드 배경과 같은 `#FFFFFF`로 채우고 별도 outline·radius를 기록하지 않아 SNS가 최종 clipping을 소유하게 함
- Share Studio PNG 저장을 stable README 이미지 직접 다운로드와 분리하고 브라우저에서 생성한 첨부용 PNG Blob을 저장
- GIF Worker 입력을 동일한 첨부 surface로 합성하고 encoder가 투명 palette index 없이 불투명 frame을 기록하도록 변경
- PNG/GIF가 같은 dimension·surface·geometry 계약을 소비하도록 공통 상수와 합성 경계를 단일 소유권으로 정리
- PNG Blob의 stale source 취소, object URL revoke, 오류 복구와 기존 GIF job lifecycle 회귀 검증
- GIF export preset version을 출력 계약 변경에 맞춰 갱신하고 session cache가 이전 결과를 재사용하지 않게 함
- GIF의 effect perimeter를 X 첨부 표시 기준인 출력 반경 `32px`로 맞추고, dark/light 모두 동일한 96 phase·속도·색상 로직을 유지한 Chrome golden을 재생성
- dark/light PNG/GIF의 dimensions, alpha, corner RGBA, content bounds와 GIF effect radius·phase·seam 자동 검증
- 대표 dark/light PNG/GIF 생성물의 수동 시각 QA와 작업지시자 검수
- 첨부 출력과 stable README/OG 출력의 차이를 `docs/readme-card.md`에 최소 반영

### 제외

- `/u/{handle}/card.png`의 `1497×918`, 투명 모서리, ETag, stable URL과 publication 계약 변경
- `/u/{handle}/social.png`의 `2400×1260` canvas, padding, 테마별 surface와 Open Graph metadata 계약 변경
- 카드 내부 여백, avatar, heatmap, 통계, typography, palette 또는 locale 변경
- 라이브 카드의 크기, radius, Border Beam 경로·속도·색상·강도 변경
- 라이브 카드의 Border Beam radius와 dark/light 96 phase 순서·기존 4.8초 motion 변경
- Reddit 등 X와 다른 clipping 정책에 맞춘 별도 플랫폼별 파일 또는 export UI 추가
- 서버 저장 GIF endpoint, D1/R2 schema, X API 업로드와 자동 게시
- 모바일 GIF UI 추가
- production 배포와 원격 Site saved version 변경

## 설계 방향

- 첨부 출력은 README 카드와 OG 소셜 이미지에 이은 세 번째 명시적 출력 계약으로 둔다. `attachment` 계약만 `998×612` 완전 불투명이고, stable README와 OG 계약은 기존 renderer와 URL을 그대로 사용한다.
- logical geometry는 기존 `499×306`을 단일 기준으로 유지한다. stable `1497×918` source를 사용할 때도 첨부 canvas의 `998×612` 전체에 정확히 대응시키며 추가 여백이나 내부 재배치를 허용하지 않는다.
- 투명도를 없애기 위해 X의 표시 반경을 추측하지 않는다. 먼저 theme surface로 출력 canvas 전체를 채우고 기존 rounded card를 같은 bounds에 합성한 뒤, 플랫폼이 최종 표시 반경을 소유하게 한다.
- 다크는 바깥 surface와 카드 배경이 모두 `#181818`이므로 원본 파일은 불투명 사각형이 되고 X에서 자연스럽게 잘린다. 라이트 저장 PNG도 카드 배경과 같은 `#FFFFFF`로 바깥을 채우고 별도 outline을 그리지 않아 각 SNS의 clipping이 파일 내부 경계와 충돌하지 않게 한다.
- PNG와 GIF runtime adapter가 달라도 dimension, theme surface와 outline 계산은 공통 모듈에서 가져온다. PNG는 저장 요청 시 짧게 생성하는 Blob으로 만들고, GIF는 기존 Worker·진행률·취소 경로를 유지한다.
- GIF encoder는 투명 픽셀 존재를 전제로 한 validation과 고정 transparent index를 제거하되 global palette, dithering 없음, 15MB 상한과 effect 합성은 유지한다. 출력 GIF를 다시 디코딩해 모든 frame이 불투명인지 검증한다.
- GIF motion은 Task #146의 20fps·96 phase·4.8초·색상 대비를 유지하되, X가 첨부 이미지에 적용하는 표시 반경을 작업지시자 제공 화면에서 출력 좌표 약 `32px`로 측정해 effect perimeter만 다시 캡처한다. PNG에는 이 반경을 기록하지 않으며 GIF에서만 애니메이션 경계를 X clipping과 정렬한다.
- 하나의 GIF가 X의 rounded clipping과 Reddit의 square clipping에 동시에 정확히 일치할 수는 없다. 이번 task는 작업지시자 승인에 따라 X를 canonical 대상으로 하고 Reddit은 같은 불투명 사각 GIF의 best-effort 표시로 문서화한다.
- Share Studio의 이미지 URL 복사와 README 복사는 stable card URL을 계속 제공한다. 오직 `Save PNG`와 `Save GIF`만 첨부용 Blob을 사용하며 dialog close, source revision·theme·locale 변경 시 오래된 Blob을 폐기한다.

## 문서 위치 판단

첨부용 PNG/GIF 규격은 Share Studio 사용자가 파일을 저장하고 외부 서비스에 직접 첨부하는 공개 사용 계약이다. 기존 카드·GIF 사용자 문서의 소유 위치가 `docs/readme-card.md`이므로 새 문서를 만들지 않고 해당 파일을 최소 수정한다. 구현 계획, 단계 보고와 검증 근거는 내부 작업 산출물이므로 `mydocs/`에 둔다.

| `docs/readme-card.md` | 공식 사용자 문서 | 카드·Share Studio 사용자 | `docs/` | `mydocs/` | 기존 stable PNG, OG 이미지와 GIF 저장 계약을 이미 설명하는 공식 문서이므로 첨부 출력 차이를 같은 위치에 기록 |

## 잠정 단계

- **Stage 1 — 첨부 canvas 계약과 PNG 저장 분리**
  - 공통 `998×612` dimension, theme surface, outline과 불투명 alpha 계약을 정의한다.
  - Share Studio의 Save PNG를 stable URL에서 분리해 첨부용 Blob을 생성·저장하고 lifecycle을 검증한다.
  - dark/light representative PNG를 생성해 geometry와 모서리 surface를 작업지시자에게 제시한다.
- **Stage 2 — 불투명 GIF encoder와 모션 동등성**
  - GIF Worker가 공통 첨부 surface를 사용하고 encoder가 투명 index 없이 96개 불투명 frame을 기록하게 한다.
  - 기존 dark/light golden, motion phase, 색상 대비, seam, 크기와 15MB 상한을 대조한다.
  - 같은 source에서 PNG와 GIF의 정지 base geometry가 일치하는지 검증하고 representative GIF를 작업지시자에게 제시한다.
- **Stage 3 — Share Studio·문서·전체 회귀**
  - PNG/GIF 저장, 취소·재시도·source/theme/locale 전환과 Blob 정리를 E2E로 검증한다.
  - stable README PNG와 OG social PNG가 변경되지 않았음을 확인하고 공식 사용자 문서를 최소 갱신한다.
  - 전체 Node·Playwright·production artifact 검증과 최종 수동 X 첨부 확인용 산출물을 준비한다.
- **Stage 4 — SNS-native PNG와 X 기준 GIF 경계 보완**
  - 라이트 저장 PNG에서 `#F3F5F7` 바깥 surface와 `#D0D7DE` outline을 제거하고 카드 배경 `#FFFFFF`만 사용한다.
  - GIF effect perimeter를 출력 반경 `32px`로 재생성하고 preset을 v4로 올리되 96 phase·20fps·4.8초·테마별 색상 로직은 유지한다.
  - dark/light PNG·GIF 시제품으로 content geometry 무변경, PNG 무경계, X GIF 경계 정렬과 stable/OG 무회귀를 다시 검증한다.

## 리스크

- **출력 계약 혼선**: attachment, stable README, OG social 세 계약의 상수와 호출 경계를 명시하고 각각의 크기·alpha 회귀를 독립 테스트한다.
- **플랫폼별 clipping 차이**: 저장 PNG는 파일 내부 경계를 제거해 플랫폼에 clipping을 위임하고, GIF는 X 반경 `32px`를 canonical로 고정한다. Reddit의 square 표시에 대한 완전 일치는 별도 export가 필요하므로 이번 범위에서는 best-effort로 둔다.
- **PNG 비동기 저장 UX 회귀**: 빠른 생성 중 중복 클릭을 방지하고 실패 시 재시도 가능하게 하며, dialog/source 변경 때 stale Blob과 object URL을 정리한다.
- **GIF palette·용량 변화**: transparency index 제거 뒤 global palette와 무디더링을 유지하고 대표 avatar를 포함한 양쪽 테마를 15MB 상한으로 검증한다.
- **GIF effect 반경 변경이 모션을 바꿀 가능성**: Chrome capture의 경계 반경만 `64px`에서 `32px`로 바꾸고 동일 duration·phase·테마 preset으로 dark/light golden을 함께 재생성한다. 사분면 순서와 seam을 자동 대조한다.
- **브라우저별 canvas encoding 차이**: 기존 지원 capability 경계 안에서 PNG/GIF를 생성하고 Node 단위 테스트와 Playwright 실제 브라우저 결과를 함께 검증한다.
- **기존 캐시 재사용**: preset version과 source key를 갱신하고 이전 transparent GIF Blob이 새 계약에서 재사용되지 않는지 확인한다.
- **stable/OG renderer 회귀**: 해당 renderer와 라이브 Border Beam을 변경 금지 대상으로 두고 기준 크기·alpha·source hash 검증을 포함한다.
