# Task M100 #23 수행계획서

GitHub Issue: [#23](https://github.com/postmelee/codex-usage-profile/issues/23)
마일스톤: M100

## 목적

`packages/codex-usage-analyzer/`로 준비된 analyzer SDK/CLI를 standalone GitHub repository로 분리한다. 완료 상태는 `postmelee/codex-usage-analyzer` 저장소가 생성되어 독립적으로 clone, test, CLI smoke 실행이 가능하고, `codex-usage-profile`에는 후속 의존성 전환 방향이 명확히 남아 있는 상태다.

이번 task는 analyzer를 별도 제품/패키지로 관리하기 위한 저장소 경계를 만드는 작업이다. `tokenmon` 같은 후속 웹 프로젝트가 analyzer를 SDK로 감싸 자체 submit CLI를 만들 수 있게 하는 기반을 마련한다.

## 배경

#20에서 analyzer 책임은 workspace package로 분리되었지만 아직 `codex-usage-profile` 저장소 내부에 있다. 이 상태에서는 profile 웹 서비스, README card renderer, 향후 카드형 서비스가 모두 같은 monorepo 구조에 묶인다.

M100 MVP에서는 `profile submit CLI`가 analyzer가 생성한 `UsageSnapshot v2`를 업로드하는 흐름을 목표로 한다. analyzer는 GitHub 로그인, avatar, bio, public profile URL 같은 GitHub-facing fields를 소유하지 않고, 로컬 usage source를 분석해 `UsageSnapshot v2`를 생성하는 범용 SDK/CLI로 유지해야 한다.

## 범위

### 포함

- `postmelee/codex-usage-analyzer` GitHub repository 생성
- 현재 `packages/codex-usage-analyzer/` 내용을 standalone repository root 구조로 이관
- standalone repo의 `package.json`, `README.md`, CLI entrypoint, SDK exports, tests가 독립 동작하도록 정리
- 새 repository에서 `npm test`와 CLI smoke test 통과 확인
- `codex-usage-profile` 쪽에는 standalone repository 생성 사실과 후속 dependency 전환 방향 문서화
- 현재 workspace package를 즉시 제거할지, npm publish 전까지 compatibility copy로 유지할지 판단 기록

### 제외

- npm publish 또는 release automation 완성
- `tokenmon` repository 생성과 카드 UI 구현
- `codex-usage-profile`의 submit CLI 전체 교체
- GitHub README card/image endpoint 구현
- GitHub OAuth, device-code, API token, device 관리 구현

## 설계 방향

- 새 repository는 `packages/codex-usage-analyzer/` 하위 구조를 root로 올린 clean initial import 방식을 기본으로 한다. monorepo의 내부 작업 문서까지 히스토리로 옮기지 않고, standalone package 사용자가 읽어야 하는 파일만 첫 커밋에 포함한다.
- `codex-usage-profile`의 workspace package는 이번 task에서 바로 제거하지 않는 방향을 우선한다. npm publish가 제외되어 있으므로 즉시 제거하면 profile repo 테스트와 후속 M100 작업이 외부 GitHub dependency나 네트워크 상태에 묶일 수 있다.
- 새 analyzer repository는 `UsageSnapshot v2` 생성과 validation을 소유한다. GitHub profile fields는 계속 web service 계층에서 병합한다.
- 외부 상태를 변경하는 작업은 명시 검증을 남긴다. `gh repo view postmelee/codex-usage-analyzer`로 repository 존재를 확인하고, 새 repository working tree에서 독립 테스트를 실행한다.
- 새 repository 생성 후 profile repo에는 migration note를 남겨, 후속 task에서 local workspace dependency를 npm package 또는 GitHub package dependency로 교체할 수 있게 한다.

## 잠정 단계

- **Stage 1 — standalone repository 분리 전략 확정**
  - 현재 analyzer package 파일, npm metadata, test/CLI entrypoint를 점검한다.
  - clean initial import와 subtree split 중 최종 방식을 확정하고 repo 생성 전 중복 존재 여부를 확인한다.
- **Stage 2 — standalone source tree 구성**
  - analyzer package를 standalone repo root 형태로 구성한다.
  - README, package metadata, CI, test 명령을 독립 repo 기준으로 정리한다.
- **Stage 3 — GitHub repository 생성과 초기 push**
  - `postmelee/codex-usage-analyzer` repository를 생성한다.
  - standalone tree를 초기 커밋으로 push하고 repository 접근성을 확인한다.
- **Stage 4 — profile repo 연동 방향 문서화**
  - `codex-usage-profile`에 standalone repo 생성 사실과 dependency 전환 계획을 기록한다.
  - workspace copy 유지/제거 판단과 후속 task 범위를 명확히 한다.

## 리스크

- **외부 repository 생성 실패**: 동일 이름 repository가 이미 있거나 권한이 부족할 수 있다. 생성 전 `gh repo view`로 존재 여부를 확인하고, 이미 있으면 덮어쓰지 않고 작업지시자에게 보고한다.
- **profile repo 테스트 안정성 저하**: npm publish 전 workspace package를 제거하면 profile repo가 외부 dependency에 묶일 수 있다. 이번 task는 standalone repo를 만들되 profile repo의 dependency 전환은 후속 task로 분리한다.
- **중복 소스 유지 비용**: standalone repo와 profile workspace copy가 일시적으로 중복될 수 있다. 문서에 canonical source와 전환 계획을 남기고, 후속 task에서 dependency 교체와 중복 제거를 처리한다.
- **network/권한 승인 필요**: GitHub repository 생성, push, 외부 경로에 standalone tree 생성은 네트워크와 파일시스템 권한 승인이 필요하다. 각 명령은 수행 시점에 명시 승인으로 진행한다.

## 승인 요청 사항

- `postmelee/codex-usage-analyzer`를 public standalone repository로 생성하는 방향을 승인해달라.
- 이번 task에서는 clean initial import를 기본 방식으로 사용하고, 기존 monorepo history 보존은 하지 않는 방향을 승인해달라.
- npm publish와 profile repo의 dependency 교체는 후속 task로 두고, 이번 task는 standalone repository 생성과 문서화까지로 제한하는 범위를 승인해달라.

승인되면 `task_m100_23_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지를 구체화한다.
