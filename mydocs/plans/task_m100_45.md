# Task M100 #45 수행계획서

GitHub Issue: [#45](https://github.com/postmelee/codex-usage-profile/issues/45)
마일스톤: M100

## 목적

공개된 `codex-usage-profile@0.1.0`과 canonical ChatGPT Sites production을
fresh 사용자 환경에서 연결해, 익명 landing부터 GitHub OAuth, browser session,
CLI device 승인, Account Usage Contract v1 submit, private preview,
publish/unpublish, public HTML·JSON·stable R2 card까지 전체 흐름을 release
기준으로 독립 검증한다.

기능 성공만 확인하지 않고 private-by-default, CSRF/origin, credential redaction,
D1/R2 cache와 일관성, backup/restore, retention, owner-only/maintenance rollback,
비용 0원 관찰과 stop trigger를 함께 판정한다. 최종 결과는 M100 MVP의 공개
홍보·release 진행 여부를 결정하는 PASS/BLOCKED 보고서로 남긴다.

## 설계 방향

- **권고안 A — canonical production 직접 QA**: 현재 public Site와 saved
  version 7, published CLI `0.1.0`을 그대로 사용한다. 작업지시자의 GitHub
  identity를 cleanup 가능한 disposable owner로 다시 만들되 fresh browser
  profile과 임시 CLI HOME/XDG/npm cache로 기존 session·credential을
  재사용하지 않는다. 실제 사용자가 접하는 artifact와 origin을 검증하므로
  별도 test Site보다 release 판정력이 높고 신규 resource나 추가 과금이 없다.
- **대안 B — 별도 owner-only test Site**: 사용자 데이터 격리는 쉽지만
  canonical public access, production OAuth callback, 실제 D1/R2와 stable URL을
  검증하지 못하고 새 Site/storage 운영 범위를 늘린다. blocker 재현이나 provider
  지원 요청 전에는 선택하지 않는다.
- **QA-first, no hotfix**: 이번 task는 검증 task다. blocker가 발견되면
  production에서 즉석 수정하지 않고 service를 승인된 safe state로 되돌린다.
  source/schema/package 수정이 필요하면 원인, 영향, 복구안을 먼저 보고하고
  수행·구현 계획 변경 또는 별도 issue 승인을 받은 뒤 진행한다.
- **fresh의 의미**: 별도 제3자 계정을 요구하지 않고 기존 owner record가 없는
  상태에서 새 OAuth state/session/device/token/usage/publication을 생성한다.
  브라우저와 CLI local state는 격리하며 기존 Task #44 credential을 재사용하지
  않는다.
- **Gate A — identity/data 생성과 Contract v1 전송**: exact origin, package
  version, GitHub owner/handle, 생성될 D1/R2 종류와 종료 상태를 제시한다.
  작업지시자가 Account Usage Contract v1 집계 전송과 disposable production
  owner/session/device/token/media 생성을 승인한 뒤에만 OAuth·submit을
  수행한다. prompt, response, Codex/OpenAI credential과 local session file은
  범위 밖이다.
- **Gate B — 짧은 운영 전환**: saved version 7 유지, 원복할 public access
  revision, service normal/environment revision, operator secret rotation,
  owner-only/maintenance 전환 순서와 예상 응답을 제시한다. 별도 승인 뒤에만
  public→owner-only→public 및 normal→maintenance→normal dry-run을 수행한다.
  각 전환은 즉시 health/access를 검증하고 실패 시 새 분석보다 원복을
  우선한다.
- **Gate C — export/restore와 exact cleanup**: fresh plan의 exact
  owner/handle, D1 record count, R2 object count, digest와 publication state가
  예상과 일치할 때만 repository 밖 `0600` export 후 delete→restore/repair와
  final delete를 수행한다. 불일치하면 mutation 없이 public/normal과
  maintenance disabled를 복원하고 중단한다.
- **export-before-mutation**: backup payload, path, session/token 원문과 private
  usage 값은 repository, command argument, tool output와 보고서에 기록하지
  않는다. 보고에는 schema/contract version, digest, count와 PASS/BLOCKED만
  남긴다.
- **public media 검증**: stable URL은 바꾸지 않고 quoted application ETag와
  content digest를 비교한다. private/missing/unpublished는 동일 `404`,
  provider 장애는 storage 정보를 숨긴 `503`이어야 한다.
- **security negative probe 최소화**: rate-limit과 abuse 검증은 기존 local
  concurrency suite를 우선하고 production에는 bounded 소량 probe만 사용한다.
  실제 서비스 방해나 quota 소진 가능성이 있으면 중단한다.
- **비용 stop**: 추가 plan, 결제수단, 자동 초과 과금, quota blocker가 보이면
  신규 submit/publication을 중단한다. 필요하면 Gate B 승인 범위에서
  owner-only/maintenance로 닫고 #43을 별도 승인 대상으로 넘긴다.
- **기존 작업 보호**: main worktree의 `local/task43`과
  `codex-extracted/`를 변경하지 않는다. #45는 최신 `origin/devel`에서 만든
  분리 worktree `local/task45`에서만 진행한다.

## 잠정 단계

- **Stage 1 — immutable release와 production baseline**
  - registry `0.1.0`, `latest`, tarball integrity, provenance/signature와 clean
    install을 재검증한다.
  - 전체 Node/E2E/build/Sites artifact/fallback 회귀와 public source scan을
    실행한다.
  - Site/version/access/linkage, anonymous landing/health/private 404,
    비용·quota·stop trigger를 read-only로 고정하고 Gate A 입력을 만든다.
- **Stage 2 — Gate A: fresh OAuth, device login과 private-by-default**
  - exact owner/handle, Contract v1 field, 생성 data와 cleanup 목표를 제시해
    승인을 받는다.
  - fresh browser GitHub OAuth/session/logout 경계와 published CLI
    device approve/exchange/status를 검증한다.
  - Contract v1 submit 뒤 private preview no-store와 anonymous
    HTML/JSON/card 404를 확인한다.
- **Stage 3 — submit idempotency와 보안 경계**
  - exact retry, stale/conflict, token revoke와 issuing-origin protection을
    확인한다.
  - same-origin browser mutation, cross-origin/CSRF 거부, response/header/client
    allowlist와 recent structured log redaction을 검증한다.
  - bounded rate-limit/stop probe와 local concurrency/failure suite를 연결해
    production abuse 없이 security 판정을 만든다.
- **Stage 4 — public profile, stable R2 card와 cache**
  - publish 뒤 canonical HTML, public JSON과 stable `en`/`ko` PNG의
    `GET|HEAD|304`, content type/cache/ETag를 검증한다.
  - public 상태에서 변경 submit 후 같은 URL과 새 digest/ETag, exact retry의
    안정성을 확인한다.
  - unpublish 뒤 HTML unavailable, JSON/card 404와 private preview no-store를
    재확인한다.
- **Stage 5 — Gate B/C: 운영 rollback, backup/restore와 cleanup**
  - Gate B 승인 뒤 saved version 7을 유지한 채 owner-only/public,
    maintenance/normal, operator route disabled와 secret rotation을
    순서대로 dry-run하고 매 전환을 원복한다.
  - retention 90일 dry-run과 protected stable/tombstone/revision 집합을
    확인한다.
  - Gate C의 exact owner/handle/digest/count가 일치할 때만 repository 밖
    export→delete→restore/repair→동일 digest/count→final cleanup을 수행한다.
- **Stage 6 — release decision, 문서 drift와 handoff**
  - 전체 자동 회귀와 anonymous final state를 재검증한다.
  - production을 public, service normal, maintenance disabled, test
    token/session/local credential 제거, disposable owner/public card 404로
    종료한다.
  - 발견된 공식 문서 drift만 수정하고 M100 공개·홍보 PASS/BLOCKED,
    잔여 위험, 비용 0원 관찰과 #43 trigger 여부를 최종 보고한다.

  - 공식 문서와 실제 npm/Sites/CLI/card 계약 diff
  - `git diff --check`

### 통합 검증

- fresh 사용자가 repository checkout 없이 public npm `0.1.0`과 canonical
  Site에서 GitHub OAuth→device 승인→Contract v1 submit→private preview→
  publish→공유→unpublish→logout/revoke를 완료한다.
- prompt, response, tool data, Codex/OpenAI/GitHub credential과 local session
  file은 전송·저장·로그되지 않는다.
- private/unpublished/missing profile과 card는 anonymous에게 같은 `404`이며
  private preview는 인증 뒤 on-demand/no-store다.
- public JSON은 allowlist만 반환하고 stable R2 card는
  `GET|HEAD|304`, locale와 application ETag/cache 계약을 유지한다.
- D1 latest usage는 owner당 한 건이고 exact retry가 중복 state를 만들지 않으며
  public accepted submit만 stable card ETag를 갱신한다.
- CSRF/origin, Bearer issuing-origin, rate-limit과 generic error가 identity,
  provider metadata 또는 credential을 노출하지 않는다.
- production export/restore, retention과 exact owner cleanup이 digest/count로
  재현되며 불일치 시 mutation 없이 fail closed한다.
- owner-only/maintenance/public/normal 전환은 saved version 7을 유지하고
  실패 시 즉시 직전 public/normal 상태로 복구된다.
- final production은 public, service normal, maintenance disabled,
  disposable owner/session/token/local credential과 public card가 제거된
  상태다.
- 추가 결제나 plan upgrade 요구가 없고 #43 trigger가 관찰되지 않으면
  ChatGPT Sites MVP를 계속 canonical production으로 판정한다.
- blocker가 하나라도 남으면 홍보·M100 release PASS를 선언하지 않고 exact
  stop/rollback 상태와 후속 수정 범위를 보고한다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **fresh user의 한계**: 작업지시자의 기존 GitHub 계정을 새 local
  session/owner로 사용하는 검증은 완전한 제3자 계정 다양성을 대신하지 않는다.
  기존 owner가 없고 browser/CLI state가 격리됐음을 증명하고 잔여 위험으로
  명시한다.
- **production data mutation**: OAuth·submit·publish는 실제 D1/R2를 바꾼다.
  Gate A에서 생성 범위와 종료 상태를 승인받고 Gate C에서 exact
  digest/count가 일치할 때만 cleanup한다.
- **운영 전환 중 짧은 중단**: owner-only/maintenance dry-run 동안 anonymous
  access나 backend가 잠시 닫힐 수 있다. Gate B에 exact 순서와 원복값을
  제시하고 public 상태에서 원인을 분석하지 않는다.
- **backup/restore 부분 실패**: export digest/count와 R2 manifest가 일치하지
  않으면 delete/restore를 시작하지 않는다. restore 뒤 일관성을 증명하지
  못하면 maintenance/owner-only safe state를 유지하고 별도 복구 승인을
  요청한다.
- **secret 노출**: Sites/OAuth/operator/session/CLI credential은 tool output,
  command argument, URL, source와 보고서에 기록하지 않는다. operator secret은
  각 전환에서 회전하고 검증 뒤 제거한다.
- **rate-limit 검증의 self-abuse**: production 부하 검증은 bounded 요청만
  사용하고 concurrency/failure 대부분을 local real-workerd suite로 대체한다.
- **immutable npm version**: `0.1.0` 결함은 같은 version으로 고칠 수 없다.
  blocker면 public package를 무단 unpublish하지 않고 별도 patch release와
  deprecation 필요성을 승인받는다.
- **Sites beta 비용·정책 변화**: 현재 관찰은 장기 무료 보장이 아니다. 추가
  과금·quota·정책 blocker가 나타나면 신규 submit/publication을 중단하고 #43
  fallback을 별도 task로 승인받는다.
- **managed fault-injection 공백**: remote D1/R2 장애를 직접 주입하지 않는다.
  local failure/concurrency suite와 hosted 정상·rollback 결과로 대체하고
  release 잔여 위험에 남긴다.
- **공식 문서 drift**: 실제 UX/계약이 문서와 다르면 검증을 문서에 맞춰
  억지로 통과시키지 않는다. runtime이 올바른지 문서가 오래됐는지 판정한 뒤
  승인된 범위만 수정한다.
- **Task #43 간섭**: main worktree의 진행 중 변경을 merge/rebase/삭제하지
  않고 #45 분리 worktree에서만 작업한다.

## 승인 요청 사항

- 권고안 A로 현재 public Site/saved version 7과 published CLI `0.1.0`을
  직접 검증하고 새 Site·storage·유료 resource를 만들지 않는 방향
- 작업지시자의 GitHub 계정을 fresh browser/CLI state의 disposable
  production owner로 사용하되, 실제 identity/handle과 Contract v1 전송은
  Gate A에서 다시 승인받는 방향

  response, Codex/OpenAI credential과 local session file은 제외하는 범위

  saved version 7 재배포 필요성 및 operator secret rotation을 exact 값으로
  별도 승인받는 방향
- Gate C에서 repository 밖 `0600` export와 exact
  delete→restore/repair→final cleanup을 owner/handle/digest/count 일치
  조건으로 별도 승인받는 방향

  README를 수정하고 일회성 증적은 `mydocs/working`·`mydocs/report`에 두는

  수행·구현 계획 변경 또는 별도 issue 승인으로 멈추는 원칙
