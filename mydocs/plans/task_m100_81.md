# Task #81 수행계획서 — 사용자 중심 README와 공개 문서·GitHub 메타데이터 정합화

GitHub Issue: [#81](https://github.com/postmelee/codex-usage-profile/issues/81)
마일스톤: M100

## 목적

처음 저장소를 방문한 사용자가 Codex Usage Profile의 가치, 시작 방법, 공개·공유 결과를 짧은 흐름으로 이해하도록 루트 README를 사용자 중심으로 재구성한다. 상단에는 production Website, npm package, CI, MIT 배지를 두고 실제 카드가 들어갈 자리는 다음 production 배포 뒤 교체할 수 있는 비렌더링 placeholder로 명시한다.

Task #78로 추가된 `/u/{handle}` 공유 문서, README 카드와 소셜 미리보기 이미지의 역할을 기존 공식 문서와 일치시킨다. GitHub 저장소의 description과 homepage도 같은 제품 메시지와 canonical production origin으로 정리하되, 실제 Sites 배포·D1 migration·카드 embed 활성화는 후속 배포 task에 남긴다.

## 배경

현재 README는 공개 npm package와 운영 경계를 정확히 기록하지만 개발·운영 설명의 비중이 높고, Task #78에서 추가된 링크 중심 공유 흐름과 실제 1497x918 README 카드·2400x1260 소셜 이미지 설명이 첫 사용자 흐름에 반영되지 않았다. `docs/readme-card.md`에는 `/u/{handle}`을 공유 링크로 설명하면서도 `/?profile={handle}`을 canonical HTML로 적은 표가 남아 있고, `docs/sites-operations.md`에는 extension 없는 `/u/{handle}`을 production link로 배포하지 말라는 이전 규칙이 남아 있다.

참고 구조는 [`codex-usage-analyzer` README](https://github.com/postmelee/codex-usage-analyzer#readme)의 배지 → 가치 제안 → Support → Quick start → 사용자 예시 흐름이다. 이 프로젝트가 지원받는 [OpenAI Codex for Open Source](https://developers.openai.com/community/codex-for-oss)는 maintainer 지원으로만 표현하고 endorsement로 오인되지 않는 고지를 함께 둔다.

현재 production은 saved version 7과 source `745be1d6b00b9b97afe5e36f0bbf691e3def8ff0`이며 `/u/{handle}` 문서 handler가 아직 배포되지 않았다. 따라서 이번 task의 README와 공식 문서는 배포 후보 계약과 현재 production 상태를 구분하고, 실제 카드 embed는 깨진 이미지가 되지 않도록 HTML comment placeholder로 유지한다.

## 설계 방향

- README는 `codex-usage-analyzer`의 정보 위계를 참고하되 이 제품의 1차 행동이 Website 진입과 `submit`이라는 점을 반영한다. 상단은 배지 4개와 짧은 가치 제안으로 제한한다.
- Website 배지는 uptime을 주장하지 않는 정적 링크로 사용한다. CI 배지는 Shields의 GitHub Actions workflow status endpoint로 `devel`의 `publish-npm.yml`을 짧은 `CI` label로 표시한다.
- 카드 embed placeholder는 `<PRODUCTION_CARD_URL>`과 `<PRODUCTION_PROFILE_URL>` marker를 HTML comment 안에 둔다. 다음 production task가 실제 `/u/{handle}` 응답과 공개 profile을 검증한 뒤 한 번에 교체한다.
- Support 섹션은 `Maintained with support from OpenAI’s Codex for Open Source program.`과 `Support is provided to the maintainer and does not imply endorsement.`를 사용한다. 기존 Trademark Notice의 비제휴·비보증 문구를 유지한다.
- 문서에서 배포 후보의 canonical 공유 링크와 현재 production의 동작을 분리한다. 새 경로가 이미 production에 배포됐다고 주장하지 않는다.
- 사용자용 세부 절차는 `docs/readme-card.md`와 `docs/cli-submit.md`, 운영 절차는 `docs/sites-operations.md`, 아키텍처·현재 배포 상태는 `docs/production-hosting.md`를 진실 원천으로 유지한다. README에 운영 상세를 복제하지 않는다.
- GitHub description/homepage는 파일 변경과 달리 Git history로 자동 복구되지 않으므로 적용 전 빈 기존 값을 확인하고, 적용 후 exact 값을 다시 조회한다.

## 리스크

- **배포 후보를 현재 production으로 오인**: README와 문서에서 `/u/{handle}`을 새 배포 후보로 명시하고, 실제 카드 embed는 후속 배포 검증 전까지 comment placeholder로 둔다.
- **README 정보 과밀**: 사용자 행동에 직접 필요한 정보만 앞쪽에 두고 운영·API·fallback 상세는 기존 `docs/` 문서로 연결한다.
- **배지 외부 의존성**: Website는 상태를 주장하지 않는 정적 링크로 사용하고 npm·CI badge source와 target을 각각 확인한다.
- **지원과 endorsement 혼동**: maintainer 지원과 비보증을 한 문단에서 함께 적고 기존 Trademark Notice를 보존한다.
- **GitHub metadata 비가역성 오해**: 적용 전 값을 기록하고 exact 적용 후 조회한다. rollback이 필요하면 이전 빈 값을 명시적으로 복원한다.
- **문서 진실 원천 중복**: URL/cache 상세는 `docs/readme-card.md`, 배포 절차는 `docs/sites-operations.md`, current baseline은 `docs/production-hosting.md`에만 유지한다.
