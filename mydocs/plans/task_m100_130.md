# Task #130 수행계획서 — 미제출 계정 Home을 운영자 카드로 표시

GitHub Issue: [#130](https://github.com/postmelee/codex-usage-profile/issues/130)
마일스톤: M100

## 목적

GitHub 로그인은 완료했지만 아직 Codex 사용량을 제출하지 않은 계정의 Home에서 현재 계정
identity를 덮어쓴 정적 sample card 대신 운영자 `postmelee`의 stable card를 표시한다. 사용량을
제출하지 않은 계정이 sample 통계를 자신의 실제 통계로 오인하지 않게 하고, PNG renderer와
HTML/CSS overlay의 좌표·font metric 차이도 미제출 흐름에서 제거한다.

사용량 제출 뒤에는 기존 owner private preview를 그대로 사용한다. anonymous operator, owner
preview 실패 sample fallback, loading Skeleton과 image resource lifecycle의 기존 의미를 보존하면서
미제출 상태만 명시적인 operator target으로 분리한다.

## 배경

- production Home 사용자 QA에서 사용량이 없는 `thechoicesinmylife` 계정에 고정 sample 통계와
  현재 GitHub identity가 함께 표시되어 실제 제출 카드처럼 보이는 현상을 확인했다.
- `resolveHomeCardTarget`은 anonymous·auth unavailable에는 operator source를 선택하지만,
  authenticated profile의 `usage`가 없으면 sample source를 선택한다.
- `HomePage`는 authenticated ready 상태에서 sample source가 보이면 `HomeSampleIdentity`를
  overlay하므로 sample card의 고정 통계와 현재 계정 identity가 결합된다.
- CSS overlay는 정적 PNG header를 가린 뒤 browser font와 percentage 좌표로 identity를 그리므로,
  실제 card renderer의 Noto Sans KR baseline과 avatar geometry에도 일치하지 않는다.
- 선행 #55는 운영자 card source와 안전한 image transition을 도입했고, #95는 auth/profile 확정 전
  중간 card를 reveal하지 않는 target authority를 확정했다. 이번 task는 그 구조를 유지한 채
  authenticated no-usage target만 operator로 보정한다.

## 범위

### 포함

- authenticated profile이 ready이고 `usage`가 없을 때 operator source 선택
- 미제출 operator load 실패 시 현재 계정 identity가 없는 정적 sample fallback
- 미제출 상태의 `먼저 사용량을 제출하세요` disabled action 유지
- anonymous operator, submitted owner, owner preview error fallback 회귀 보존
- target resolver 단위 테스트와 Home Playwright E2E 보정
- Sites full-stack production artifact build·검증

### 제외

- submitted owner card renderer, 통계와 heatmap 데이터 변경
- Share Studio, publish/private 전환과 stable public card endpoint 변경
- 운영자 handle, 운영자 card endpoint와 정적 sample asset 교체
- CLI device login, 프라이빗 브라우저 선택과 GitHub OAuth 변경
- Home layout, card tilt·beam·Skeleton motion과 일반 identity UI 재설계
- `.openai/hosting.json`, D1/R2 schema, runtime secret와 production 배포 변경

## 설계 방향

- Home target 우선순위를 `auth/profile unresolved → anonymous operator → ready no-usage
  operator → ready usage owner → owner/profile 오류 sample`로 명시한다.
- no-usage 분기는 `profileStatus === "ready" && hasUsage === false`일 때만 operator를 선택한다.
  profile 조회 오류나 사용량은 있지만 owner preview URL이 없는 실패 경로는 기존 sample target을
  유지한다.
- operator image가 404/503 또는 decode 실패로 정적 sample에 fallback하더라도 미제출 계정
  identity는 overlay하지 않는다. `HomeSampleIdentity`는 사용량이 존재하는 owner preview 실패
  fallback에만 유지해 이번 범위를 넘는 기존 UX를 보존한다.
- operator source와 fallback 처리는 기존 `homeCardTransition`의 target, generation, preload/decode와
  resource lease를 그대로 사용한다. 새 timeout, browser storage, 별도 fetch 또는 cache를 추가하지
  않는다.
- owner preview URL은 기존처럼 `hasUsage`일 때만 만들고, no-usage Home에서 owner card endpoint를
  요청하지 않는다.
- product copy, card asset과 social preview는 변경하지 않는다. 기존 Sites capability path와
  Cloudflare Worker-compatible build를 유지하되, 승인된 Issue 제외 범위에 따라 배포와 hosting
  manifest 변경은 수행하지 않는다.

- no-usage operator card 실패 시 정적 sample로 fail closed하되 현재 계정 identity를 overlay하지

- submitted owner는 owner preview를 표시하고, owner preview 실패 시 기존 personalized sample
  fallback을 유지한다.

  회귀하지 않는다.
- `.openai/hosting.json`, public card asset, backend/API와 공식 문서에는 diff가 없다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **no-usage와 owner 실패 fallback 혼동**: 두 상태 모두 sample을 거칠 수 있어 identity overlay를
  전부 제거하면 submitted owner fallback UX가 바뀐다. `hasUsage`와 target/source 상태를 함께
  검증해 no-usage만 비개인화한다.
- **operator 실패 시 다시 개인화되는 회귀**: target은 operator여도 transition fallback의 visible
  source는 sample이므로 기존 조건만 보면 overlay가 다시 나타날 수 있다. 404/503와 decode 실패
  E2E에서 sample identity 부재를 확인한다.
- **초기 reveal 회귀**: 초기 transition은 operator를 preload할 수 있지만 auth/profile authority가
  확정되기 전에는 reveal하면 안 된다. #95의 unresolved gate와 상태 이력 테스트를 보존한다.
- **불필요한 owner 요청**: no-usage 상태에서 owner preview URL을 만들면 404 요청과 이중 transition이
  발생할 수 있다. request count와 source URL로 operator 단일 target을 검증한다.
- **진행 중 task와 충돌**: 메인 worktree와 `local/task90`을 건드리지 않고 분리된
  `.worktrees/task130`의 `local/task130`에서만 작업한다.

## 승인 요청 사항

- authenticated ready no-usage target을 sample이 아닌 operator로 선택한다.
- operator 실패 fallback은 정적 sample을 허용하되 미제출 계정 identity를 overlay하지 않는다.
- submitted owner preview 실패의 personalized sample fallback은 기존 동작으로 유지한다.
- backend, card renderer, public asset, 공식 문서, hosting manifest와 production 배포는 제외한다.
- 위 범위를 3개 Stage로 진행하고 각 Stage 종료 시 보고·커밋·다음 단계 승인을 받는다.

승인되면 `task_m100_130_impl.md`에서 단계별 조건식, E2E fixture, 검증 명령과 커밋 경계를
구체화한다.
