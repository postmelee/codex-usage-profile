# Task M100 #63 수행계획서

GitHub Issue: [#63](https://github.com/postmelee/codex-usage-profile/issues/63)
마일스톤: M100

## 목적

ChatGPT Sites의 D1 migration과 Worker 변경이 같은 후보에 포함될 때
schema 준비 여부를 확인하지 않은 채 public traffic을 받는 경로를
fail-closed로 바꾼다. 운영 순서를 검증 가능한 계약으로 고정하고,
application migration manifest와 여러 readiness/artifact 경로 사이의
파생 가능한 중복을 줄인다.

동시에 CLI와 browser UI가 사용하는 canonical Sites production origin이
서로 다르게 변경되면 자동 검증이 실패하도록 한다. 단, production
artifact의 exact migration filename allowlist처럼 application manifest와
독립돼야 하는 보안 검증은 단일화하지 않는다.

## 배경

Task #59와 PR #62에서 D1 migration 3을 추가하면서 다음 중복과 운영
불확실성이 드러났다.

- `DEFAULT_D1_MIGRATIONS`와 D1 store readiness가 migration version을 각각
  보유한다.
- local full-stack Worker harness와 full-stack artifact verifier가
  migration 수와 항목을 별도로 고정한다.
- production artifact verifier는 exact allowlist를 의도적으로 독립
  검증하지만, 그 목적이 단순 count 중복과 구분돼 있지 않다.
- CLI `DEFAULT_SERVICE_ORIGIN`과 UI
  `DEVICE_APPROVAL_PRODUCTION_ORIGIN`이 같은 문자열을 별도 보유한다.
- `docs/sites-operations.md`는 candidate build/package/deploy를 설명하지만
  schema readiness가 public 전환보다 먼저 확인돼야 한다는 exact gate를
  명시하지 않는다.

2026-07-31 read-only Sites 확인에서 기존 project
`appgprj_6a62f58721788191a7cd82f37320f244`, saved version 7, canonical live
origin과 public access가 유지됨을 확인했다. Sites version/hosting
interface는 source/archive/version/access 정보를 제공하지만 원격 D1
schema를 saved version 생성 전에 직접 조회하는 interface는 제공하지
않는다. 따라서 지원되지 않는 provider API 또는 credential을 새로
도입해 “배포 전 원격 D1 query”를 가장하지 않는다.

### 포함

  full-stack artifact count/filename 검증 중 파생 가능한 경로를 manifest와

  readiness/preflight operation 추가
- owner-only candidate에서 protected readiness를 통과한 뒤 public access로
  전환하도록 `docs/sites-operations.md`의 순서와 중단 조건 보강
- CLI와 UI canonical production origin의 exact contract test
- migration, maintenance, artifact, production local smoke와 전체 회귀 검증

### 제외

- production D1 migration, saved version 생성, Sites deploy, access/environment

- D1/R2 resource 또는 새 Site 생성
- migration 4 또는 schema 변경
- 현재 canonical production origin 값과 OAuth callback 변경
- public `/healthz`에 D1 schema version이나 migration metadata 노출
- 모든 request마다 D1 readiness query를 실행하는 runtime hot-path 변경
- production exact allowlist를 application manifest에서 자동 파생
- Task #59 device approval UI, #61 shell/Profile navigation과 #43 Cloud Run

## 설계 방향

### 1. migration manifest 경계

- version, name, repository-relative SQL file path만 가진 pure manifest를
  D1 계약의 진실 원천으로 둔다.
- Node `migrate.js`는 pure manifest를 사용해 SQL을 읽고 기존
  `migrateD1Database` 계약을 유지한다.
- D1 store readiness의 expected versions는 manifest에서 파생한다.
- local full-stack Worker harness는 Vite가 정적으로 포함할 수 있는 raw SQL
  map과 pure manifest를 결합한다. 새 migration에서 version/name/count
  literal을 반복하지 않도록 하되 bundle-time SQL inclusion은 명시적으로
  검증한다.
- full-stack artifact verifier는 pure manifest의 filename/count와 packaged
  `.openai/drizzle`을 비교한다.
- production artifact verifier의 exact ordered filename allowlist는 별도
  상수로 유지한다. application manifest만 바뀌고 production allowlist
  review가 빠지면 verifier가 실패해야 한다.

### 2. Sites readiness gate — 권고안 A

원격 D1 direct-query interface가 없는 현재 Sites 경계에서는 다음 순서를
운영 계약으로 고정한다.

1. exact commit에서 build·artifact verifier·package 검증
2. migration을 포함한 saved version을 owner-only candidate로 배포
3. 기존 maintenance secret/origin 보호를 사용하는 read-only readiness
   operation 실행
4. expected/applied/missing version이 exact match일 때만 OAuth/CLI/public
   smoke와 public access 전환
5. mismatch, provider error 또는 unknown version이면 public 전환 없이
   이전 owner-only/maintenance 상태 유지

readiness operation은 owner/usage/token/session/R2 payload를 읽거나
반환하지 않고 bounded migration version 상태만 다룬다. 정상 production
baseline에서는 operator route를 계속 disabled/secret-absent로 둔다.
Task #63 자체는 이 원격 절차를 실행하지 않고 local dependency seam과
full-stack smoke로 계약만 검증한다.

이 방식은 “saved version 생성 전 remote query”를 주장하지 않는다.
대신 **public traffic 전에 candidate Worker와 shared D1 schema가 함께
준비됐음을 확인**한다. Sites가 향후 공식 pre-deploy D1 query/apply
interface를 제공하면 별도 task에서 gate 위치를 saved-version 이전으로
앞당긴다.

### 3. canonical origin — 권고안 A

- CLI package가 UI source를 import하거나 UI가 npm package 내부 구현을
  import하도록 runtime dependency를 만들지 않는다.
- root contract test가 CLI `DEFAULT_SERVICE_ORIGIN`과 UI
  `DEVICE_APPROVAL_PRODUCTION_ORIGIN`을 직접 비교한다.
- npm packed artifact의 독립 expected-origin smoke는 공급망 검증 경계이므로
  유지한다.
- 한쪽 origin만 바꾸면 root test가 즉시 실패하고, 값 변경 자체는 별도
  production origin/OAuth migration task와 승인 없이는 허용하지 않는다.

### 4. 호환성과 보안

- migration SQL과 schema는 바꾸지 않는다.
- 기존 D1 `schema_migrations`, idempotent runner와 store API를 유지한다.
- maintenance endpoint는 기존 disabled mode, bearer secret, same-origin,
  bounded JSON과 generic error 경계를 재사용한다.
- readiness는 read-only operation으로 `--apply`, owner scope, backup을
  요구하지 않는다.
- public health response와 observability allowlist에 migration 값이나
  provider metadata를 추가하지 않는다.

## 리스크

- **공식 pre-deploy D1 query 부재**: saved version 생성 전에 remote schema를
  조회한다고 주장하지 않는다. 권고안 A는 owner-only candidate 이후,
  public 전환 전에 protected readiness를 강제한다.
- **manifest 단일화가 보안 검증을 약화**: production exact allowlist는
  별도 상수와 negative test로 유지한다.
- **Worker bundle에서 SQL 자동 포함 실패**: pure metadata와 raw SQL
  inclusion을 분리하고 build/artifact test에서 manifest file별 포함을
  검증한다.
- **readiness endpoint 정보 노출**: 기존 hidden operator gate를 재사용하고
  bounded version 상태 외 identity/payload를 반환하지 않는다.
- **D1 query가 hot path에 추가되는 비용**: 일반 request와 public health에는
  readiness query를 추가하지 않고 operator command로만 실행한다.
- **origin shared module이 npm package 경계를 침범**: runtime import를
  만들지 않고 root exact contract test를 선택한다.
- **Sites beta lifecycle 변화**: 실제 배포 task 시점에 Sites connector와
  공식 문서를 다시 확인하고, 지원되는 pre-deploy query가 생기면 별도
  계획 변경 승인을 받는다.

## 승인 요청 사항

1. **권고안 A — readiness gate 위치**
   - remote direct-query가 없는 현재 플랫폼에서는 owner-only candidate
     배포 뒤 protected readiness를 통과한 경우에만 public 전환한다.
   - “saved version 생성 전 remote query”는 이번 수용 기준으로 주장하지
     않는다.
2. **선택적 manifest 단일화**
   - application/store/harness/full-stack verifier는 pure manifest에서
     파생한다.
   - production exact migration allowlist는 독립 검증으로 유지한다.
3. **origin exact contract test**
   - CLI/UI runtime을 서로 import시키지 않고 root test로 두 상수를
     비교한다.
4. **외부 변경 제외 유지**
   - 이 task는 local source/test/docs만 변경하고 production migration,
     Sites saved version/deploy/access/environment와 데이터 작업은 하지
     않는다.

승인되면 `task_m100_63_impl.md`에서 Stage별 exact 산출물, 검증 명령과
커밋 메시지를 구체화한다.
