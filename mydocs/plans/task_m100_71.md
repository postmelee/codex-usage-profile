# Task #71 통합 수행계획서 — Profile locale·format·share 계약 정리

GitHub Issue: [#71](https://github.com/postmelee/codex-usage-profile/issues/71)
연결 Issue: [#72](https://github.com/postmelee/codex-usage-profile/issues/72), [#73](https://github.com/postmelee/codex-usage-profile/issues/73)
마일스톤: M100

## 목적

MVP 배포 전에 Profile과 Marketing이 공유하는 locale 표시 계약을 한 번에 정리한다.
Profile 통계와 히트맵은 설치된 Codex 앱의 숫자 축약 동작과 일치시키고, Marketing
custom copy는 문자열 값 비교가 아닌 명시적인 source 계약으로 판별하며, Share
Studio는 placeholder 자기 치환과 수동 2차 보간을 제거한다.

#71을 대표 타스크와 브랜치로 사용하되 #72와 #73의 수용 기준, 단계, 검증과
커밋 경계를 각각 유지한다. 최종 Open PR 하나가 세 이슈를 함께 닫도록 게시한다.

## 배경

- PR #70 리뷰에서 Profile 통계의 `Intl.NumberFormat` 기반 formatter와 히트맵의
  수동 단위 formatter가 서로 다른 경계값을 표시하는 문제가 확인됐다.
- 설치된 ChatGPT/Codex 앱 `26.727.51351`의 Profile 화면은 locale-native compact
  unit과 최대 한 자리 소수를 사용한다. 현재 관찰 기준은 영어 `K/M/B/T`, 한국어
  `천/만/억/조`, 단위 경계 반올림, exact count의 지역화 정수 표시다. Stage 1에서
  앱 bundle과 실제 경계값을 읽기 전용으로 특성화해 구현계획서에 고정한다.
- Marketing 기본 copy와 명시적 custom copy가 값 동등성으로 구분되어, custom
  값이 기본 영어 문자열과 같을 때 의도와 다르게 locale catalog를 선택한다.
- Share Studio는 `{platform}`을 자기 자신으로 먼저 치환한 뒤 React 소비 지점에서
  다시 `replace`하는 2단계 보간에 의존하고, Profile의 Share 버튼은 지역화된
  문맥 이름이 충분히 명시되지 않았다.
- 세 이슈는 `messages.js`, formatter와 Profile/Marketing E2E 경계가 겹치므로 한
  PR에서 순서대로 처리하는 편이 중복 변경과 merge 충돌을 줄인다.

## 설계 방향

- 대표 브랜치는 `local/task71`, 게시 브랜치는 `publish/task71`로 사용한다. 오늘할일과
  PR 본문은 #71·#72·#73을 모두 추적하고 PR은 세 이슈를 모두 닫는다.
- #71의 compact 표시는 Codex 앱 관찰 결과를 기준으로 프로젝트의 공용 helper 한
  곳에 둔다. 현재 기준안은 `Intl.NumberFormat(resolveLocale(locale), {
  notation: "compact", maximumFractionDigits: 1 })`와 동등한 계약이며, Stage 1
  특성화 결과가 다르면 구현 전에 구현계획서에서 보정한다.
- compact tooltip은 공용 helper를 사용하고 exact tooltip은 기존 지역화 정수
  formatter를 사용한다. heatmap bucket, level, mode와 원본 token 값은 바꾸지 않는다.
- #72는 `configuredValue === DEFAULT_MARKETING_COPY[key]` sentinel을 제거한다.
  default/localized와 explicit custom override를 per-key source metadata 또는
  동등하게 명시적인 override map으로 표현해, 값이 우연히 같아도 caller intent를
  보존하고 누락 key는 locale catalog로 fallback한다.
- Quickstart step config는 실제 소비되는 안정적인 `id`만 가진다. title과
  description은 locale catalog를 단일 진실 원천으로 유지한다.
- #73의 platform 포함 message는 최종 값이 존재하는 렌더 지점에서 한 번만
  `formatMessage`하도록 한다. `{ platform: "{platform}" }` 자기 치환과 후속
  `.replace`는 제거한다.
- Profile Share 버튼은 보이는 `Share`/`공유` 문구를 유지하되 전용
  `common.shareProfile` message로 문맥이 포함된 접근성 이름을 제공한다.
- 구현 커밋은 #71, #72, #73 범위를 분리해 리뷰와 회귀 원인을 추적할 수 있게 한다.

### 통합 검증

- Profile 통계와 heatmap compact tooltip이 같은 locale·반올림 계약을 사용한다.
- exact token count는 반올림 없는 지역화 정수로 유지된다.
- Marketing default는 locale catalog, explicit custom key는 custom 값, 누락 key는
  locale catalog를 결정적으로 사용한다.
- Share Studio에 placeholder 자기 치환이나 수동 2차 `.replace`가 남지 않는다.
- 영어·한국어 Share UI와 접근성 이름이 일치하고 공유 URL은 기존과 같다.
- production artifact와 Sites sample-only 계약에 회귀가 없다.
- PR 준비 전 tracked working tree가 깨끗하고 `git diff --check`가 통과한다.

## 리스크

- **Codex 앱 minified bundle 해석 오판**: 버전, 실제 표시와 경계값 runtime 결과를
  함께 기록하고 추정만으로 formatter를 바꾸지 않는다.
- **compact 경계 반올림 변화**: 대표값뿐 아니라 단위 직전·직후 값을 특성화하고
  통계와 tooltip 비교 test를 둔다.
- **custom copy 하위 호환**: 기존 `options.copy` 입력은 유지하고 내부 source
  metadata만 명시화한다. partial override의 누락 key는 locale catalog로 복구한다.
- **message 보간 회귀**: platform을 포함하는 message를 typed key 수준으로 제한하고
  target URL test와 접근성 E2E를 함께 실행한다.
- **통합 PR 범위 혼합**: 이슈별 Stage·커밋·검증 결과를 분리하고 최종 PR에서
  `Closes #71`, `Closes #72`, `Closes #73`을 각각 명시한다.
