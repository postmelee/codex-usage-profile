# Task #78 수행계획서 — 소셜 공유 OG 메타데이터와 PublicProfilePage 카드 인트로

GitHub Issue: [#78](https://github.com/postmelee/codex-usage-profile/issues/78)
마일스톤: M100

## 목적

공개 카드 링크 하나를 붙여넣는 것만으로 X, 카카오톡, Threads에서 카드 썸네일과 설명이 정상 노출되게 한다. 지금까지 소셜 공유의 실질적 수단이던 PNG 주소 대신, Open Graph 메타데이터를 갖춘 `/u/{handle}` HTML 주소를 1차 공유 수단으로 만든다.

동시에 그 링크의 착지 지점인 `PublicProfilePage`를 카드가 주인공인 화면으로 바꾼다. 진입 시 카드를 모달로 먼저 보여주고, 닫으면 하단 `공유된 Codex 카드` 자리로 이어지는 인계 애니메이션으로 연결한다. 카드의 크기와 효과는 `/profile`과 동일한 컴포넌트를 재사용해 통일한다.

기존 `/u/{handle}/card.png`와 README Markdown 흐름은 그대로 유지한다. 이번 변경은 공유 경로를 추가하고 재배치하는 것이지, 기존 카드 URL 계약을 바꾸는 것이 아니다.

## 배경

- 현재 배포본에서 Share Studio의 `이미지 URL 복사`로 얻은 PNG 주소를 X와 카카오톡에 붙여넣으면 미리보기가 뜨지 않는다. 두 플랫폼은 HTML `<head>`의 Open Graph 메타데이터로 링크 카드를 구성하는데, SPA `index.html`에 OG 태그가 없다.
- `/u/{handle}` 경로는 백엔드를 거치지 않고 정적 `index.html`로 SPA fallback 된다. Workers는 [`worker.js:142`](../../src/profile-runtime/sites/worker.js), Node는 [`static-assets.js:29`](../../src/profile-runtime/static-assets.js)가 처리한다. 크롤러는 JS를 실행하지 않으므로 handle별 메타데이터는 서버가 주입해야 한다.
- 소셜 버튼은 프로필 URL을 계산만 하고([`shareStudio.js:66`](../../src/profile-ui/shareStudio.js)) intent 파라미터에 `url`을 넣지 않는다([`shareStudio.js:80`](../../src/profile-ui/shareStudio.js)). 즉 제품에 링크 공유 경로가 존재하지 않았고, 그 공백을 PNG 주소가 대신 떠맡아 왔다.
- README Markdown 스니펫은 같은 PNG URL을 마크다운으로 감싼 값이다([`cardShare.js:39`](../../src/profile-ui/cardShare.js)). `이미지 URL 복사`와 값이 동일해 두 액션의 구분이 모호하다.
- 카드 출력은 1497x918이다([`renderer.js:16`](../../src/profile-card/renderer.js), 499x306 논리 크기의 3배). 비율 1.63:1이라 1.91:1 미리보기 영역에서 잘린다. Threads에서 실제로 잘려 보였다.
- `PublicProfilePage`의 카드는 raw `<img>`로 스테이지를 꽉 채운다([`PublicProfilePage.jsx:69`](../../src/profile-ui/PublicProfilePage.jsx)). 1440px 뷰포트 실측 결과 `/profile`은 600x368, `/u/{handle}`은 920x564다. 차이의 원인은 `/profile`이 쓰는 `.home-card-tilt`의 `max-width: min(600px, calc(100% - 24px))`([`styles.css:823`](../../src/styles.css))를 공유 카드가 사용하지 않기 때문이다.
- 기준 문서는 [README](../../README.md), [README 카드 사용 문서](../../docs/readme-card.md), [production hosting architecture](../../docs/production-hosting.md), [Open Graph 명세](https://ogp.me/), [카카오 캐시 초기화 도구](https://developers.kakao.com/tool)와 Issue #78이다.

- `social.png`를 handle당 단일 stable object로 유지하고 publish, 카드 설정 저장, 사용량 갱신, unpublish 시점에 함께 관리
- 미디어 캐시 키의 format 축 확장과 orphan cleanup 반영
- `PublicProfilePage` 카드의 `MarketingCardPreview` 재사용과 크기·효과 통일
- 비공개 프로필 소유자에 대한 공개 전환 안내 UX
- Share Studio FLIP 모션 로직의 공용 훅 추출
- `PublicProfilePage` 진입 시 카드 인트로 모달과 닫기 인계 애니메이션
- Share Studio 보조 액션 재배치와 소셜 intent의 공유 링크 전달
- `docs/readme-card.md`의 공유 흐름 갱신

### 제외

- 홈(`/`)에서 방문자 카드로 placeholder를 교체하는 동작. 공유 링크는 `PublicProfilePage`로 착지시키기로 결정했고, 로그인 사용자의 홈 카드 로직([`HomePage.jsx:113`](../../src/profile-ui/HomePage.jsx))과 충돌한다.
- `PublicProfilePage`를 폐기하거나 홈으로 통합하는 라우팅 변경

- `/api/profiles/public/{handle}` 응답을 소유자 여부에 따라 분기하는 변경
- 카드 렌더러의 시각 디자인 변경. 소셜 변형은 기존 카드를 축소 배치하는 것에 한정한다.
- 소셜 이미지의 locale x theme 변형 생성과 소셜 경로의 theme/locale 쿼리 지원. 소유자 저장 설정을 반영한 단일 이미지만 유지한다.
- Animated GIF와 Web Share ([#39](https://github.com/postmelee/codex-usage-profile/issues/39) 범위)
- 새 카드 effect preset 추가
- `/u/{handle}/card.png`의 URL, 응답, ETag 계약 변경

## 설계 방향

- **라우팅 경계 유지**: `/u/{handle}` HTML을 백엔드 라우트로 승격하지 않는다. canonical 배포인 ChatGPT Sites에서 백엔드 핸들러는 `config`, `database`, `media`, `githubClient`만 받고 `environment.ASSETS`를 받지 않으므로([`backend.js:41`](../../src/profile-runtime/sites/backend.js)) index.html을 읽을 수 없고 [`http.js:590`](../../src/profile-backend/http.js)의 `Route not found`로 404가 된다. `isProfileBackendRoutePath`는 `looksLikeStaticAsset`에서도 쓰이므로([`worker.js:184`](../../src/profile-runtime/sites/worker.js)) 자산 판별까지 함께 흔들린다. 따라서 [`host-adapter.js`](../../src/profile-runtime/host-adapter.js)는 수정하지 않는다.
- **문서 핸들러 조립**: 프로필 조회, index.html 로딩, 태그 주입을 조합하는 런타임 무관 핸들러를 만들고 런타임별로 `loadIndexHtml`만 다르게 주입한다. Sites는 `environment.ASSETS.fetch`, Node 프로덕션은 파일 읽기, dev는 vite `transformIndexHtml`을 사용한다. Sites의 `handleProfileSitesRequest`와 Node의 `startProductionServer`는 이미 store와 자산 로딩 수단을 같은 스코프에서 다루므로 조립 지점이 존재한다([`worker.js:87`](../../src/profile-runtime/sites/worker.js), [`production-server.js:212`](../../src/profile-runtime/production-server.js)). 정적 자산 모듈에 데이터 의존성을 넣지 않는다.
- **D1 조회 비용**: 공개 카드 PNG는 R2만 조회하고 D1과 owner/usage record를 건드리지 않는 것이 문서화된 계약이다([production hosting](../../docs/production-hosting.md) 참조). OG HTML은 handle에서 owner 설정 리비전과 usage 업로드 시각을 얻어야 하므로 D1을 탄다. 공유가 확산되면 크롤러와 방문자가 이 경로로 몰리므로, owner와 latest usage를 JOIN하는 공개 프로필 전용 projection 한 번으로 제한하고 HTML 응답에 짧은 edge 캐시를 둔다. 핸들별 응답이 섞이지 않도록 캐시 키는 경로를 포함해야 한다.
- **owner-only 모드 차단**: 현재 `owner-only` 서비스 모드의 공개 차단 목록은 `/api/profiles/public/`, `/api/snapshots/public/`, `/u/{handle}/card.png` 세 가지다([`backend.js:193`](../../src/profile-runtime/sites/backend.js)). `/u/{handle}` HTML은 빠져 있어, OG를 붙이면 공개를 닫은 상태에서도 카드 썸네일이 외부에 노출된다. 운영 가이드가 owner-only를 스테이징 검증과 공개 원복 수단으로 사용하므로([Sites 운영 가이드](../../docs/sites-operations.md) 참조) 차단 목록에 HTML 경로를 추가한다.
- **OG 값 계약**: `og:type`은 `website`. `og:title`은 `{handle}'s Codex card`. `og:description`은 지표가 아니라 서비스 설명 고정 문구를 쓴다. 플랫폼이 제목·설명·이미지를 `og:url` 기준으로 한 덩어리로 캐시하고 이미지까지 미러링하므로, 지표를 넣어도 신선함을 보장하지 못하고 이미지에 이미 있는 숫자를 반복할 뿐이다. `og:url`과 canonical은 쿼리 없는 `/u/{handle}`로 고정한다.
- **이미지 리비전**: `og:image`는 `/u/{handle}/social.png?v={revision}` 형태로 두고 리비전 토큰만 붙인다. 플랫폼이 재수집할 때 미러 사본이 아닌 최신 이미지를 가져가게 하기 위한 것이다. PR 리뷰에서 사용량 `uploadedAt`만 쓰면 theme·locale 저장을 추적하지 못하는 문제가 확인돼, owner `updatedAt`과 usage `uploadedAt` 중 최신 시각의 밀리초 epoch를 사용한다.
- **폴백 정책**: 비공개와 미존재 handle은 구분 없이 사이트 기본 OG를 반환한다. 프로필 존재 여부가 새지 않아야 한다.
- **소셜 캔버스 분리**: `/u/{handle}/card.png`는 README 원본으로 그대로 두고 `/u/{handle}/social.png`를 신설한다. 1497x918 카드를 약 960x589로 축소해 1200x630 캔버스 중앙에 배치하고 좌우 약 120px, 상하 약 20px 안전 여백을 둔다.
- **소셜 이미지 단일화**: `social.png`는 handle당 하나의 stable object로 유지한다. locale과 theme 조합별 변형을 만들지 않고, 소유자가 저장한 `cardLocale`과 `cardStyle.theme`을 그대로 반영한 이미지 하나만 둔다. 따라서 소셜 경로는 theme/locale 쿼리를 받지 않고 리비전 토큰만 받는다. `card.png`가 유지하는 locale x theme 변형과 대비되는 지점이다.
- **소셜 이미지 갱신 시점**: 카드 설정 저장(`PATCH /api/profile/card-settings`)은 `ensureCardStyleMedia`에서 social bytes와 현재 storage ETag를 준비하되 stable object를 덮어쓰지 않는다. owner 설정 CAS가 성공한 요청만 ETag 조건부 commit을 수행하고, 실패·패배 요청은 기존 `social.png`를 유지한다. publish와 usage refresh는 기존 `publishOwnerCard` 경로를 유지하며 unpublish에서는 함께 제거한다.
- **소셜 미디어 키**: 캐시 키가 locale과 theme만 구분하므로([`service-core.js:157`](../../src/profile-card/service-core.js)) format 축을 추가하되, `social` format은 locale x theme 축을 갖지 않는 단일 표현으로 정의한다. [`cleanup-orphan-card-media.mjs`](../../scripts/cleanup-orphan-card-media.mjs)의 정리 대상에도 이 단일 객체를 반영한다.
- **문구와 이미지의 로케일 분리**: 이미지가 소유자 저장 설정 하나로 고정되므로, 공유 링크의 `?locale`은 이미지가 아니라 HTML 문구(`og:title`, `og:description`, `og:locale`)에만 영향을 준다. `?locale`이 없으면 소유자 저장 `cardLocale`을 따른다.
- **카드 컴포넌트 통일**: `PublicProfilePage`의 raw `<img>`를 `MarketingCardPreview`([`MarketingLanding.jsx:81`](../../src/profile-marketing/MarketingLanding.jsx))로 교체한다. 600px 상한, hover-tilt, BorderBeam, 스켈레톤, glare가 함께 따라오고, 인계 모션이 쓰는 `data-card-source`와 `data-share-transition-active` 훅도 확보된다. 새 CSS를 만들지 않는다.
- **소유자 판별**: 비공개 소유자 안내는 클라이언트 세션의 handle과 경로 handle 비교로만 수행한다. `PublicProfilePage`는 이미 `authState`, `client`, `onAuthStateChange`를 받고 있고([`App.jsx:135`](../../src/App.jsx)) 공개 전환 API도 존재한다([`client.js:84`](../../src/profile-api/client.js)). 서버 응답을 소유자 여부로 분기하면 handle 존재 여부 오라클이 되므로 공개 API는 균일한 404를 유지한다. 전환은 자동이 아니라 명시적 버튼으로 둔다.
- **모션 재사용**: 인트로 모달의 닫기 동작은 Share Studio 닫기 경로와 같은 메커니즘을 방향만 바꾼 것이다. `buildRectTransform`([`ShareStudio.jsx:800`](../../src/profile-ui/ShareStudio.jsx))과 `beginSourceHandoff`([`ShareStudio.jsx:365`](../../src/profile-ui/ShareStudio.jsx))가 852줄 컴포넌트 안에 인라인이므로 공용 훅으로 먼저 추출한다. 홈과 `/profile` 두 곳이 쓰는 코드라 추출 단계와 신규 모달 단계를 분리해 회귀 지점을 좁힌다.
- **모달 모션**: 첫 진입에는 출발 rect가 없으므로 열기는 FLIP이 아니라 360도 회전 등장으로 정의한다. `hover-tilt` 웹 컴포넌트가 자체 transform을 쓰므로 회전은 바깥 래퍼에 `perspective`와 함께 적용한다. 닫을 때 목적지인 하단 카드가 뷰포트 밖일 수 있으므로 목적지 rect를 스크롤 보정하거나 선 스크롤 후 인계한다. `prefers-reduced-motion`이면 회전을 생략하는 기존 관례를 따른다.
- **모달 노출 정책**: 매 진입마다 표시한다. 로그인 상태로 자기 링크를 열 때도 동일하게 표시해 공유 결과 확인 창구로 쓴다.
- **Share Studio 재배치**: 1차 `공유 링크 복사`(HTML 주소), 2차 `README Markdown`, 3차 `이미지 원본 주소` 순으로 둔다. PNG 주소는 Notion·블로그·Discord 임베드 수요가 남아 제거하지 않고 강등한다. 소셜 intent에는 공유 링크를 전달한다.

## 리스크

- **플랫폼 캐시**: 배포 후에도 기존 미리보기가 남는다. 카카오는 캐시 초기화 도구, Meta 계열은 sharing debugger로 재수집을 유도한다. X는 강제 재수집 수단이 제한적이므로 검증은 새 URL 또는 신규 공유로 수행한다.
- **Share Studio 회귀**: 모션 훅 추출은 홈과 `/profile` 두 진입점에 영향을 준다. Stage 5.1을 별도 하위 단계로 두고 기존 동작 확인을 통과한 뒤에만 5.2로 진행한다.
- **세 런타임 불일치**: OG 주입 지점이 Workers, Node 프로덕션, dev로 나뉘어 있어 한 곳만 고쳐지면 환경별로 다르게 보인다. 태그 생성과 주입은 공통 모듈에 두고 런타임별로는 `loadIndexHtml`만 다르게 주입한다. Stage 3에서 세 응답을 대조하는 검증을 필수로 둔다.
- **D1 hot path**: OG HTML은 공개 카드 PNG와 달리 D1을 탄다. 공유 확산 시 크롤러와 방문자가 몰리면 D1 읽기가 급증한다. owner와 latest usage를 JOIN하는 projection 한 번으로 제한하고 짧은 edge 캐시를 둔다.
- **owner-only 노출**: 공개를 닫은 상태에서 `/u/{handle}` HTML이 열려 있으면 OG 썸네일이 외부에 노출된다. Stage 3에서 차단 목록에 추가하고 해당 모드 응답을 검증한다.
- **미디어 캐시 키 확장**: format 축 추가가 기존 revision·stable key 및 cleanup 판정과 얽힌다. `social` format은 locale x theme 축이 없는 단일 표현이라 기존 키 구조와 형태가 다르므로, 기존 키의 하위 호환을 먼저 고정하고 신규 format을 추가하는 순서로 진행한다.
- **소셜 이미지 갱신 누락**: 단일 이미지 정책에서는 카드 설정과 소셜 객체가 어긋나면 안 된다. 설정 저장은 렌더 준비 → owner CAS → storage ETag 조건부 social commit 순서로 고정하고, CAS 실패와 동시 요청 회귀 테스트로 패배 요청의 stable overwrite를 막는다.
- **handle 열거 오라클**: 소유자 안내를 서버 응답 분기로 구현하면 비공개와 미존재를 구분할 수 있게 된다. 클라이언트 세션 비교로만 구현하고 Stage 4 검증에 응답 동일성 대조를 포함한다.
- **모달 피로도**: 매 진입마다 표시하므로 뒤로가기와 새로고침에서도 뜬다. 작업지시자 결정 사항이며, 닫기 동작이 가볍고 즉시 반응하도록 유지하는 것으로 대응한다.

## 승인 요청 사항

- 위 범위의 포함·제외 항목
- OG `og:description`을 지표가 아닌 서비스 설명 고정 문구로 두는 설계

- `owner-only` 서비스 모드 공개 차단 목록에 `/u/{handle}` HTML을 추가하는 범위 확대
- Issue 본문의 7단계를 6단계로 묶은 잠정 단계 구성
- 공식 문서는 새로 만들지 않고 `docs/readme-card.md`의 공유 흐름 절만 수정하는 문서 위치 판단
