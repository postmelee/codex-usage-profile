# Task #78 수행계획서 — 소셜 공유 OG 메타데이터와 PublicProfilePage 카드 인트로

GitHub Issue: [#78](https://github.com/postmelee/codex-usage-profile/issues/78)
마일스톤: M100

## 목적

공개 카드 링크 하나를 붙여넣는 것만으로 X, 카카오톡, Threads에서 카드 썸네일과 설명이 정상 노출되게 한다. 지금까지 소셜 공유의 실질적 수단이던 PNG 주소 대신, Open Graph 메타데이터를 갖춘 `/u/{handle}` HTML 주소를 1차 공유 수단으로 만든다.

동시에 그 링크의 착지 지점인 `PublicProfilePage`를 카드가 주인공인 화면으로 바꾼다. 진입 시 카드를 모달로 먼저 보여주고, 닫으면 하단 `공유된 Codex 카드` 자리로 이어지는 인계 애니메이션으로 연결한다. 카드의 크기와 효과는 `/profile`과 동일한 컴포넌트를 재사용해 통일한다.

기존 `/u/{handle}/card.png`와 README Markdown 흐름은 그대로 유지한다. 이번 변경은 공유 경로를 추가하고 재배치하는 것이지, 기존 카드 URL 계약을 바꾸는 것이 아니다.

## 배경

- 현재 배포본에서 Share Studio의 `이미지 URL 복사`로 얻은 PNG 주소를 X와 카카오톡에 붙여넣으면 미리보기가 뜨지 않는다. 두 플랫폼은 HTML `<head>`의 Open Graph 메타데이터로 링크 카드를 구성하는데, SPA `index.html`에 OG 태그가 없다.
- `/u/{handle}` 경로는 백엔드를 거치지 않고 정적 `index.html`로 SPA fallback 된다. Workers는 [`worker.js:142`](../../src/profile-runtime/sites/worker.js), Node는 [`static-assets.js:29`](../../src/profile-runtime/static-assets.js)가 처리한다. 크롤러는 JS를 실행하지 않으므로 handle별 메타데이터는 서버가 주입해야 한다.
- 소셜 버튼은 프로필 URL을 계산만 하고([`shareStudio.js:66`](../../src/profile-ui/shareStudio.js)) intent 파라미터에 `url`을 넣지 않는다([`shareStudio.js:80`](../../src/profile-ui/shareStudio.js)). 즉 제품에 링크 공유 경로가 존재하지 않았고, 그 공백을 PNG 주소가 대신 떠맡아 왔다.
- README Markdown 스니펫은 같은 PNG URL을 마크다운으로 감싼 값이다([`cardShare.js:39`](../../src/profile-ui/cardShare.js)). `이미지 URL 복사`와 값이 동일해 두 액션의 구분이 모호하다.
- 카드 출력은 1497x918이다([`renderer.js:16`](../../src/profile-card/renderer.js), 499x306 논리 크기의 3배). 비율 1.63:1이라 1.91:1 미리보기 영역에서 잘린다. Threads에서 실제로 잘려 보였다.
- `PublicProfilePage`의 카드는 raw `<img>`로 스테이지를 꽉 채운다([`PublicProfilePage.jsx:69`](../../src/profile-ui/PublicProfilePage.jsx)). 1440px 뷰포트 실측 결과 `/profile`은 600x368, `/u/{handle}`은 920x564다. 차이의 원인은 `/profile`이 쓰는 `.home-card-tilt`의 `max-width: min(600px, calc(100% - 24px))`([`styles.css:823`](../../src/styles.css))를 공유 카드가 사용하지 않기 때문이다.
- 기준 문서는 [README](../../README.md), [README 카드 사용 문서](../../docs/readme-card.md), [production hosting architecture](../../docs/production-hosting.md), [Open Graph 명세](https://ogp.me/), [카카오 캐시 초기화 도구](https://developers.kakao.com/tool)와 Issue #78이다.

## 설계 방향

- **라우트 승격**: `/u/{handle}` HTML을 백엔드 라우트로 올린다. 현재 `isProfileBackendRoutePath`는 `/u/{handle}/card.png`만 백엔드로 넘긴다([`host-adapter.js:52`](../../src/profile-runtime/host-adapter.js)). 여기에 HTML 경로를 추가하되, 정적 자산 판별(`looksLikeStaticAsset`)과 충돌하지 않도록 경계를 명시한다.
- **OG 값 계약**: `og:type`은 `website`. `og:title`은 `{handle}'s Codex card`. `og:description`은 지표가 아니라 서비스 설명 고정 문구를 쓴다. 플랫폼이 제목·설명·이미지를 `og:url` 기준으로 한 덩어리로 캐시하고 이미지까지 미러링하므로, 지표를 넣어도 신선함을 보장하지 못하고 이미지에 이미 있는 숫자를 반복할 뿐이다. `og:url`과 canonical은 쿼리 없는 `/u/{handle}`로 고정한다.
- **이미지 리비전**: `og:image`에 리비전 토큰을 붙여 플랫폼이 재수집할 때 미러 사본이 아닌 최신 이미지를 가져가게 한다. `presentationDigest`는 cardStyle만 반영하므로([`http.js:1035`](../../src/profile-backend/http.js)) 사용량 갱신 추적에는 `uploadedAt` 기반 값을 사용한다. 최종 형식은 Stage 1에서 확정한다.
- **폴백 정책**: 비공개와 미존재 handle은 구분 없이 사이트 기본 OG를 반환한다. 프로필 존재 여부가 새지 않아야 한다.
- **소셜 캔버스 분리**: `/u/{handle}/card.png`는 README 원본으로 그대로 두고 `/u/{handle}/social.png`를 신설한다. 1497x918 카드를 약 960x589로 축소해 1200x630 캔버스 중앙에 배치하고 좌우 약 120px, 상하 약 20px 안전 여백을 둔다. 캐시 키가 locale과 theme만 구분하므로([`service-core.js:157`](../../src/profile-card/service-core.js)) format 축을 추가하고 [`cleanup-orphan-card-media.mjs`](../../scripts/cleanup-orphan-card-media.mjs)의 정리 대상에 반영한다.
- **카드 컴포넌트 통일**: `PublicProfilePage`의 raw `<img>`를 `MarketingCardPreview`([`MarketingLanding.jsx:81`](../../src/profile-marketing/MarketingLanding.jsx))로 교체한다. 600px 상한, hover-tilt, BorderBeam, 스켈레톤, glare가 함께 따라오고, 인계 모션이 쓰는 `data-card-source`와 `data-share-transition-active` 훅도 확보된다. 새 CSS를 만들지 않는다.
- **소유자 판별**: 비공개 소유자 안내는 클라이언트 세션의 handle과 경로 handle 비교로만 수행한다. `PublicProfilePage`는 이미 `authState`, `client`, `onAuthStateChange`를 받고 있고([`App.jsx:135`](../../src/App.jsx)) 공개 전환 API도 존재한다([`client.js:84`](../../src/profile-api/client.js)). 서버 응답을 소유자 여부로 분기하면 handle 존재 여부 오라클이 되므로 공개 API는 균일한 404를 유지한다. 전환은 자동이 아니라 명시적 버튼으로 둔다.
- **모션 재사용**: 인트로 모달의 닫기 동작은 Share Studio 닫기 경로와 같은 메커니즘을 방향만 바꾼 것이다. `buildRectTransform`([`ShareStudio.jsx:800`](../../src/profile-ui/ShareStudio.jsx))과 `beginSourceHandoff`([`ShareStudio.jsx:365`](../../src/profile-ui/ShareStudio.jsx))가 852줄 컴포넌트 안에 인라인이므로 공용 훅으로 먼저 추출한다. 홈과 `/profile` 두 곳이 쓰는 코드라 추출 단계와 신규 모달 단계를 분리해 회귀 지점을 좁힌다.
- **모달 모션**: 첫 진입에는 출발 rect가 없으므로 열기는 FLIP이 아니라 360도 회전 등장으로 정의한다. `hover-tilt` 웹 컴포넌트가 자체 transform을 쓰므로 회전은 바깥 래퍼에 `perspective`와 함께 적용한다. 닫을 때 목적지인 하단 카드가 뷰포트 밖일 수 있으므로 목적지 rect를 스크롤 보정하거나 선 스크롤 후 인계한다. `prefers-reduced-motion`이면 회전을 생략하는 기존 관례를 따른다.
- **모달 노출 정책**: 매 진입마다 표시한다. 로그인 상태로 자기 링크를 열 때도 동일하게 표시해 공유 결과 확인 창구로 쓴다.
- **Share Studio 재배치**: 1차 `공유 링크 복사`(HTML 주소), 2차 `README Markdown`, 3차 `이미지 원본 주소` 순으로 둔다. PNG 주소는 Notion·블로그·Discord 임베드 수요가 남아 제거하지 않고 강등한다. 소셜 intent에는 공유 링크를 전달한다.

- **플랫폼 캐시**: 배포 후에도 기존 미리보기가 남는다. 카카오는 캐시 초기화 도구, Meta 계열은 sharing debugger로 재수집을 유도한다. X는 강제 재수집 수단이 제한적이므로 검증은 새 URL 또는 신규 공유로 수행한다.
- **Share Studio 회귀**: 모션 훅 추출은 홈과 `/profile` 두 진입점에 영향을 준다. Stage 5.1을 별도 하위 단계로 두고 기존 동작 확인을 통과한 뒤에만 5.2로 진행한다.
- **세 런타임 불일치**: OG 주입 지점이 Workers, Node 프로덕션, dev로 나뉘어 있어 한 곳만 고쳐지면 환경별로 다르게 보인다. Stage 3에서 세 응답을 대조하는 검증을 필수로 둔다.
- **미디어 캐시 키 확장**: format 축 추가가 기존 revision·stable key 및 cleanup 판정과 얽힌다. 기존 키의 하위 호환을 먼저 고정하고 신규 format을 추가하는 순서로 진행한다.
- **handle 열거 오라클**: 소유자 안내를 서버 응답 분기로 구현하면 비공개와 미존재를 구분할 수 있게 된다. 클라이언트 세션 비교로만 구현하고 Stage 4 검증에 응답 동일성 대조를 포함한다.
- **모달 피로도**: 매 진입마다 표시하므로 뒤로가기와 새로고침에서도 뜬다. 작업지시자 결정 사항이며, 닫기 동작이 가볍고 즉시 반응하도록 유지하는 것으로 대응한다.
