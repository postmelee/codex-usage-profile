# Task M100 #61 수행계획서

GitHub Issue: [#61](https://github.com/postmelee/codex-usage-profile/issues/61)
마일스톤: M100

## 목적

Landing, owner/public Profile, Settings와 device Approve 화면이 같은 제품의
페이지로 인식되도록 공통 전역 헤더와 기본 page canvas를 정렬한다. 로그인
사용자는 우측 상단 계정 메뉴에서 `/profile`로 직접 이동할 수 있어야 하고,
Settings의 GitHub 동기화 계정 영역은 향후 카드 커스터마이징 화면으로 사용할
Profile과 명칭이 충돌하지 않아야 한다.

Profile과 Settings의 화면 전체를 감싸는 큰 둥근 외곽 프레임은 제거하되 기존
내부 정보·설정 panel과 카드 관리 동작은 보존한다. Device Approve는 별도
application처럼 보이는 큰 외곽 프레임 대신 공통 header 아래의 집중 작업
card로 유지하고, 승인·재시도·완료 계약은 변경하지 않는다.

## 배경

#14에서 `ProfileShell`과 `AccountMenu`, Settings shell을 만들었고 #34에서
Landing을 fullscreen page와 전역 header 구조로 확장했다. #59는 device 승인
intent와 완료 문구를 보강했지만 `DeviceApprovalPage`는 아직 `ProfileShell`을
사용하지 않고 자체 `app-frame`을 렌더한다. 현재 `ProfileShell`의 기본 layout은
큰 `app-frame`이고 Home만 `layout="fullscreen"`을 사용하므로 owner/public
Profile과 Settings가 웹사이트 안의 별도 창처럼 보인다.

현재 계정 menu는 `Settings`와 `Log out`만 제공하고, Playwright도 Profile
menuitem이 없음을 기존 상태로 고정한다. Settings 본문의 첫 heading은
`Profile`이어서 `/profile`의 카드 관리 역할과 의미가 겹친다. 이번 task는
기존 app-owned GitHub OAuth, session, profile·settings API와 device 승인
protocol을 그대로 두고 navigation, semantic heading, shell layout과 접근성만
정렬한다.

## 범위

### 포함

- 로그인 상태 계정 menu에 `/profile`로 연결되는 `Profile` 항목을
  `Settings` 위에 추가
- `Profile` → `Settings` → `Log out` 순서와 icon, pointer·keyboard 조작,
  focus 이동·복원, Escape, 외부 click, ARIA menu 상태 검증
- 기존 `ProfileShell`을 Landing, owner `/profile`, public
  `/?profile={handle}`, Settings와 Approve가 공유하는 전역 header 경계로 정리
- 전역 header의 product brand를 일관된 Home link로 유지하고 각 화면의 실제
  제목은 main content의 semantic heading으로 제공
- owner/public Profile과 Settings를 fullscreen page canvas로 전환하고 큰
  둥근 외곽 frame 제거
- Profile card, Share action, Settings account/token/device panel 등 기존 내부
  section 구조와 기능 유지
- Settings의 GitHub identity 영역을 `GitHub account`로 명명하고 page heading
  `Settings`와 역할 분리
- Approve 화면을 공통 header 아래에 배치하고 중앙 approval card의 집중도,
  user code, 승인·재시도·완료·copy와 Home/Profile link 유지
- desktop, mobile, short viewport, keyboard와 reduced-motion 회귀 검증
- Sites full-stack production build와 artifact 검증

### 제외

- 카드 커스터마이징 기능, 편집 상태와 저장 API
- GitHub OAuth, browser session, backend, API, D1/R2 schema와 device 승인 계약
  변경
- usage card renderer, heatmap, Share Studio의 기능·시각 효과 변경
- 새로운 route, localization framework, branding asset 또는 외부 이미지 제작
- canonical URL, custom domain, npm package와 production environment 변경
- Sites saved version 생성, production 배포, access 변경과 원격 데이터 작업

## 설계 방향

- 새 application shell을 병렬로 만들지 않고 기존 `ProfileShell`의 topbar를
  공통 전역 header 진실 원천으로 확장한다. `AccountMenu`와 page action도 이
  경계에서 재사용한다.
- 전역 header의 brand는 모든 제품 route에서 `Codex Usage` Home link로
  고정한다. `Settings`, `Your Codex card`, 공개 profile과 `Authorize device`
  같은 화면 제목은 main landmark 안의 `h1`으로 유지해 brand와 page heading
  의미를 분리한다.
- fullscreen은 외곽 frame만 제거하는 layout 변경이다. owner/public Profile의
  card와 visibility, Settings의 account/token/device panel, Approve의 중앙
  작업 card는 내부 정보 계층으로 유지한다.
- `/profile`뿐 아니라 사용자가 직접 공유받는 public
  `/?profile={handle}`에도 같은 header/canvas를 적용한다. legacy local
  `/u/{handle}` alias는 같은 public page 결과를 유지한다.
- 계정 menu는 trigger와 menuitem ref를 명시적으로 관리한다. 열 때 첫
  menuitem focus, ArrowUp/ArrowDown·Home/End 이동, Escape 닫기와 trigger focus
  복원, 외부 pointer 닫기, navigation·logout 후 닫기를 검증한다. Tab을 막는
  focus trap은 만들지 않는다.
- Device Approve는 `ProfileShell`을 사용하도록 합성하되 `user_code`가 포함된
  login return path와 승인 state machine은 그대로 둔다. header logout을 위해
  기존 `onAuthStateChange`만 전달하고 새로운 인증 경로를 추가하지 않는다.
- CSS는 기존 color, spacing, focus token을 재사용하고 document-level
  horizontal overflow, sticky header가 content를 가리는 문제, Share Studio의
  overlay stacking 회귀를 방지한다.
- `.openai/hosting.json`, Sites D1/R2 linkage와 production origin은 변경하지
  않는다. 이슈의 제외 범위에 따라 local build/artifact까지만 검증하며 배포는
  후속 공개 release task에서 별도 Gate로 수행한다.

## 문서 위치 판단

이번 task는 기존 제품 UI의 navigation과 layout을 정렬하며 공개 API,
architecture, deployment 또는 사용자 실행 절차를 변경하지 않는다. 따라서
공식 `README.md`와 `docs/`는 수정하지 않고, 설계·검증·승인 기록만 표준 task
산출물에 남긴다.

| 파일 | 분류 | 대상 독자 | 선택 위치 | 대안 위치 | 선택 이유 |
|---|---|---|---|---|---|
| 수행·구현 계획서 | 작업 산출물 | 내부 작업자·에이전트 | `mydocs/plans/` | 공식 `docs/` | 이슈별 범위와 승인 판단 기록 |
| 단계 보고서 | 작업 산출물 | 내부 작업자·에이전트 | `mydocs/working/` | 공식 `docs/` | 단계별 구현·검증 증적 |
| 최종 보고서 | 작업 산출물 | 내부 작업자·리뷰어 | `mydocs/report/` | 공식 `docs/` | PR 전 수용 기준과 잔여 위험 기록 |
| 공식 제품 문서 | 해당 없음 | 사용자·외부 통합자 | 변경하지 않음 | `README.md`, `docs/` | route·API·사용자 실행 계약이 바뀌지 않음 |

구현 중 사용자 실행 절차나 공개 route 계약 변경이 필요하다고 판단되면 공식

## 리스크

- **heading·landmark 회귀**: topbar의 page title을 product brand로 바꾸면
  `h1`이 사라지거나 중복될 수 있다. 각 route main content의 단일 page
  heading을 E2E로 고정한다.
- **menu focus 회귀**: menu를 닫은 뒤 제거된 item에 focus가 남거나 keyboard
  동작이 native link navigation을 막을 수 있다. trigger/item ref와 닫기
  이유를 분리하고 Tab은 강제로 trap하지 않는다.
- **fullscreen scroll 회귀**: frame 내부 scroll에서 document scroll로 바뀌며
  sticky header, short viewport와 mobile safe area가 겹칠 수 있다. route별
  scroll metrics와 horizontal overflow를 검증한다.
- **device login redirect 회귀**: 공통 account menu 합성 과정에서
  `user_code`가 OAuth return path에서 사라질 수 있다. 기존
  `buildDeviceRedirectPath`와 login URL을 그대로 사용하고 시나리오 test를
  유지한다.
- **Share overlay stacking 회귀**: header stacking context 변경이 Share Studio
  overlay보다 앞에 보일 수 있다. owner profile의 open/close와 z-index를
  browser test로 확인한다.
- **scope 확장**: header 정렬 과정에서 backend/auth/API 또는 카드 디자인을
  함께 바꾸지 않는다. 필요성이 발견되면 별도 issue 또는 계획 변경 승인을
  요청한다.

## 승인 요청 사항

- 기존 `ProfileShell`을 공통 전역 header의 단일 진실 원천으로 확장하고 별도
  header system을 만들지 않는 방향
- header brand는 모든 제품 route에서 `Codex Usage` Home link로 고정하고
  실제 page title은 main content의 `h1`으로 분리하는 방향
- owner `/profile`, public `/?profile={handle}`와 Settings는 fullscreen page로,
  Approve는 같은 page 안의 중앙 작업 card로 정렬하는 범위
- 계정 menu를 `Profile` → `Settings` → `Log out` 순서와 roving keyboard
  navigation, Escape focus 복원으로 구현하는 방향
- Settings identity section을 `GitHub account`로 명명하는 방향
- 공식 제품 문서는 변경하지 않고 task 산출물만 기록하는 문서 위치 판단
- production 배포, canonical URL, backend·database·auth contract와 카드
  커스터마이징을 제외하는 범위

승인되면 `task_m100_61_impl.md`에서 단계별 산출물, 검증 명령과 커밋 메시지를
구체화한다.
