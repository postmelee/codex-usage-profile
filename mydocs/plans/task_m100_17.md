# Task M100 #17 수행계획서

GitHub Issue: [#17](https://github.com/postmelee/codex-usage-profile/issues/17)
마일스톤: M100

## 목적

CLI가 `codex-usage-profile` 계정에 연결될 수 있도록 device-code login API를 구현한다. 사용자는 로컬 CLI에서 device login을 시작하고, 브라우저에서 GitHub 계정으로 로그인한 뒤 user code를 승인한다. CLI는 polling으로 승인 상태를 확인하고 승인 완료 시 raw CLI API token을 한 번만 수령한다.

이 작업은 analyzer와 독립된 인증 경계다. analyzer snapshot 생성, `npx ... submit` CLI 구현, README 카드 갱신은 후속 이슈에서 다룬다.

## 배경

M100 MVP는 사용자가 로컬 터미널에서 submit 명령을 실행하면 최신 사용량 snapshot이 웹 프로필과 README 카드에 반영되는 흐름이다. #4, #12, #13, #19, #20으로 snapshot 저장, GitHub OAuth session, 로컬 runtime, analyzer/profile 책임 분리, analyzer repo 분리는 완료됐다.

현재 backend에는 `src/profile-backend/cli-login.js`의 challenge 기반 `start/approve/exchange` 흐름과 `src/profile-backend/tokens.js`의 digest 기반 CLI token 발급이 있다. 다만 CLI가 local callback 없이 쓰기 좋은 device-code 형태의 API 경계, user code 승인 화면/route, poll 상태 모델은 아직 없다. #17은 기존 challenge 모델을 재사용하되 device code/user code/poll semantics를 명확히 추가한다.

## 범위

### 포함

- device login start route: `POST /api/auth/device` 또는 기존 route와 호환되는 동등 API
- device approval route/API: `/device` 화면이 사용할 조회/승인 contract 및 `POST /api/auth/device/authorize`
- polling route: `POST /api/auth/device/poll`
- device code, user code, expires, poll interval 응답 모델
- pending/approved/exchanged/expired 상태 전이와 재사용 방지
- GitHub OAuth browser session과 device approval 연결
- raw CLI API token 1회 반환 및 token digest 저장 유지
- 만료, 중복 승인, 중복 exchange, 세션 없음, 잘못된 code 테스트
- credential-like 값이 store/serialized response에 노출되지 않는 보안 검증

### 제외

- 실제 npm CLI 명령 구현: #5
- analyzer SDK/CLI 연동 및 UsageSnapshot 생성
- Settings shell/account menu UI: #14
- API token/device 관리 UI 전체: #15
- README 카드 PNG endpoint: #6
- production rate limit/storage 최종 선택

## 설계 방향

- 기존 `createCliLoginService`를 device login 서비스의 중심으로 유지한다. 새 서비스를 만들더라도 `cli-login.js`의 상태 전이와 `createCliTokenService` 발급 경계를 재사용한다.
- 기존 `/api/cli/login/*` contract는 테스트 호환성을 위해 즉시 제거하지 않는다. 새 device API를 우선 추가하고, 필요한 경우 기존 route는 wrapper 또는 legacy alias로 유지한다.
- start 응답은 CLI가 저장해야 하는 `deviceCode`, 사용자가 입력/확인하는 `userCode`, `verificationUri`, `verificationUriComplete`, `expiresAt`, `intervalSeconds`를 반환한다.
- raw CLI API token은 poll이 `approved`에서 `exchanged`로 전이되는 순간 한 번만 반환한다. 이후 같은 device code poll은 `gone` 또는 `exchanged` 상태로 raw token 없이 응답한다.
- device code는 bearer-like 값으로 취급한다. 가능하면 store에는 raw device code 대신 digest를 저장하고, poll 시 digest lookup을 사용한다. user code는 approval lookup을 위해 normalized 값으로 저장하되, approval은 authenticated session이 있어야 한다.
- `/device` UI는 #14의 Settings shell과 분리해 최소 승인 화면으로 구현한다. 로그인되지 않은 경우 GitHub login으로 보낸 뒤 device approval 흐름으로 돌아오게 한다.
- 에러 응답은 기존 `ProfileBackendError` code 체계를 유지한다. pending/expired/approved/exchanged 상태는 CLI가 분기하기 쉬운 안정 JSON 형태로 직렬화한다.

## 잠정 단계

- **Stage 1 — device login domain model**
  - `cli-login` challenge에 device/user code와 poll 상태 모델을 추가한다.
  - store lookup과 상태 전이 테스트를 정리한다.
- **Stage 2 — HTTP API and OAuth/session bridge**
  - device start/authorize/poll routes를 추가한다.
  - GitHub OAuth session, login redirect, approval 흐름을 연결한다.
- **Stage 3 — minimal device approval UI**
  - `/device` 최소 승인 화면과 API client 함수를 추가한다.
  - authenticated/anonymous 상태의 승인 흐름을 수동 또는 테스트로 확인한다.
- **Stage 4 — security and integration hardening**
  - 만료, 중복 exchange, 세션 없음, 잘못된 code, raw token 미저장 검증을 보강한다.
  - 전체 테스트/build/security scan을 실행하고 최종 보고서를 작성한다.

## 리스크

- **기존 cli-login contract와 새 device API 중복**: 기존 route를 바로 제거하지 않고 alias/wrapper로 유지해 회귀를 줄인다.
- **device code 저장 방식**: raw device code가 credential-like 값이 될 수 있으므로 digest 저장을 우선 설계한다.
- **approval UI 범위 확장**: #14 Settings shell과 섞이지 않도록 `/device` 최소 승인 화면만 다룬다.
- **poll 상태 의미 혼선**: token이 발급되는 poll 응답은 한 번만 허용하고, 이후 상태는 raw token 없이 명확히 응답한다.
- **로컬 runtime host 차이**: production host adapter 최종화는 별도 범위로 두고, 기존 dev/runtime 테스트 가능한 contract를 우선 구현한다.

## 승인 요청 사항

- 기존 `/api/cli/login/*`를 즉시 제거하지 않고 새 `/api/auth/device*` API를 추가하는 방향 승인
- raw device code는 digest 저장을 우선 적용하고 user code는 승인 lookup용 normalized 값으로 저장하는 방향 승인
- #17 범위에 `/device` 최소 승인 화면을 포함하되 Settings/account UI는 #14로 남기는 방향 승인
- 공식 사용자/API 문서는 #5 CLI 구현 시점으로 미루고, 이번 task는 작업 산출물과 테스트로 contract를 고정하는 방향 승인

승인되면 `task_m100_17_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지를 구체화한다.
