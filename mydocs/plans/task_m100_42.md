# 수행계획서 — Task #42: R2 public card media 및 stable URL 구현

GitHub Issue: [#42](https://github.com/postmelee/codex-usage-profile/issues/42)
마일스톤: M100

## 목적

공개 card PNG를 R2(S3 호환 object storage)에 immutable revision과 stable public object로 안전하게 저장하고, README에 삽입한 stable image URL(`/u/{handle}/card.png`)이 최신 성공 revision을 ETag 재검증으로 제공하도록 구현한다. publish/unpublish, 재시도 멱등성, conflict, 부분 실패에서도 이전 공개 카드를 보존한다. private preview는 R2에 저장하지 않는다. 이로써 #41(Neon structured store)에 이어 MVP의 두 번째 durable 경계(공개 media)를 완성하고, #41에서 문서화한 "콜드스타트 × card.png" 리스크(공개 card 요청이 Postgres/Cloud Run을 직접 조회)를 R2 stable object로 해소한다.

## 배경

- #37에서 공개 card media는 R2 소유, private preview는 Cloud Run 렌더로 경계를 확정했다([`docs/production-hosting.md`](../../docs/production-hosting.md)의 "Public Media Contract").
- [`src/profile-media/media-store-contract.js`](../../src/profile-media/media-store-contract.js)는 5개 method(`putRevision`, `getRevision`, `publishRevision`, `getPublishedCard`, `unpublishCard`)와 object key 규칙, `image/png`·`public, no-cache, must-revalidate` 계약, memory fixture를 이미 정의한다. 그러나 **backend/runtime에 전혀 배선되어 있지 않다** — publish endpoint 없음, media store 주입 없음, R2 없음.
- 현재 공개 route `GET /u/{handle}/card.png`는 [`http.js:508`](../../src/profile-backend/http.js)에서 `cardService.renderPublicCard`로 **매 요청 on-demand 렌더**한다. R2 stable object 서빙으로 전환해야 한다.
- S3/R2 SDK는 아직 의존성에 없다. 신규 도입이 필요하다.
- #41이 확립한 패턴(env-gated 외부 adapter, `PROFILE_STORE_MODE=external` fail-closed, 로컬 Docker 검증, 벤더 중립 코드)을 media에도 대칭 적용한다.

## 범위

### 포함

- R2 adapter(S3 호환)로 media store 계약 5 method 구현, bucket/key/configuration 계약
- `cards/v1/owners/{ownerId}/revisions/{revision}.png` immutable write, `cards/v1/owners/{ownerId}/card.png` stable object materialization
- 인증된 owner의 publish/unpublish backend 서비스와 endpoint (render → putRevision → publishRevision)
- idempotent retry(같은 revision·bytes), conflict(같은 revision·다른 bytes), ETag/revision metadata
- 공개 route가 stable R2 object를 `public, no-cache, must-revalidate` + ETag/`If-None-Match` 조건부 요청으로 제공
- private preview 비저장 보장(owner private preview는 on-demand 렌더 유지)
- runtime wiring(`PROFILE_MEDIA_MODE=external` fail-closed, R2 credential은 server-only secret), readiness
- revision retention·orphan cleanup·failure recovery 기본 정책 문서화 + cleanup 도구

### 제외

- Neon structured data adapter(#41 완료)
- GIF 생성과 Web Share(#39), Share Studio UI 변경(#38)
- custom domain과 Cloud Run resource 생성(#43)

## 설계 방향

- **R2 client (벤더 중립, 승인 필요)**: R2는 S3 호환이다. client는 코드에 R2 고유 요소를 두지 않고 S3 API로 구현하며 "R2임"은 endpoint·credential·운영 문서에만 존재한다. 디렉터리는 `src/profile-media/r2/`(또는 `s3/`)로 벤더 중립 유지. SDK는 저장소 최소주의(#41의 `pg` 판단과 동일 기조)를 고려해 **`aws4fetch`(fetch 기반 SigV4, R2 검증됨, 초경량)** 를 권고하되, 표준 `@aws-sdk/client-s3`와 함께 승인받는다. Cloud Run은 장수 컨테이너라 어느 쪽도 무방하나 번들·의존성 크기에서 `aws4fetch`가 유리.
- **revision 식별자**: card ETag content digest(renderer version + owner + usage 기반, [`service.js` `createProfileCardEtag`](../../src/profile-card/service.js))를 object-key 안전 세그먼트로 정규화해 revision으로 사용한다. 같은 내용 재publish는 자연히 idempotent, 내용이 바뀌면 새 revision.
- **publish 원자성**: `putRevision`(immutable, 존재 시 same-bytes idempotent·different-bytes conflict) → `publishRevision`(revision을 stable key로 **copy**). S3/R2 copy는 성공 시 새 stable, 실패 시 이전 stable 유지 — "stable object 전환 실패 시 이전 public card 계속 제공"을 자연 충족. 부분 실패에서 immutable revision이 먼저 보존되므로 재시도가 안전.
- **serving 모델**: 공개 `/u/{handle}/card.png`는 published stable object가 있으면 R2에서 body+ETag로 서빙하고 `If-None-Match` 시 304. published가 없거나 owner private면 404(private data 비공개). owner private preview(`/api/profile/card.png`)는 on-demand 렌더 유지·R2 미저장.
- **runtime wiring**: `PROFILE_MEDIA_MODE=external`에서 R2 adapter 주입, credential 부재 시 fail-closed(#41 `createProductionStore` 대칭). 연결 secret은 adapter 생성 시점에만 로딩하고 config·log로 전파하지 않음. readiness는 bucket 접근성 확인.
- **retention/orphan**: unpublish는 stable object만 제거. immutable revision은 보존하되 orphan(어느 owner의 stable도 가리키지 않는 오래된 revision) 정리 기본 정책과 cleanup 도구(dry-run) 제공. failure recovery(부분 실패 후 재시도)는 idempotent write로 보장.
- **기존 패턴 유지**: memory media store는 계약 fixture로 유지, `node --test`·`__tests__/*.test.js`, env-gated 실 저장소(MinIO) test는 `TEST_S3_ENDPOINT` 없으면 skip해 `npm test`는 어디서나 green.

## 리스크

- **R2 client SDK 신규 의존성**: 크기·공급망. → 벤더 중립 코드 + 경량 SDK(`aws4fetch`) 권고, 승인 후 확정.
- **S3 호환 integration test 실행 환경**: 실제 R2 접근 제약. → 로컬 Docker MinIO(S3 호환) env-gated, 없으면 skip해 `npm test` green 유지.
- **publish 원자성 오해**: R2 copy가 실패해도 이전 stable 유지됨을 test로 고정. 부분 실패 재시도는 immutable idempotent write로 안전.
- **serving 전환 회귀**: 공개 route를 on-demand→R2로 바꾸며 기존 렌더 테스트 영향. → private preview 경로는 유지, 공개 경로만 전환하고 회귀 test로 고정.
- **credential 노출**: R2 secret이 bundle/log로 새는 위험. → adapter 생성 시점 로딩 한정, grep·bundle inspection으로 고정.

## 승인 요청 사항

1. **R2 client SDK**: `aws4fetch`(경량, 권고) vs `@aws-sdk/client-s3`(표준) 선택.
2. **publish 흐름 범위**: 인증된 owner publish/unpublish backend endpoint + 공개 route R2 서빙을 이 task에 포함(Share Studio UI는 제외).
3. **serving 모델**: 공개 `/u/{handle}/card.png`를 published R2 stable object로 서빙(미published/private → 404), private preview는 on-demand 렌더 유지.
4. **revision 식별자**: card ETag content digest 정규화 값 사용.
5. **env 이름**: `PROFILE_MEDIA_MODE=external`, R2 server-only secret(`R2_*`), gated test용 `TEST_S3_ENDPOINT`(MinIO).
6. **retention/orphan**: 기본 정책 문서 + dry-run cleanup 도구 포함.
7. 제외 범위(Neon/GIF/Share UI/Cloud Run 프로비저닝) 유지 확인.
