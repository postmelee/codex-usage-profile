# 수행계획서 — Task #42: R2 public card media 및 stable URL 구현

GitHub Issue: [#42](https://github.com/postmelee/codex-usage-profile/issues/42)
마일스톤: M100

## 목적

공개 card PNG를 R2(S3 호환 object storage)에 locale별 immutable revision과 handle 기반 stable public object로 안전하게 저장하고, README에 삽입한 stable image URL(`/u/{handle}/card.png`)이 최신 성공 publication을 ETag 재검증으로 제공하도록 구현한다. 최초 publish/unpublish뿐 아니라 이미 공개된 owner의 이후 Account Usage submit도 같은 URL을 자동 갱신한다. 재시도 멱등성, conflict, 동시 요청과 부분 실패에서도 이전 공개 publication을 보존하고 private preview는 R2에 저장하지 않는다.

이로써 #41(Neon structured store)에 이어 MVP의 두 번째 durable 경계(공개 media)를 완성한다. 공개 PNG route는 handle로 R2 stable object를 직접 찾고 Neon의 handle→ownerId 조회나 on-demand render를 수행하지 않으므로, #41에서 문서화한 Neon scale-to-zero 재개 지연이 공개 card 요청에 노출되는 리스크를 해소한다.

## 배경

- #37에서 공개 card media는 R2 소유, private preview는 Cloud Run 렌더로 경계를 확정했다([`docs/production-hosting.md`](../../docs/production-hosting.md)의 "Public Media Contract").
- [`src/profile-media/media-store-contract.js`](../../src/profile-media/media-store-contract.js)는 5개 method(`putRevision`, `getRevision`, `publishRevision`, `getPublishedCard`, `unpublishCard`)와 memory fixture를 정의하지만 backend/runtime에 배선되어 있지 않고, ownerId stable key 하나만 표현해 handle route와 `en`/`ko` representation을 함께 지원하지 못한다.
- 현재 공개 route `GET /u/{handle}/card.png`는 [`http.js`](../../src/profile-backend/http.js)에서 structured store를 조회하고 매 요청 on-demand render한다. 반면 private preview `GET /api/profile/card.png`의 on-demand render는 유지해야 한다.
- 현재 `PATCH /api/profile`은 Neon visibility만 변경한다. 이를 publish/unpublish orchestration의 기존 호환 endpoint로 유지해 현재 Home의 publish 동작을 깨뜨리지 않으면서 R2 publication과 visibility를 함께 처리해야 한다.
- README와 MVP 흐름은 최초 publish 뒤의 성공한 CLI submit이 같은 stable URL의 ETag와 이미지를 갱신한다고 약속한다. 따라서 공개 owner의 새 submit뿐 아니라 media 실패 뒤 exact retry에서도 publication 갱신을 다시 시도해야 한다.
- 현재 `createProfileCardEtag`는 renderer 입력 hash이며 실제 PNG bytes나 내려받은 avatar bytes의 digest가 아니다. immutable revision과 strong ETag에는 최종 PNG bytes의 SHA-256 digest를 사용해야 한다.
- S3/R2 SDK는 아직 의존성에 없다. 서버 전용 adapter의 Copy/List pagination, stream, XML error, retry와 MinIO 호환 구현량을 줄이기 위해 표준 modular client인 `@aws-sdk/client-s3`를 사용한다.

## 범위

### 포함

- S3-compatible R2 adapter로 media store 계약 5 method 구현, 계약 v2 key/configuration/metadata 정의
- locale별 immutable object: `cards/v2/owners/{ownerId}/revisions/{locale}/{revision}.png`
- handle 기반 stable public object: `cards/v2/public/{handle}/card.png`
  - body는 기본 `en` PNG
  - metadata는 publication id와 `en`/`ko` immutable key·revision·application ETag를 함께 보존
  - `ko` 요청은 stable metadata가 가리키는 immutable `ko` representation을 제공
- 인증된 owner의 기존 `PATCH /api/profile`을 통한 publish/unpublish orchestration
- 공개 owner의 `POST /api/account-usage/submit` 성공 후 자동 publication refresh와 exact retry 재시도
- final PNG bytes의 SHA-256 base64url digest를 locale별 revision으로 사용하고 quoted digest를 application ETag로 사용
- `putRevision`의 conditional create, same revision/same bytes 멱등, same revision/different bytes conflict
- 두 locale immutable write 완료 후 `en` revision을 stable key로 copy하면서 두 locale metadata를 함께 교체하는 단일 publication commit
- 공개 route의 stable R2 serving, `public, no-cache, must-revalidate`, ETag/`If-None-Match`, GET/HEAD
- private/missing/unpublished → 404, private preview on-demand render·R2 미저장
- owner 단위 publish/unpublish/refresh 직렬화, write/copy/delete/timeout/structured commit 실패 복구
- runtime wiring(`PROFILE_MEDIA_MODE=memory|external`), production external fail-closed, R2 server-only secret, readiness
- revision retention·orphan cleanup·failure recovery 기본 정책 문서화와 default dry-run cleanup 도구
- MinIO 또는 별도 S3-compatible endpoint에서 실행할 수 있는 env-gated integration test

## 설계 방향

- **S3 client**: `@aws-sdk/client-s3`를 서버 전용 의존성으로 사용한다. adapter 코드는 `src/profile-media/s3/`에 두고 endpoint·region·path-style 주입으로 R2와 MinIO를 모두 지원한다. R2라는 배포 선택은 env와 운영 문서에만 둔다. frontend import graph에 adapter나 credential loader가 들어가지 않도록 server-only export 경계를 test한다.
- **media contract v2와 주소 해소**: immutable revision은 변경 가능한 public handle과 분리해 ownerId 아래 보존한다. stable public key는 URL의 handle에서 바로 계산하므로 공개 PNG 요청이 Neon을 조회하지 않는다. handle 변경이 도입되면 이전 handle stable 제거를 같은 publication mutation에서 처리하도록 계약과 test를 둔다.
- **locale publication commit**: `en`과 `ko` PNG를 각각 immutable key에 먼저 conditional write한다. 마지막에 `en` revision을 handle stable key로 copy하면서 metadata를 replace해 두 locale의 key/revision/ETag와 publication id를 한 번에 기록한다. 이 copy가 publication의 단일 commit point이므로 copy 실패 시 이전 stable body와 locale metadata가 유지된다. `ko` route는 stable metadata가 가리키는 immutable object만 읽는다.
- **revision과 ETag**: 각 최종 PNG bytes를 SHA-256 후 base64url로 인코딩한 43자 digest를 revision으로 사용하고 HTTP application ETag는 `"{digest}"`로 사용한다. 기존 renderer-input ETag는 PNG cache용 `sourceDigest`로 역할을 분리한다. stable/R2 storage ETag와 application ETag를 혼동하지 않고 application ETag는 object metadata에 저장한다.
- **publish/unpublish orchestration**: 기존 `PATCH /api/profile`을 호환 facade로 유지한다. `public` 전환은 owner row를 serialization key로 잠근 structured transaction 안에서 최신 owner/usage를 재확인하고 두 locale render→immutable write→stable publication commit→visibility public 갱신 순으로 처리한다. R2 단계 실패는 structured transaction을 rollback한다. stable commit 뒤 structured commit이 실패하면 최초 private→public 전환은 stable 제거를 보상 동작으로 시도하고 명시적 partial-failure 오류를 반환한다.
- **unpublish privacy 우선**: 같은 owner serialization 아래 stable key를 먼저 삭제하고 성공한 경우에만 visibility를 private으로 갱신한다. delete 실패를 성공 또는 private으로 응답하지 않는다. delete 뒤 structured commit 실패는 PNG가 404인 privacy-safe 상태를 유지하고 재시도로 structured visibility를 수렴시킨다.
- **future submit refresh**: Account Usage structured transaction이 commit된 뒤 owner가 public이면 별도 owner-serialized publication refresh를 실행한다. media 갱신 실패 시 이전 stable publication을 유지하고 retriable service error를 반환한다. 저장된 Account Usage의 exact retry도 media refresh를 생략하지 않아 별도 background job 없이 복구할 수 있게 한다.
- **동시성 의미**: 동일 owner의 publish, unpublish와 submit refresh는 structured store의 owner row lock을 serialization key로 사용해 Cloud Run 다중 인스턴스에서도 순서를 고정한다. R2가 같은 key에서 last-completed-writer-wins라는 사실만으로 cross-store 일관성을 주장하지 않는다. 서로 다른 owner는 병렬 처리한다.
- **runtime wiring과 env**: development/spike 기본은 `PROFILE_MEDIA_MODE=memory`, production은 `external`만 허용한다. external adapter는 `R2_ENDPOINT`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`를 필수로 읽고 `R2_REGION`은 `auto`가 기본이다. access key와 secret은 server-only secret이고 endpoint/bucket/region은 운영 config다. config 객체와 log에는 credential 값을 복사하지 않는다.
- **integration test env**: `TEST_S3_ENDPOINT`, `TEST_S3_BUCKET`, `TEST_S3_ACCESS_KEY_ID`, `TEST_S3_SECRET_ACCESS_KEY`가 모두 있을 때만 실행한다. `TEST_S3_REGION`은 기본 `us-east-1`, MinIO는 `TEST_S3_FORCE_PATH_STYLE=true`로 지원한다. 임의 기본 credential을 가정하지 않고 test별 고유 prefix만 생성·정리한다.
- **retention/orphan**: 현재 stable metadata가 참조하는 모든 locale revision은 무조건 보존한다. 그 외 revision은 owner·locale별 최근 5개 또는 생성 후 90일 이내 중 더 넓은 집합을 보존한다. cleanup은 기본 dry-run이며 명시적 `--apply`에서만 삭제한다. pagination, 대상 prefix 제한, 삭제 직전 stable metadata 재확인으로 concurrent publish가 다시 참조한 revision 삭제를 막는다. 자동 schedule과 실제 운영 값 조정은 #43에 남긴다.

### 통합 검증

- 같은 locale revision/bytes 재시도는 멱등이고 같은 revision/different bytes는 conflict다.
- 두 locale immutable write 또는 final stable copy 실패 시 이전 stable publication의 body와 locale metadata가 유지된다.
- 최초 publish 뒤 공개 owner의 changed submit과 media failure 뒤 exact retry가 같은 public URL을 최신 성공 publication으로 갱신한다.
- publish/unpublish/submit refresh 동시 요청은 owner 단위로 직렬화되고 최종 visibility와 stable 존재 여부가 일치한다.
- unpublish delete 실패는 public visibility를 유지하며, 성공한 unpublish 뒤 공개 route는 private/missing과 같은 404를 반환한다.
- 공개 route는 handle로 R2를 직접 조회하고 structured store나 renderer를 호출하지 않는다.
- 공개 route는 stable 부재·불완전 publication·referenced revision 불일치에 404를 반환하고, R2 provider·timeout·bucket 장애에는 owner-agnostic `media_unavailable` 503을 반환한다.
- 기본 locale stable HEAD→GET 사이 conditional 412가 발생하면 publication HEAD부터 한 번만 재시도하며, 반복 경합은 404로 접지 않고 503으로 반환한다.
- default/`locale=ko` URL이 각 representation의 strong application ETag를 재검증하며 304와 HEAD는 body를 반환하지 않는다.
- private preview는 on-demand render를 유지하고 R2에 revision/stable object를 만들지 않는다.
- R2 credential과 private payload가 client bundle, response, log에 노출되지 않는다.
- cleanup은 stable metadata가 참조하는 revision과 owner·locale별 최근 5개/90일 보존 집합을 삭제하지 않는다.
- `npm test`, `npm run build`, `git diff --check`가 통과하고 PR 준비 전 작업 상태를 검토한다.

## 리스크

- **서버 의존성 증가**: `@aws-sdk/client-s3`가 `aws4fetch`보다 크다. → server-only import 경계를 지키고, raw S3 XML/error/retry/pagination 구현을 저장소에 추가하지 않는 쪽을 우선한다.
- **cross-store 완전 원자성 부재**: Neon transaction과 R2 copy/delete는 하나의 distributed transaction이 아니다. → owner row serialization, stable copy 단일 commit point, privacy-first ordering, 보상 동작과 partial-failure test로 허용 상태를 고정한다.
- **locale publication 부분 실패**: 두 PNG를 별도 stable object로 덮으면 mixed revision이 생긴다. → `en` stable body와 두 locale pointer metadata를 한 번에 교체하는 단일 stable copy를 publication commit으로 사용한다.
- **application/storage ETag 혼동**: R2 storage ETag를 card content digest로 오인하면 conditional response와 revision 계약이 흔들린다. → PNG SHA-256 application ETag를 metadata에 저장하고 storage ETag는 S3 conditional mutation에만 사용한다.
- **S3 호환 차이**: MinIO 통과가 실제 R2 remote 검증을 의미하지 않는다. → 표준 S3 API만 사용하고 같은 gated suite가 R2 endpoint에도 실행될 수 있게 하며 실제 remote smoke/resource 구성은 #43에서 수행한다.
- **transaction 중 외부 I/O**: owner lock을 잡은 publication이 avatar fetch/R2 timeout 동안 connection을 점유한다. → owner별 저빈도 mutation으로 한정하고 명시적 avatar/R2 timeout을 두며 서로 다른 owner는 병렬 처리한다.
- **cleanup과 publish 경쟁**: 오래된 immutable revision을 concurrent publication이 다시 참조할 수 있다. → 90일/최근 5개 guard와 삭제 직전 stable metadata 재확인을 함께 적용한다.
- **credential 노출**: R2 secret이 bundle/log로 새는 위험. → adapter 생성 시점 로딩 한정, config 비복사, bundle/log scan으로 고정한다.
- **일시적 provider 장애의 404 캐시**: public route가 R2 unavailable을 publication 부재와 같은 404로 접으면 이미지 proxy가 실패를 오래 유지할 수 있다. → invalid/missing publication만 404로 두고 provider·timeout은 generic 503, conditional read race는 1회 bounded retry 뒤 503으로 구분한다.

## 승인된 결정

1. **S3 client**: `@aws-sdk/client-s3`를 사용한다.
2. **publish 범위**: 기존 인증 owner visibility endpoint의 publish/unpublish orchestration, 공개 route R2 serving과 공개 owner의 future submit 자동 refresh를 포함한다. Share Studio UI는 제외한다.
3. **serving 모델**: ownerId immutable + handle stable publication, `en`/`ko` representation을 R2에서 제공한다. 미published/private·불완전 publication은 404, provider·timeout 장애는 generic 503이며 private preview는 on-demand render를 유지한다.
4. **revision 식별자**: 최종 PNG bytes SHA-256 base64url digest를 revision과 quoted application ETag로 사용한다.
5. **env 이름**: `PROFILE_MEDIA_MODE=memory|external`, `R2_ENDPOINT`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, optional `R2_REGION`; gated test는 완전한 `TEST_S3_*` 설정과 optional path-style을 사용한다.
6. **retention/orphan**: referenced revision 무조건 보존 + owner·locale별 최근 5개 또는 90일 이내 보존, default dry-run cleanup 도구를 포함한다. scheduling은 #43에서 확정한다.
7. **제외 범위**: Neon adapter 재구현, durable job/outbox, GIF/Web Share, Share Studio UI, R2/Cloud Run resource provisioning, npm production publish는 제외한다.
