# Task M100 #35 수행계획서

GitHub Issue: [#35](https://github.com/postmelee/codex-usage-profile/issues/35)
마일스톤: M100
계획 변경 승인: 2026-08-02

## 목적

Codex usage card 자체는 공유와 README 삽입에 적합한 정적 이미지로 유지하고,
날짜별 상세 사용량 interaction은 owner 및 public Profile의 전용 52주 token
activity heatmap에서 제공한다.

Profile heatmap은 Account Usage Contract v1의
`dailyUsageBuckets[{ startDate, tokens }]`를 사용해 일별, 주간, 누적 보기를 제공한다.
desktop hover와 keyboard focus, touch tap에서 기간과 토큰 사용량을 확인할 수 있어야
하며 기존 Profile의 공개/비공개, Share와 card preview 기능을 보존한다.

## 계획 변경 배경

최초 계획은 Home과 public card PNG 위에 26주 × 7일 투명 interaction overlay를
합성하는 것이었다. Stage 1에서 card geometry와 tooltip pure contract를, Stage 2에서
실제 overlay와 source 연결을 구현했다.

작업지시자 검토 결과, 공유 card는 간결한 정적 표현으로 유지하고 상세 탐색 기능을
Profile에 집중하는 편이 제품 정보 구조와 모바일 interaction에 더 적합하다고
판단했다. 아직 Task #35가 PR로 병합되지 않았으므로 같은 이슈에서 방향을 변경한다.

| 기존 Stage | 상태 | 변경 후 처리 |
|---|---|---|
| Stage 1 — card geometry와 tooltip contract | 완료 기록 보존, 제품 방향은 대체됨 | card overlay에만 필요했던 geometry/helper는 최종 diff에서 정리 |
| Stage 2 — Home/public card overlay | 완료 기록 보존, 제품 방향은 대체됨 | Home과 card image의 tooltip overlay를 제거 |
| 기존 Stage 3 — card overlay QA | 취소 | Profile 중심 Stage 3~5로 대체 |

기존 단계 커밋과 보고서는 당시 구현·검증 기록으로 보존한다. Git history를 재작성하지
않고 이후 단계에서 최종 제품 범위에 필요 없는 변경을 명시적으로 제거한다.

## UX 및 데이터 설계

### Profile 정보 구조

- 현재 Site의 공통 header를 유지한다.
- Profile 첫 영역은 GitHub identity, visibility와 Account Usage summary stats를 표시한다.
- `Token activity`를 핵심 상세 영역으로 배치하고 일별·주간·누적 mode control을 둔다.
- owner Profile의 card preview와 publish/share control은 별도 `Your Codex card` 영역으로
  유지해 analytics 탐색과 공유 작업을 분리한다.
- public Profile도 공개 API가 이미 제공하는 동일 daily bucket으로 token activity를
  표시하되 owner 전용 mutation control은 노출하지 않는다.
- Account Usage Contract에 없는 activity insight와 plugin ranking은 표시하지 않는다.

### Heatmap mode 의미

- 일별은 각 cell이 한 UTC 날짜와 그 날짜의 실제 token 수를 나타낸다.
- 주간은 Sunday 기준 한 주의 합계를 계산한다. 같은 주 합계를 7개 독립 focus target에
  중복하지 않고 한 column을 하나의 semantic target으로 취급한다.
- 누적은 화면에 표시된 52주 시작일부터 해당 주 종료일까지의 running total이다.
- mode별 intensity는 해당 mode의 표시 값 최댓값을 기준으로 독립적으로 계산한다.
- 데이터가 없는 날짜는 0이며 미래 날짜는 interaction과 합계에서 제외한다.

### Tooltip 및 접근성

- tooltip은 `2026년 8월 2일 · 1.2억 토큰 (123,456,789)`처럼 축약값과 정확한 값을
  함께 제공한다. weekly/cumulative는 기간 또는 `~까지` 의미를 명시한다.
- visual tooltip과 `aria-label`은 같은 formatter를 사용한다.
- 일별 grid는 Tab 한 번으로 진입하고 Arrow key로 날짜를 이동한다.
- 주간·누적 grid는 한 주 단위로 좌우 이동하며 불필요한 7개 중복 focus를 만들지 않는다.
- tooltip은 viewport 경계를 clamp하고 위 공간이 없으면 아래에 배치한다.
- pointer, keyboard와 touch 상태를 분리하고 mode/source 변경 시 열린 tooltip을 닫는다.

### 구현 재사용

- 현재 사용되지 않는 `TokenActivityChart`와 `buildTokenHeatmap`의 52주, mode, month
  label, responsive 기반을 Account Usage Contract v1 입력에 맞게 정리해 재사용한다.
- legacy snapshot의 `dailyUsage[{ date, credits }]`를 웹 canonical 입력으로 삼지 않고
  `dailyUsageBuckets[{ startDate, tokens }]`를 Profile heatmap의 진실 원천으로 둔다.
- owner와 public Profile은 같은 pure builder와 component를 사용해 mode 계산과
  tooltip formatting drift를 방지한다.

## 수용 기준

- Home, owner/public card image와 README card에는 tooltip target이 없다.
- owner 및 public Profile은 실제 해당 사용자의 daily bucket으로 52주 heatmap을 만든다.
- 일별, 주간, 누적 mode가 정의된 기간과 합계로 정확히 계산된다.
- 주간·누적 mode는 한 주당 하나의 semantic interaction target을 제공한다.
- tooltip은 축약값과 정확한 token 수를 함께 표시하고 locale/UTC 경계를 지킨다.
- hover, keyboard focus와 touch tap에서 동일한 정보가 제공된다.
- 좁은 화면은 최근 기간을 우선 보이며 문서 전체 horizontal overflow를 만들지 않는다.
- owner visibility/share와 public card URL 동작에 회귀가 없다.
- no-usage 또는 불완전 payload에서 임의 demo 값이나 다른 사용자의 값이 노출되지 않는다.
- API, D1/R2, CLI, card renderer와 Sites hosting manifest에 변화가 없다.

## 리스크와 대응

- **기존 미사용 chart의 legacy `credits` 계약**: Account Usage Contract의 `tokens`와
  혼용하지 않고 canonical adapter/builder 입력을 명시적으로 바꾼다.
- **weekly/cumulative 중복 의미**: 7개 cell에 같은 값을 중복 focus하지 않고 week
  column을 하나의 semantic unit으로 만든다.
- **public privacy 오인**: public Profile은 이미 공개 API가 반환하는 daily bucket만
  사용하고 private owner data를 fallback으로 섞지 않는다.
- **52주 mobile overflow**: chart wrapper만 수평 스크롤하고 최초·mode 변경 시 최근
  기간을 표시하며 page-level overflow는 금지한다.
- **기존 card 변경 잔존**: Stage 3에서 `origin/devel` 대비 card renderer, Home overlay,
  static asset diff를 검사해 대체된 방향의 코드를 제거한다.
- **범위 확장**: Account Usage Contract에 없는 activity insight, plugin/skill 통계를
  추가하지 않는다. 필요하면 별도 이슈로 분리한다.
