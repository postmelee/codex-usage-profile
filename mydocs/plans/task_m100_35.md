# Task M100 #35 수행계획서

GitHub Issue: [#35](https://github.com/postmelee/codex-usage-profile/issues/35)
마일스톤: M100

## 목적

웹에 표시되는 26주 × 7일 Codex usage card의 각 heatmap 셀에서 날짜와
집계 토큰 사용량을 확인할 수 있게 한다. desktop에서는 hover와 keyboard
focus, touch 환경에서는 tap으로 같은 정보를 제공하고, tooltip은 카드와
viewport 경계를 벗어나지 않도록 보정한다.

정적 PNG/GIF와 stable README card URL은 그대로 유지한다. interaction layer는
PNG 위의 웹 UI에만 추가하고, 기존 tilt, glare, Border Beam, loading skeleton과
공개 profile 동작을 보존한다.

## 배경

Account Usage Contract v1과 owner/public profile API는 이미
`dailyUsageBuckets[{ startDate, tokens }]`를 제공한다. `src/profile-card/heatmap.js`는
이 데이터를 26 × 7 column-major cell로 정규화하지만, Node canvas renderer와
Sites worker renderer는 heatmap 위치 상수를 각각 보유하고 있어 웹 interaction
layer가 재사용할 단일 geometry 계약은 없다.

현재 Landing의 `MarketingCardPreview`는 `<img>` 위에 personalized identity,
loading skeleton과 glare를 겹쳐 표시하며 desktop에서는 `hover-tilt`를 사용한다.
owner card에는 실제 usage payload가 있고 public profile API도 공개된 daily
bucket을 반환한다. 반면 anonymous/static sample에는 API payload가 없으므로
sample fixture를 명시적인 demo 데이터로 사용해야 한다. 실제 usage가 없는
로그인 사용자의 personalized sample에는 demo 수치를 실제 사용자 데이터처럼
노출하지 않는다.

기존 `TokenActivityChart`에도 별도의 52주 chart tooltip이 있으나 geometry,
mode와 화면 역할이 다르다. 이번 task는 그 chart를 확장하지 않고 share card의
26주 renderer와 정확히 일치하는 전용 overlay를 만든다.

## 범위

### 포함

- Node canvas renderer, Sites worker renderer와 웹 overlay가 공유하는 card 및
  26 × 7 heatmap geometry 진실 원천
- `buildCardHeatmap` 결과를 사용하는 재사용 가능한 투명 interaction layer
- owner Home card와 public web profile card의 실제 daily bucket 연결
- anonymous static sample card의 deterministic demo bucket 연결
- anonymous operator card는 대응 public profile payload가 확인될 때만 tooltip을
  활성화하고, payload 불일치 또는 부재 시 interaction을 표시하지 않는 fail-safe
- 실제 usage가 없는 로그인 사용자의 personalized sample에서 demo tooltip 비활성화
- pointer hover, keyboard focus, touch tap, 외부 pointer와 Escape 닫기
- 하나의 tab stop과 arrow-key 이동을 사용하는 roving grid keyboard interaction
- 영어·한국어 날짜와 token count formatting, screen-reader용 cell label
- 카드 내부 우선 배치와 viewport 경계 보정, 모서리 cell의 위/아래 placement 전환
- tilt, glare, Border Beam, loading skeleton과 share transition 회귀 검증
- desktop/mobile/reduced-motion Playwright와 geometry/formatting unit test

### 제외

- PNG, GIF 파일 내부 또는 GitHub README 이미지의 interaction
- 정적 card pixel 디자인, renderer version, ETag/revision, R2 object 변경
- Account Usage Contract, owner/public profile API 응답 형식, backend, D1/R2 schema 변경
- `codex-usage-analyzer`와 CLI 변경
- daily bucket 이외 token breakdown 또는 새 analytics chart
- 기존 52주 `TokenActivityChart`의 mode·tooltip 재설계
- Share Studio preview와 export 결과에 tooltip 합성
- production Sites 배포, environment/access/secret 또는 공개 URL 변경

## 설계 방향

- `src/profile-card/geometry.js`를 logical card size와 heatmap bounds/cell size,
  column·row step 계산의 단일 진실 원천으로 둔다. Node canvas와 worker SVG
  renderer는 이 값을 import하고 웹 overlay는 같은 geometry를 비율 좌표로
  사용한다. geometry를 복제한 CSS magic number는 만들지 않는다.
- `buildCardHeatmap`의 column-major `cells`가 날짜·token 매핑의 진실 원천이다.
  overlay는 PNG 색을 재현하지 않고 투명 hit target만 만들며, 각 target은
  renderer cell의 중심과 대응한다.
- 웹 interaction은 `CardHeatmapOverlay` 후보 component로 캡슐화한다. Home의
  owner/sample/operator와 public profile이 같은 component를 사용하고, 데이터가
  card source와 일치할 때만 렌더한다.
- Home은 보이는 card source와 tooltip payload를 함께 전환한다. owner source는
  `profile.usage.usage.dailyUsageBuckets`, static sample은 고정 sample fixture,
  operator source는 같은 handle의 public profile payload를 사용한다. source와
  payload가 불일치하거나 loading/error 상태이면 overlay를 숨겨 stale tooltip을
  방지한다.
- public profile은 이미 로드된 `profile.usage.usage.dailyUsageBuckets`와
  `publicCardUrl`을 같은 wrapper에 전달한다. public API contract는 변경하지 않는다.
- keyboard 접근은 182개 cell을 모두 Tab 순서에 넣지 않는다. grid 안에 roving
  `tabIndex` 하나를 두고 Arrow key로 날짜 cell을 이동하며 focus 시 tooltip과
  `aria-label`을 제공한다. Escape는 tooltip을 닫되 focus는 유지한다.
- pointer hover는 fine pointer에서, tap toggle은 touch/coarse pointer에서
  동작한다. 외부 pointer와 focus 이동 시 열린 tap tooltip을 닫고 동일 cell
  재탭은 toggle한다.
- tooltip 문자열은 `Intl.DateTimeFormat`과 기존 card locale/token formatter를
  재사용해 `en`/`ko`만 지원한다. locale은 현재 share card와 동일하게
  `resolveShareLocale(navigator.language)` 결과를 사용한다.
- tooltip은 card media wrapper를 기준으로 측정 후 좌우 clamp하고, 위 공간이
  부족하면 아래에 배치한다. transform된 `hover-tilt` 내부에서도 cell hit target과
  tooltip이 같은 좌표계를 사용하게 하며 document horizontal overflow를 만들지 않는다.
- skeleton/loading/share transition 중에는 overlay를 inert/hidden 처리한다.
  glare는 시각 layer로 유지하되 interaction을 가로채지 않게 한다.

## 리스크

- **renderer/overlay 좌표 drift**: Node와 worker가 상수를 계속 복제하면 responsive
  overlay가 pixel cell과 어긋난다. shared geometry와 parity unit test로 고정한다.
- **card source와 usage mismatch**: Home은 sample, operator와 owner source를
  비동기로 전환한다. source identity와 payload readiness를 함께 확인하고
  불일치 시 overlay를 숨긴다.
- **182개 focus target의 keyboard 피로**: 모든 cell을 Tab 순서에 넣지 않고
  roving tab stop과 arrow-key grid navigation을 사용한다.
- **tilt pointer 회귀**: 투명 button layer가 custom element의 pointer tracking을
  막을 수 있다. event bubbling, pointer-events와 transform 좌표를 E2E로 검증한다.
- **tooltip clipping/overflow**: card wrapper의 `overflow: hidden`과 transformed
  stacking context 때문에 모서리 tooltip이 잘릴 수 있다. 측정 기반 clamp와
  placement 전환을 사용하고 document overflow를 검증한다.
- **touch hover 중복**: emulated mouse event가 tap 뒤 tooltip을 즉시 닫거나 다시
  열 수 있다. pointer type별 activation을 분리하고 outside pointer를 검증한다.
- **sample 수치 오인**: 로그인했지만 usage가 없는 사용자에게 demo bucket을
  개인 usage처럼 표시하지 않는다. anonymous static sample에만 demo 표시를 허용한다.
- **범위 확장**: API contract, renderer visual, Share Studio와 52주 chart를 함께
  변경하지 않는다. 필요성이 발견되면 계획 변경 또는 별도 issue로 분리한다.

- `src/profile-card/geometry.js`를 Node renderer, Sites worker renderer와 웹 overlay의
  card/heatmap geometry 단일 진실 원천으로 두는 방향
- overlay는 PNG를 다시 그리지 않고 `buildCardHeatmap` cell 위에 투명 hit target만
  배치하는 방향
- owner/public은 실제 profile usage, anonymous static sample은 fixture,
  anonymous operator는 대응 public profile payload가 확인된 경우에만 활성화하는
  source-aligned data 정책
- authenticated no-usage personalized sample에는 demo tooltip을 표시하지 않는 정책
- 182개 Tab stop 대신 roving tab stop과 Arrow key navigation을 제공하는 접근성 방향
- 기존 card locale에 맞춘 `en`/`ko` formatting과 card/viewport clamp 정책
- 공식 제품 문서는 변경하지 않고 task 산출물만 기록하는 문서 위치 판단
- backend/API/D1/R2, static card design·asset, Share Studio export, production 배포와
