# Task #83 수행계획서 — 누적 Sites 후보 production artifact preflight와 owner-only 배포 검증

GitHub Issue: [#83](https://github.com/postmelee/codex-usage-profile/issues/83)
마일스톤: M100

## 목적

Task #74·#78·#81이 누적된 Sites 후보에서 production artifact에 포함된 절대 로컬 경로를 제거하고, 동일 문제가 다시 배포 archive에 유입되지 않도록 재현 가능한 검증 경계를 고정한다. 보정 뒤에는 검증한 exact source commit과 그 commit에서 만든 artifact만 기존 Sites project의 owner-only saved version으로 배포한다.

owner-only 후보에서 D1 migration `1..5` readiness, maintenance 비활성화, OAuth·CLI·private preview·publish/unpublish·README 카드·canonical OG 문서·social image 계약을 확인한다. 별도 승인된 Gate B에서만 잠시 public access를 열어 `/u/{handle}` 캐시 헤더와 submit 직후 `og:image?v=` 갱신을 실측하고, 즉시 owner-only·private·credential/data 정리 baseline으로 복원한다. 완료 결과는 후속 릴리스 [#84](https://github.com/postmelee/codex-usage-profile/issues/84)의 명시적 선행 증적으로 넘긴다.

## 배경

현재 `npm run build:production`과 `npm run verify:sites-fullstack`은 통과하지만 `npm run verify:sites-production`은 `dist/server/.vite/manifest.json`의 `/Users/...` 경로 때문에 실패한다. 이 manifest에는 renderer Wasm과 글꼴 원본의 절대 경로가 기록되며, Sites packaging helper는 `dist/` 전체를 archive에 포함하므로 검증을 우회해 배포할 수 없다. production verifier의 절대 경로 차단은 credential·로컬 환경 유출을 막는 독립 보안 경계이므로 완화하지 않는다.

`/u/{handle}`은 짧은 shared-cache 지시자를 선언하지만 application이 Workers Cache API를 직접 사용하지 않는다. ChatGPT Sites 외부 계층이 동적 HTML에 적용하는 실제 캐시는 로컬 계약만으로 확정할 수 없으므로, 보정 코드에 추측성 cache configuration을 추가하지 않고 Gate B에서 `CF-Cache-Status`, `Age`, `x-request-id`, `og:image?v=`를 시간 순서로 측정한다.

현재 production baseline은 saved version 7, public access, migration `1..2`, maintenance disabled, operator secret absent다. 원격 mutation은 단계별 read-only snapshot과 별도 Gate 승인 뒤에만 수행하며, application rollback은 이전 saved version을 사용하고 data/schema downgrade는 수행하지 않는다.

## 설계 방향

- **차단 계약 유지**: `verify:sites-production`의 절대 경로 패턴을 완화하거나 해당 manifest를 검사 예외로 만들지 않는다. production runtime과 Sites package에 필요하지 않은 metadata라면 build 완료 시 artifact에서 제거하고, 필요하다면 절대 경로만 안정적인 상대 식별자로 정규화한다.
- **runtime 필요성부터 증명**: manifest를 제거하기 전에 `wrangler.json`, Worker entry, emitted JS/Wasm/font 참조와 package archive를 대조한다. runtime이 참조하지 않는다는 테스트 증거가 있을 때만 제외한다.
- **최소 source 변경**: 우선 후보는 `build/sites-fullstack-vite-plugin.js`와 관련 회귀 테스트다. Cloudflare plugin hook 순서 때문에 정리 시점이 불안정하면 `vite.sites-fullstack.config.js`의 plugin ordering 또는 명시적 post-build 경계를 함께 검토하되, Worker·renderer 제품 코드는 수정하지 않는다.
- **verifier 독립성**: full-stack verifier는 runtime shape와 migration manifest를, production verifier는 exact binding·migration allowlist·secret/path·size를 계속 독립 검증한다. fix가 verifier를 약화하는 방식이면 채택하지 않는다.
- **exact provenance**: local 검증이 끝난 commit을 source로 push하고 같은 commit에서 다시 만든 `dist/`를 Sites helper로 package한다. saved version의 `commit_sha`, artifact와 단계 보고서의 candidate SHA를 일치시킨다.
- **migration/readiness 분리**: migration `3..5` 적용은 mutation이며 readiness는 read-only다. owner-only·maintenance window에서 적용한 뒤 `appliedVersions`와 `expectedVersions`가 순서까지 `[1,2,3,4,5]`인지 확인한다. missing·unexpected version이면 기능 smoke와 public Gate를 중단한다.
- **원격 Gate 분리**: owner-only 배포·environment·migration은 Gate A, 잠시 public access를 여는 실측은 Gate B로 분리한다. 각 Gate 직전 project/version/access/environment/quota와 rollback target을 read-only로 제시하고 별도 승인을 받는다.
- **fail-closed rollback**: 배포·readiness·maintenance 비활성화·smoke 중 하나라도 실패하면 public으로 진행하지 않는다. owner-only access, 이전 saved version 또는 승인된 candidate, maintenance disabled/secret-absent를 복원하고 operator route와 health를 재확인한다.
- **캐시 판단은 측정 기반**: 같은 URL의 반복 GET/HEAD, submit 직후와 경과 후 요청을 순서대로 측정한다. application HTML/ETag/리비전 갱신과 외부 cache header를 분리해 기록하며, privacy·publish 정합성 문제만 release blocker로 분류한다. 단순 최적화는 별도 이슈로 넘긴다.

## 리스크

- **build hook 순서**: 정리 hook이 Cloudflare plugin보다 먼저 끝나면 manifest가 다시 생성될 수 있다. 실제 hook 순서를 테스트로 고정하고 최종 `dist/`에서 검증한다.
- **필수 runtime metadata 오삭제**: `.vite` 전체를 근거 없이 제거하면 Worker asset 참조가 깨질 수 있다. emitted entry/config/import를 대조하고 불필요성이 증명된 파일만 제외한다.
- **verifier 우회**: 검사 예외나 path pattern 축소는 다른 로컬·credential 노출을 허용할 수 있다. verifier는 독립적으로 유지하고 artifact producer를 보정한다.
- **migration 뒤 application rollback**: migration `3..5` 적용 뒤 saved version 7로 돌아갈 수 있어야 한다. additive/backward-compatible 근거와 backup 가능성을 Gate A 전에 확인하고 schema downgrade는 하지 않는다.
- **원격 데이터·credential**: OAuth code, session, token, owner/usage와 backup payload가 로그·문서·archive에 남을 수 있다. exact disposable scope와 redacted count/digest만 보고하고 cleanup을 검증한다.
- **cache 오판**: 외부 edge cache와 application 리비전 갱신을 혼동할 수 있다. 시간 순서, response header, HTML revision과 image ETag를 함께 기록한다.
- **공개 상태 잔류**: Gate B 중간 실패가 public access를 남길 수 있다. 실패 원인 분석 전에 owner-only를 먼저 복원하고 anonymous gate를 재확인한다.
- **Sites quota·과금**: public beta quota나 plan 정책이 바뀔 수 있다. Gate마다 추가 결제·자동 초과 과금 표시를 확인하고 요구되면 mutation을 중단한다.

## 승인 요청 사항

- production verifier를 완화하지 않고 artifact producer에서 불필요한 manifest를 제거하거나 필요한 경우 상대 경로로 정규화하는 방향
- build metadata의 runtime 필요성을 먼저 증명하고 최소 파일만 다루는 범위
- 공식 문서는 장기 운영 사실이 달라질 때만 기존 `docs/` 문서를 최소 갱신하고, 원시 실측은 `mydocs/` task 증적에 두는 위치 판단
- Stage 1~4 구성과 Stage 3 Gate A·Stage 4 Gate B를 각각 별도 승인으로 중단하는 절차
- migration `3..5` 적용과 read-only readiness를 구분하고 exact `1..5`만 통과시키는 기준
- Gate B 뒤 영구 공개가 아니라 owner-only baseline으로 즉시 원복하며, #84에서 Gate C와 `main` 릴리스를 수행하는 handoff 경계

승인되면 `task_m100_83_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지와 Gate 입력을 구체화한다.
