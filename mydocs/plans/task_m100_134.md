# Task #134 수행계획서 — CLI 재인증 복구와 도움말·온보딩 UX 정합성 개선

GitHub Issue: [#134](https://github.com/postmelee/codex-usage-profile/issues/134)
마일스톤: M100

## 목적

저장된 로컬 자격 증명이 만료되거나 서버에서 폐기된 경우에도 사용자가 `npx codex-usage-profile@latest submit` 한 번으로 브라우저 재승인과 사용량 제출을 안전하게 마칠 수 있도록 CLI 복구 경계를 보정한다. 전역·명령별 도움말, 잘못된 입력의 도움말 유도, 웹 빈 상태와 공개 문서를 같은 사용자 계약으로 맞춰 정식 공개 전 첫 사용과 재인증 경험의 단절을 제거한다.

## 배경

현재 `submit`은 로컬 자격 증명이 없으면 device login을 시작하고 같은 프로세스에서 제출을 이어가지만, 파일 자격 증명으로 제출한 요청이 HTTP 401/410을 받으면 `login`과 `submit`을 수동으로 다시 실행하라는 오류로 종료한다. production 테스트 계정을 초기화한 뒤 기존 로컬 자격 증명으로 제출하면서 이 경로가 재현됐다. 웹 빈 상태는 `submit` 하나만 안내하므로 실제 CLI 동작과 사용자 약속이 어긋난다.

CLI에는 이미 전역 `-h, --help`와 `-v, --version`이 있지만 모든 command 뒤의 help도 같은 전역 문서를 반환하고, 잘못된 명령·옵션은 다음 행동을 안내하지 않는다. 루트 README와 npm README의 Commands도 코드 블록 중심이며 help/version과 명령별 용도를 빠르게 비교하기 어렵다.

## 범위

### 포함

- 파일 자격 증명을 사용한 첫 제출이 확정적 인증 실패인 HTTP 401/410이면 기존 device login 흐름으로 다시 승인받고 원래 제출을 정확히 한 번 재시도한다.
- 재로그인 성공 전에는 기존 자격 증명을 삭제하지 않고, 성공 시 기존 atomic credential 저장 경계로 교체한다.
- 환경 변수 자격 증명이 401/410을 받으면 자동 교체하지 않고 환경 변수 해제와 재로그인 방법을 안내한다.
- 인증 외 오류와 재인증 뒤 두 번째 인증 실패는 추가 로그인·제출 반복 없이 기존 오류 경계로 종료한다.
- 전역 help와 `login`, `status`, `submit`, `logout`별 help를 실제 옵션 범위와 맞추고 잘못된 입력에 실행 가능한 help 힌트를 제공한다.
- 루트 README와 npm README의 Commands를 사용자 중심 표로 통일하고 help/version을 포함한다.
- `docs/cli-submit.md`에 재인증, 상세 명령·옵션, 복구 경계를 기록한다.
- 웹 빈 프로필의 영어·한국어 제목과 설명을 한 명령어로 로그인부터 제출까지 이어지는 동작에 맞춘다.
- CLI 단위·통합, npm package smoke, UI E2E와 문서 정합성 검증을 보강한다.

### 제외

- 서버 인증, device login API, submit API와 credential file schema 변경
- 로그인 실패·취소 시 기존 파일 자격 증명 선제 삭제
- 환경 변수 자격 증명의 자동 제거·교체
- 공개 README Commands 표에 내부·고급 용도의 `--server` 노출
- npm version bump·publish, `devel`→`main` release PR과 production 배포
- Stage5 데이터·배포 변경

## 설계 방향

- **한 명령어 계약**: 자격 증명 부재와 만료된 파일 자격 증명을 `submit` 관점에서 같은 device approval 흐름으로 수렴시킨다. 기존 `login` command도 유지하되 정상 사용의 필수 선행 단계로 문서화하지 않는다.
- **제한된 재시도**: 인증 복구는 `submit_auth_failed`로 정규화된 최초 401/410과 `source === "file"`인 경우에만 한 번 허용한다. 네트워크 unknown, conflict, rate limit, media refresh failure와 contract rejection은 기존 재시도·오류 의미를 유지한다.
- **credential 보존**: device login이 승인된 뒤 credential store가 atomic save를 완료할 때만 새 토큰으로 바뀐다. 실패·취소·만료에서는 이전 파일을 제거하지 않는다. 환경 변수 토큰은 파일보다 우선하는 현재 계약을 유지하고 수정하지 않는다.
- **출력·보안 경계**: 사용자 메시지는 토큰, owner ID, 내부 응답 본문을 포함하지 않는다. JSON·비대화형 실행은 환경 토큰 복구를 자동화하지 않으며 기존 machine-readable 결과 경계를 회귀시키지 않는다.
- **help 구조**: 전역 usage와 command별 usage를 하나의 코드 진실 원천으로 구성하고 `-h/--help`, `-v/--version` 호환성을 유지한다. unknown command/option은 원래 오류와 nonzero exit을 유지하면서 전역 또는 해당 command의 help 실행 예를 안내한다.
- **문서 표면 분리**: 루트·npm README에는 일반 사용자가 필요한 명령과 help/version만 표로 제공한다. `--json`, `--timeout`, 환경 변수와 고급 origin override는 `docs/cli-submit.md` 및 실제 CLI help에서 설명한다.
- **웹 역할**: 웹은 로컬 credential 상태를 탐지하려 하지 않는다. 빈 상태에서는 `submit` 한 번으로 필요 시 브라우저 승인이 이어진다는 기대만 짧게 설명한다.

### 통합 검증

- `submit` 하나로 credential 없음과 만료된 파일 credential 모두 승인 후 성공하고, login·submit 요청 횟수가 bounded하다.
- environment token과 인증 외 오류에서 local credential mutation이 없다.
- help·README·웹 문구가 실제 command semantics와 일치하며 공개 README에 `--server`를 추가하지 않는다.
- 출력·fixture·문서에 credential, raw token, 내부 owner ID와 민감한 provider 오류가 없다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **중복 제출 또는 무한 재인증**: 인증 실패만 한 번 복구하고 두 번째 제출 결과는 재귀 없이 종료해 횟수를 테스트한다.
- **환경 토큰 덮어쓰기**: credential source를 분기해 환경 토큰이 있으면 file login을 시작하거나 저장 파일을 바꾸지 않는다.
- **기존 credential 유실**: device login 성공 전 remove를 호출하지 않고 저장 실패·취소 fixture에서 기존 값 유지 여부를 검증한다.
- **network unknown 의미 훼손**: 기존 submit 내부의 ambiguous network 1회 retry와 auth recovery를 별도 경계로 유지한다.
- **JSON stdout 오염**: 자동 로그인 경로의 출력 채널과 최종 JSON을 검토해 기존 automation 계약을 회귀시키지 않는다.
- **문서·npm 불일치**: 루트·package README를 한 단계에서 함께 바꾸고 package smoke로 실제 게시 산출물을 확인한다.

## 승인 요청 사항

- 최초 파일 credential 401/410에서 device login 후 submit을 정확히 한 번 자동 재시도하는 방향
- 환경 변수 credential은 자동 복구하지 않고 actionable 오류로 종료하는 경계
- 전역·명령별 help와 unknown input hint를 추가하되 기존 command·option 호환성을 유지하는 방향
- 공개 README에는 일반 명령과 help/version 표만 두고 상세 옵션은 `docs/cli-submit.md`에 유지하는 문서 위치 판단
- 구현 PR에서는 npm publish·production 배포를 하지 않고 별도 release gate로 인계하는 제외 범위

승인되면 `task_m100_134_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지를 구체화한다.
