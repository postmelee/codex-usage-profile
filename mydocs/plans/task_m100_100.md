# Task #100 수행계획서 — README 카드 고정 URL의 대표 설정 자동 반영

GitHub Issue: [#100](https://github.com/postmelee/codex-usage-profile/issues/100)
마일스톤: M100

## 목적

README와 이미지 원본 공유에 쿼리 없는 `/u/{handle}/card.png` 하나만 제공하고, 사용량 제출뿐
아니라 저장된 카드 theme·locale 변경도 같은 URL의 PNG와 ETag에 자동 반영되게 한다. 사용자는
README Markdown을 한 번 삽입한 뒤 카드 설정이 바뀌어도 링크를 다시 복사하거나 교체하지 않아야
한다.

명시적인 `theme`·`locale` query URL은 특정 표현을 고정하는 호환·고급 경로로 유지한다. 공개
media hot path는 D1을 조회하지 않는 현재 원칙을 보존하고, publication authority가 저장된 대표
선택을 함께 소유하게 해 queryless 요청만 canonical 선택을 따르도록 한다. `card.png`와
`social.png`는 동일한 저장 설정을 반영하고 private/unpublished 경계와 ETag·조건부 요청 계약을
유지한다.

## 배경

- M100 milestone은 stable README card와 이후 submit이 같은 URL의 ETag를 갱신하는 흐름을 MVP
  핵심으로 정의한다.
- Task #74는 query 없는 URL을 dark/en 하위 호환 표현으로 고정하고, 저장된 설정은
  `selectedPublicCardUrl`의 query 조합으로 제공했다. 현재 Share Studio도 이 URL을 다시
  정규화해 README Markdown과 이미지 URL에 theme·locale query를 넣는다.
- 이 구조에서는 사용량 변경은 기존 링크에 반영되지만 카드 설정 변경은 새 URL을 만들어 이미
  삽입된 README를 수동 교체하게 한다. 이는 “한 링크를 한 번 삽입하고 데이터·설정만 갱신한다”는
  제품 목적과 맞지 않는다.
- Task #78의 `social.png`는 이미 저장된 `cardLocale`과 `cardStyle.theme`을 반영하는 단일 stable
  표현이다. README card도 같은 대표 선택을 사용하되 1497x918 card endpoint와 2400x1260 social
  endpoint의 역할은 계속 분리한다.
- 현재 media contract v4는 dark/en stable object를 publication authority로 사용하고 light stable
  object와 네 immutable revision의 정합성을 검증한다. store reader는 selector가 없으면
  dark/en으로 normalize하므로, 외부 queryless 의미와 내부 authority 기본 표현이 결합돼 있다.
- 진행 중인 Task #84 worktree는 queryless dark와 설정별 `selectedPublicCardUrl`을 Gate C 검증
  가정으로 보유한다. 본 task는 `.worktrees/task84`를 수정하지 않고 독립 branch에서 새 계약을
  완성한 뒤 #84가 최신 devel로 재정렬할 handoff를 남긴다.

## 설계 방향

- 외부 URL 계약은 요청 query의 존재로 구분한다. `theme`과 `locale`이 모두 없으면 publication에
  기록된 canonical 선택을 사용한다. 하나라도 있으면 explicit mode이며 빠진 축은 기존 기본값
  dark/en을 사용해 `?theme=light`, `?locale=ko` 등 기존 링크의 의미를 보존한다.
- queryless endpoint는 redirect나 version query를 만들지 않고 선택된 immutable revision bytes를
  직접 200/304로 반환한다. ETag는 실제 선택된 representation의 ETag여야 한다.
- public media GET은 D1을 읽지 않는다. 저장된 owner 설정을 publication authority metadata 또는
  동등한 storage-only manifest에 기록한다. 내부 dark authority와 외부 canonical 선택은 논리적으로
  분리하되, 새 stable object가 꼭 필요한지는 Stage 1 호환성·failure audit 뒤 구현계획서에서
  확정한다.
- 기존 contract v3/v4 publication에 canonical 선택 metadata가 없으면 dark/en으로 읽어 현재 배포
  bytes를 보존한다. 새 publication shape를 additive v4로 수용할지 contract version을 올릴지는
  adapter의 fail-close·restore 판별과 rollback 호환성을 비교해 구현계획서 승인 항목으로 고정한다.
- 새 publish와 usage refresh는 저장된 owner 설정을 authority에 포함한다. 설정 변경은 새 revision과
  후보 publication을 먼저 준비하되 owner CAS 전 canonical 선택을 노출하지 않는다. CAS 성공 뒤
  committed owner revision과 storage ETag를 확인해 authority/social을 commit하고, superseded 작업은
  이전 또는 최신 일관 상태를 보존한다.
- DB와 object storage 사이에 단일 transaction을 가정하지 않는다. commit 실패는 성공으로 숨기지
  않고 안전한 retry/convergence 경로를 유지하며, exact retry가 같은 URL을 최신 저장 설정으로
  수렴시키는 테스트를 둔다.
- API에서 `publicCardUrl`은 canonical queryless URL의 진실 원천이다. `selectedPublicCardUrl`은 기존
  consumer를 깨지 않도록 유지하되 canonical과 동일한 의미로 전환하는 방향을 우선하며,
  explicit URL은 `publicCardUrls`와 `publicCardVariantUrls`에서만 제공한다. 정확한 deprecation 표기는
  구현계획서에서 response consumer audit 뒤 확정한다.
- Share Studio는 canonical URL과 selected preview URL을 별도 값으로 다룬다. README Markdown과
  이미지 URL 복사는 canonical을 사용하고, preview 및 PNG 저장은 현재 저장 설정과 일치하는 explicit
  representation을 사용할 수 있다.
- 외부 cache는 즉시 갱신을 보장하지 않는다. origin의 `public, no-cache, must-revalidate`와 ETag
  계약을 유지하고 “같은 링크가 자동으로 수렴하되 image proxy 표시에는 지연이 있을 수 있음”을
  문서화한다.

- **Stage 1 — canonical selection 계약과 legacy 호환 고정**

    회귀를 고정한다.

- **Stage 2 — R2/S3 publication과 설정 commit 정합성**

    유지하도록 backend와 profile response를 보정한다.

- **Stage 4 — Share Studio·Profile 공유 흐름 전환**
  - preview/download representation과 README·이미지 URL canonical copy를 분리한다.
  - Home·owner/public Profile, 설정 저장·reload·다른 context 및 handoff E2E 무회귀를 검증한다.
- **Stage 5 — maintenance·공식 문서·통합 검증과 #84 handoff**

## 리스크

- **authority와 canonical 의미 혼선**: 현재 dark stable object가 authority와 queryless 응답을 함께
  표현한다. selector mode와 publication metadata를 분리하고 legacy fallback을 contract test로
  고정한다.
- **D1/R2 commit 간극**: 설정 CAS와 object storage commit은 단일 transaction이 아니다. media를
  준비한 뒤 committed owner revision·storage ETag를 확인하고 superseded commit을 거부하며 exact
  retry로 수렴시킨다.
- **legacy/rollback 호환성**: 기존 v3/v4 object 또는 이전 saved version은 새 selection metadata가
  없다. dark/en fallback과 old reader가 허용할 additive shape를 먼저 검증하고 필요할 때만 contract
  version을 올린다.
- **캐시 표시 지연**: origin ETag가 바뀌어도 GitHub image proxy는 늦게 표시할 수 있다. URL에
  cachebuster를 넣어 핵심 요구를 훼손하지 않고 origin 계약과 외부 지연을 분리해 문서화한다.
- **UI source 분리 회귀**: preview와 copy URL을 나누면서 download, handoff, image readiness source가
  어긋날 수 있다. 각 액션이 사용하는 URL과 화면 source를 단위·E2E에서 별도로 검증한다.
- **maintenance 누락**: publication metadata 또는 stable key를 바꾸면 exact count, restore, cleanup이
  정상 object를 orphan으로 판단할 수 있다. adapter 변경과 같은 Stage에서 maintenance fixture를
  추적하고 Stage 5 전체 검증으로 닫는다.
- **진행 중 Task #84·#101과 충돌**: 각 worktree를 건드리지 않는다. `orders/20260813.md`와 #84의
  release 검증 가정은 merge 시점에 최신 devel 기준으로 재정렬하고, 본 task 보고서에 의존 순서를
  명시한다.

## 승인 요청 사항

- query가 전혀 없는 요청만 저장된 canonical theme·locale을 따르고, query가 하나라도 있는 기존
  링크는 빠진 축을 dark/en으로 보완하는 explicit variant로 유지한다.
- public media hot path는 D1을 조회하지 않고 publication authority가 canonical selection을 소유한다.
- `publicCardUrl`을 canonical 진실 원천으로 사용하고 `selectedPublicCardUrl`은 호환을 위해 유지하되
  canonical과 같은 의미로 전환하는 방향을 승인한다.
- 설정 저장은 media 준비 → owner CAS → supersession-safe authority/social commit 순서로 설계하며
  exact retry가 실패 간극을 수렴시킨다.
- 기존 v3/v4는 selection metadata 부재 시 dark/en으로 읽고, additive v4와 새 contract version 중
  선택은 Stage 1 audit 결과를 구현계획서 승인 항목으로 확정한다.
- preview/download에는 explicit representation을 사용할 수 있지만 README Markdown과 이미지 URL
  복사는 항상 queryless canonical URL을 사용한다.
- 기존 `README.md`와 `docs/` 네 문서만 필요한 부분을 수정하고 새 공식 문서를 만들지 않는다.
- Task #84·#101 worktree와 production은 건드리지 않으며, #84 Gate C 재개는 Task #100 반영 뒤 최신
