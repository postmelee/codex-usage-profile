# Task #90 수행계획서 — 공개 README·문서 정보구조와 GitHub metadata 현행화

GitHub Issue: [#90](https://github.com/postmelee/codex-usage-profile/issues/90)
마일스톤: M100

## 목적

canonical production과 npm `codex-usage-profile@0.1.3`이 공개된 현재 상태를 기준으로
GitHub repository 첫 화면을 사용자 중심 launch surface로 다시 구성한다. 실제 카드 예시를
제목 가까이에서 기존 50% 폭으로 보여 주고, 사용자가 제품 가치·시작 방법·공유 방법·개인정보
경계를 짧은 흐름으로 이해하게 한다.

README에서 개발·배포·legacy contract처럼 일반 사용자가 알 필요 없는 정보를 분리하고,
공식 `docs/`를 사용자·기여자·maintainer·legacy 대상으로 분류한다. 공개 사용자 문서는
영어를 canonical language로 사용하고, Hyper-Waterfall 작업 문서의 한국어 locale은 유지한다.
최종 source가 `main`에 반영된 뒤 GitHub homepage와 default branch를 실제 production 기준으로
맞춰 본격적인 마케팅이 참조할 단일 공개 진입면을 완성한다. repository description은 현재 문구를
그대로 보존한다.

## 배경

- Task #108/PR #127로 canonical production
  `https://codex-usage-profile.meleeisdeveloping.chatgpt.site`, public CLI `0.1.3`,
  production/Stage5 분리와 운영 runbook이 완료됐다.
- 현재 README는 production URL과 실제 카드 이미지를 사용하지만 예시가 50% 폭이고 긴 소개·
  endpoint 표·개발/배포 문서가 같은 정보 계층에 있어 제품 결과와 Quick start가 덜 두드러진다.
- `Documentation`은 사용자 가이드와 analyzer integration, production architecture, Sites/npm
  운영, legacy contract를 한 목록에 노출한다. 일반 사용자에게 불필요한 maintainer 문서가
  README 첫 화면의 정보 밀도를 높인다.
- 공개 README와 package README는 영어지만 사용자 링크인 `docs/cli-submit.md`와
  `docs/readme-card.md`는 한국어이고, contributor/contract 문서와 maintainer 문서의 언어도
  섞여 있다. 모든 문서를 일괄 번역하기보다 대상 독자와 canonical language를 먼저 고정해야 한다.
- GitHub repository description은 현재 기능과 대체로 맞지만 homepage는 Stage5 URL,
  default branch는 `devel`이다. 사용자 공개 기준은 canonical production과 release branch
  `main`이어야 한다.
- `origin/main`은 `dfc80d0b...`, `origin/devel`은 PR #127 merge `d604ff3...`다. #90 문서와
  metadata를 공개하기 전에 source integration과 exact `main` 반영 순서를 분리해야 한다.
- Issue #90이 지목한 개인 절대경로 외에도 public scan에서 과거 작업 문서의
  개인 macOS home 재현 명령이 추가로 관찰된다. 역사적 결과는 보존하되 재현 가능한 placeholder로
  일반화할 필요가 있다.

## 설계 방향

### README 정보 구조

- 첫 viewport는 `title → value proposition → 실제 카드 → primary CTA/Quick start` 순서를 사용한다.
- 카드 예시는 stable fixed href/src 계약을 유지하고 현재 50%보다 크게 표시하되 GitHub
  desktop/mobile 렌더에서 과도하게 넘치지 않는 width를 Stage 1 render audit로 결정한다.
- README는 사용자가 무엇을 얻고 어떻게 시작·게시·공유하는지에 집중한다. architecture,
  operator runbook, release 명령과 legacy schema는 제거하지 않고 `CONTRIBUTING.md` 또는
  `docs/README.md`에서 역할별로 찾게 한다.
- privacy/security는 사용자 결정을 돕는 핵심 경계만 유지하고 backend 구현 순서와 endpoint
  matrix는 상세 사용자 문서로 이동한다.
- OpenAI Codex for Open Source 지원 표기, 비후원 고지, MIT license와 trademark notice는
  과장 없이 보존한다.

### 문서 대상 독자와 언어

- public product surface인 root README, package README, 사용자 가이드는 영어를 canonical로
  사용한다. 이는 글로벌 npm/GitHub 사용자가 처음 보는 공개 표면의 일관성을 위한 정책이다.
- `.hyper-waterfall/version.json`의 `locale=ko`와 `mydocs/` 작업 산출물은 변경하지 않는다.
- maintainer 문서는 현재 한국어를 유지한다. 일괄 번역은 정보 손실과 대규모 diff를 만들므로
  #90에서 수행하지 않고, 사용자 README에서 제외한 뒤 docs index에 대상·언어를 표시한다.
- contract/legacy 문서는 현재 영어를 유지하고 사용자 기능처럼 홍보하지 않는다.
- 같은 사실을 README, package README, user guide에 장문 복제하지 않는다. README는 요약,
  user guide는 상세, CONTRIBUTING/docs index는 기여자·maintainer navigation을 담당한다.

### release와 GitHub metadata Gate

- #90 문서 source는 먼저 non-closing checkpoint PR로 `devel`에 통합한다.
- 작업지시자가 checkpoint merge를 승인한 뒤 `devel → main` release PR로 exact tree를 올리고
  GitHub가 표시할 README를 `main`에서 확인한다.
- homepage/default branch 변경은 exact `main` 확인 뒤 별도 remote mutation Gate로 실행한다.
  homepage는 canonical production, default branch는 `main`이어야 한다.
- CI badge는 최종 default/release branch 의미와 실제 workflow trigger를 대조해 branch query를
  `main`으로 고정하거나 불필요하면 제거한다. green처럼 보이기 위한 임의 badge는 두지 않는다.
- metadata cutover 실패 시 homepage/default branch를 이전 값으로 되돌리는 exact API payload를
  실행 전 기록하고, source tree나 production Site를 변경하지 않는다.

### 호환성과 공개 경로

- 실제 카드 예시는 fixed `/api/share/postmelee` href와 query 없는
  `/u/postmelee/card.png` src를 유지한다. README에서 revision URL을 embed로 안내하지 않는다.
- 사용자 예시 명령은 `npx codex-usage-profile@latest submit`을 기본으로 하며 Stage5 또는
  `--server`를 노출하지 않는다.
- 기존 문서 경로는 가능한 한 유지해 외부 링크를 깨뜨리지 않는다. 사용자 문서는 같은 경로에서
  내용과 언어를 보정하고 운영 문서는 이동하지 않는다.

## 잠정 단계

- **Stage 1 — 공개 표면 audit와 정보구조·언어 계약 확정**
  - README GitHub 렌더, live card/badge/link, workflow/default branch, package README와 docs의
    대상 독자·언어·중복·private path를 전수 분류한다.
  - 사용자 first viewport wire outline, 문서 index와 exact 변경 파일, main release/metadata
    rollback payload를 구현계획서에 고정한다.
- **Stage 2 — 사용자 중심 README와 공개 user guide 보정**
  - 카드 예시·Quick start·기능·publish/share·privacy·help 순서로 README를 재구성한다.
  - CLI/card 사용자 가이드와 package README를 영어 사용자 관점으로 보정하고 internal
    Stage/version/override 표현을 제거한다.
- **Stage 3 — contributor/maintainer navigation과 공개 tree 위생**
  - `docs/README.md`, `CONTRIBUTING.md`에서 대상 독자·언어별 navigation과 development
    진실 원천을 고정한다.
  - 사용자 README에서 운영/legacy 문서를 제거하고 개인 절대경로를 재현 가능한 형태로 일반화한다.
- **Stage 4 — source integration과 exact-main 공개 문서 승격**
  - 전체 문서/link/render/public scan을 통과한 source를 non-closing checkpoint PR로 `devel`에
    통합하고, 별도 승인 뒤 `devel → main` release PR의 exact tree를 검증한다.
  - GitHub README와 live card가 `main` 기준으로 정상 렌더되는지 확인한다.
- **Stage 5 — GitHub metadata cutover와 최종 공개 검증**
  - 별도 승인 Gate로 homepage를 canonical production으로, default branch를 `main`으로 변경한다.
  - description, badge, card/share GET/HEAD, README/docs link, public scan과 rollback readiness를
    재검증하고 최종 보고·PR handoff를 준비한다.
