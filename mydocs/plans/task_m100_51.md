# 수행계획서 — Task #51: Sites MVP production migration 및 공개 cutover

GitHub Issue: [#51](https://github.com/postmelee/codex-usage-profile/issues/51)
마일스톤: M100

## 목적

Task #49에서 적합성 PASS를 받은 **ChatGPT Sites + D1 + native R2** 구성을 M100 MVP의 실제 canonical production origin으로 전환한다. 현재 owner-only Stage 5 검증 Site에서 통과한 GitHub OAuth, browser session, packed CLI device login과 Account Usage Contract v1 submit, private preview, publish/unpublish, stable card route의 의미를 유지하면서 추가 과금 없이 공개 MVP까지 단계적으로 cutover한다.

이 task는 공개 버튼을 먼저 누르는 배포 작업이 아니다. source/build와 CLI origin을 production 기준으로 정리하고, 기존 test data를 export한 뒤 승인된 범위만 정리하며, D1/R2 복구·retention·operator account deletion·관찰·중단 절차를 검증한다. 이후 owner-only candidate, 일시적 public smoke와 원복, 최종 public cutover를 서로 다른 승인 Gate로 수행한다.

## 배경

- #49와 PR #50은 실제 Sites project, D1, native R2, GitHub OAuth와 packed CLI를 사용한 hosted 검증을 완료하고 architecture 적합성을 PASS로 판정했다.
- 공식 진실 원천인 `docs/production-hosting.md`는 Sites를 M100 canonical target으로, Cloud Run + Neon + S3-compatible R2를 tested fallback으로 지정한다.
- 현재 `.openai/hosting.json`은 실제 project와 logical `DB`/`PROFILE_MEDIA` binding을 가리키며, Site version 2는 active 상태지만 접근 정책은 owner-only다.
- 현재 Site의 display title과 slug는 Stage 5 test 용어를 포함하고, runtime에는 test GitHub OAuth app이 연결돼 있다.
- Stage 5 D1/R2에는 작업지시자가 승인한 owner의 identity-free Account Usage Contract v1 집계와 immutable media가 private 상태로 남아 있다. 공개 전에는 export, 정리 범위와 복구 가능성을 고정해야 한다.
- CLI는 현재 기본 production origin을 갖지 않으며 README와 사용자 문서는 placeholder origin을 사용한다. npm registry 실제 게시는 #44의 범위지만, #44가 게시할 packed candidate는 이번 task에서 canonical Sites origin으로 검증돼야 한다.
- #43, #44, #45와 #46의 본문·선행관계는 #49 이전의 Cloud Run canonical 결정을 반영하므로, Sites cutover 결과와 일치하도록 재정렬해야 한다.

## 설계 방향

- **기존 Site 재사용**: 새 Site를 만들지 않고 `.openai/hosting.json`의 project와 `DB`/`PROFILE_MEDIA` binding을 재사용한다. source에 project id 외 credential, data id 또는 runtime secret을 추가하지 않는다.
- **무료 origin 우선**: 초기 MVP는 현재 `chatgpt.site` origin을 기본 후보로 사용한다. display title은 production 용도로 바꾸되 URL slug를 바꾸기 위해 Site를 삭제·재생성하거나 유료 domain을 도입하지 않는다. 정확한 origin과 Stage 5 명칭이 남은 slug 수용 여부는 remote Gate A에서 다시 승인받는다.
- **canonical build와 fallback 분리**: Sites full-stack artifact를 production 기본 surface로 승격하되 기존 `build:cloud-run`, Postgres/S3 adapter와 tests를 유지한다. sample-only marketing build는 중복 여부를 판단한 뒤 제거가 필요하면 별도 승인 범위로 처리한다.
- **CLI origin 우선순위 보존**: `--server`, `CODEX_USAGE_PROFILE_URL`, 저장된 credential origin이 명시적 기본 origin보다 우선하는 기존 계약을 유지한다. 이번 task에서는 default candidate와 packed smoke를 완성하고 npm publish는 #44에 남긴다.
- **export-before-delete**: D1/R2 material 변경 전에 schema/version, record/object count와 content digest를 포함한 export manifest를 만들고 저장소에 실제 backup·credential·PII를 커밋하지 않는다. 삭제와 restore는 dry-run을 기본으로 하며 `--apply`와 exact target 확인을 요구한다.
- **최소 PII와 fail closed**: raw GitHub token, CLI token/device code, session/state 원문과 private usage는 export log나 runtime log에 기록하지 않는다. account deletion은 owner scope와 종속 record를 먼저 열거하고, stable public object는 tombstone 처리 후 structured state를 정리한다. 일관성을 증명할 수 없으면 성공으로 보고하지 않는다.
- **disposable 복구 smoke**: production data를 임의 복제하지 않는다. restore/repair smoke는 명시적으로 tag된 disposable owner/key 또는 승인된 test record만 사용하고, 종료 시 record/key count와 public `404`로 cleanup을 증명한다.
- **remote 설정은 Sites가 진실 원천**: GitHub client id/secret 등 runtime 값은 Sites environment에서 관리하고 `.openai/hosting.json`이나 source에 넣지 않는다. environment 변경 후에는 정확히 검증된 saved version을 owner-only로 재배포해 적용한다.
- **공개 Gate 분리**:
  - Gate A: exact origin/title, current access, production OAuth callback, runtime key 목록, export manifest, 삭제 대상, 비용·quota 화면과 candidate commit 승인
  - Gate B: owner-only candidate smoke 결과, 공개 노출 범위, 일시적 public 전환 시간대와 즉시 원복 절차 승인
  - Gate C: 일시적 public smoke와 owner-only 원복 증적을 검토한 뒤 최종 public access cutover 승인
- **추가 과금 금지**: Sites/D1/R2가 plan upgrade, 결제수단 또는 자동 초과 과금을 요구하면 public cutover를 중단하고 owner-only를 유지한다. Cloud Run fallback 평가는 별도 승인 없이는 provider resource 생성으로 이어지지 않는다.
- **관련 이슈의 의미 정렬**: #43/#44/#45/#46 수정안은 최종 architecture·Gate 결과를 근거로 제시한다. close나 선행관계 변경은 해당 Stage 승인 뒤에만 GitHub에 반영한다.

## 잠정 단계

- **Stage 1 — canonical Sites build와 production origin 계약**
  - Sites full-stack artifact를 production 기본 surface로 정리하고 Cloud Run fallback build를 유지한다.
  - CLI default origin 후보, explicit override/stored-origin 우선순위와 문서 placeholder 제거 범위를 test로 고정한다.
  - production origin/title/slug 제약, environment와 remote Gate 입력을 명세한다.
- **Stage 2 — D1/R2 lifecycle, retention과 account deletion**
  - versioned export manifest와 dry-run 기본 restore/cleanup/account deletion/repair operation을 구현한다.
  - disposable D1/R2 fixture로 export→mutate/delete→restore/repair→cleanup을 검증한다.
  - public stable/tombstone과 immutable revision 보호, owner scope와 raw credential 비저장을 확인한다.
- **Stage 3 — 관찰·abuse·비용 stop과 전체 local candidate**
  - structured log/redaction, health/error 분류, shared rate-limit 운영 값과 maintenance/fallback runbook을 구성한다.
  - secret/private-data artifact 검사와 전체 local browser/CLI/hosting matrix 회귀를 통과한다.
  - Gate A에 제출할 exact remote 값, data manifest와 candidate commit을 준비한다.
- **Stage 4 — Gate A: production OAuth와 owner-only candidate**
  - exact Site origin/title/access, OAuth callback, runtime key 목록, export 위치·digest·count, 삭제 대상과 비용·quota 조건을 제시하고 승인받는다.
  - 승인 후 production OAuth app/env를 적용하고 검증된 saved version을 owner-only로 배포한다.
  - 승인된 test data cleanup, disposable restore/repair와 GitHub OAuth/CLI/private/publication smoke를 수행하되 Site access는 owner-only로 유지한다.
- **Stage 5 — Gate B: 일시적 public smoke와 owner-only 원복**
  - anonymous landing, GitHub OAuth, private-by-default account, CLI submit과 공개 card의 노출 범위 및 원복 명령을 제시하고 승인받는다.
  - 승인된 짧은 구간에만 public access로 전환해 end-to-end와 secret/private-data 경계를 검증한다.
  - smoke 종료 즉시 owner-only로 원복하고 anonymous 차단, session/token revoke와 public card tombstone을 확인한다.
- **Stage 6 — Gate C: 최종 cutover, 공식 문서와 roadmap 정렬**
  - Stage 5 증적과 잔여 위험을 제시해 최종 public access 승인을 받는다.
  - 승인 시 public cutover와 final smoke를 수행하고, 미승인 시 owner-only candidate를 유지한 상태로 결과를 기록한다.
  - README와 공식 문서, #43/#44/#45/#46을 최종 architecture와 release gate에 맞게 갱신하고 전체 검증·최종 보고를 완료한다.

### 통합 검증

- 추가 결제, plan upgrade, 결제수단 등록과 자동 초과 과금 없이 현재 계정에서 MVP를 유지할 수 있다.
- production OAuth, browser와 CLI가 같은 canonical Sites origin을 사용하고 `--server` override와 기존 credential origin 보호가 유지된다.
- test credential과 승인되지 않은 usage/media가 final production state에 남지 않는다.
- D1/R2 export·restore, retention, account deletion과 publication repair가 재현 가능하며 destructive operation은 dry-run과 exact target 확인 없이는 실행되지 않는다.
- source, saved artifact, client asset, response/header와 recent log에 secret, token/state/session 원문, private usage와 local path가 없다.
- anonymous 사용자는 landing과 명시적으로 published card만 볼 수 있고 private/unpublished/missing profile/card는 동일하게 닫힌다.
- Sites beta/quota/장애 시 신규 submit/publication을 중단하고 owner-only 또는 maintenance로 전환한 뒤 Cloud Run fallback을 평가할 수 있다.
- Cloud Run/Postgres/S3-compatible fallback build와 tests가 삭제되거나 손상되지 않는다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **현재 slug의 Stage 5 명칭**: Sites metadata 변경은 URL slug를 바꾸지 못할 수 있다. 무료 MVP에서는 현재 origin 재사용을 기본안으로 두고 Gate A에서 명칭 수용 여부를 승인받는다. 새 Site 생성이나 유료 domain으로 우회하지 않는다.
- **공개 access의 ChatGPT 인증 경계 변화**: owner-only에서 보이던 ChatGPT account gate가 public access에서는 제거돼 anonymous traffic이 Worker에 도달한다. API/session/private route와 abuse protection을 일시적 public smoke에서 검증하고 즉시 원복할 수 있게 한다.
- **test data cleanup의 비가역성**: D1/R2 삭제 전에 export digest/count와 복구 smoke를 완료하며, exact owner/key와 `--apply` 승인을 분리한다. backup payload는 저장소에 커밋하지 않는다.
- **restore/repair 중 공개 상태 불일치**: disposable namespace와 conditional publication/tombstone을 사용하고, 일관성을 증명할 수 없으면 generic 503과 repair-required로 fail closed한다.
- **production OAuth secret rotation 실패**: callback과 secret을 같은 Gate에서 바꾸고 owner-only smoke가 통과할 때까지 public 전환하지 않는다. secret 값은 tool output, 문서와 log에 복제하지 않는다.
- **CLI origin 변경과 기존 credential**: 저장된 credential origin을 새 default보다 우선하고 다른 origin에는 token을 보내지 않는다. migration 안내와 clean config smoke를 함께 제공한다.
- **Sites beta quota·가격 변경**: 현재 계정의 표시와 배포 결과를 Gate마다 확인한다. 추가 과금 조건이 나타나면 task를 owner-only 상태에서 중단하고 fallback 판단을 별도 승인으로 넘긴다.
- **운영 기능 과대 구현**: self-service deletion UI, 유료 monitoring과 새로운 admin surface를 만들지 않는다. 개인 MVP에 필요한 dry-run operator 도구와 최소 관찰만 구현한다.
- **#43 branch와 기존 worktree 충돌**: #51은 최신 `origin/devel` 기반 분리 worktree에서 진행하고 메인 `local/task43`과 미추적 분석 자료를 수정·rebase하지 않는다.
- **외부 이슈 상태 변경**: #43/#44/#45/#46의 exact diff와 close 여부를 Stage 6 승인 전에 제시한다. architecture 정렬을 이유로 임의 close하지 않는다.
