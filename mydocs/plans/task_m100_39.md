# Task #39 수행계획서 — 웹 전용 Animated GIF 생성 및 저장

GitHub Issue: [#39](https://github.com/postmelee/codex-usage-profile/issues/39)
마일스톤: M100

## 목적

데스크톱 웹 Share Studio에서 현재 공개 카드 PNG를 바탕으로 Animated GIF를
필요할 때 생성하고 사용자가 파일로 저장할 수 있게 한다. 생성물은 카드 경계에
딱 맞는 투명 캔버스에서 카드 회전·크기 변화·이동 하이라이트 없이, 현재 웹 카드의
Ocean Border Beam만 4.8초 동안 한 바퀴 순환하는 단일 표현으로 고정한다.

GIF는 X 웹 업로드의 15MB 상한 안에서 998×612, 20fps 품질을 유지하는 것을
목표로 한다. 서버 endpoint나 R2 저장 없이 사용자의 브라우저에서만 생성하고,
파일 첨부는 사용자가 직접 수행하게 하여 서버 자원·저장 용량과 외부 서비스
연동을 이번 범위에 추가하지 않는다.

## 배경

- Task #38에서 Share Studio와 PNG 저장 흐름이 완료되어 #39의 선행조건을
  충족했다.
- 원래 이슈 #39는 `Rotate | Pulse`, 안정적인 `.gif` endpoint와 Web Share까지
  포함했으나, 2026-08-27 작업지시자 피드백으로 다음 시제품을 최종 방향으로
  선택했다.
  - 회전, scale, 커서 위치 이동 하이라이트 없음
  - 기존 웹 카드와 같은 Ocean Border Beam만 순환
  - 카드 외부 공백·그림자 없이 투명 배경과 카드 경계에 맞는 캔버스
  - 2배 해상도 998×612, 20fps
- 96프레임·4.8초·256색 global palette·dithering 없음 조건의 최종 시제품은
  6,784,344 bytes로 측정되어 웹 15MB 상한에 충분한 여유가 있었다.
- X 공식 도움말은 Animated GIF를 모바일에서 최대 5MB, 웹에서 최대 15MB까지
  허용하고 반복되지 않는 GIF는 정지 이미지로 표시한다고 안내한다.
  따라서 이번 단계는 데스크톱 웹 생성·저장과 무한 반복을 명시적으로 고정한다.
  참고: https://help.x.com/en/using-x/posting-gifs-and-pictures
- canonical production은 ChatGPT Sites + D1 + native R2다. 이번 선택은 GIF를
  client-side Blob으로만 유지하므로 Worker 렌더링 시간, D1 schema, R2 object와
  정리 정책을 늘리지 않는다.

## 범위

### 포함

- 데스크톱 웹 Share Studio의 `PNG | GIF` 형식 선택
- GIF 선택 시 단일 `Border Beam` 표현과 생성·진행·완료·실패·취소 상태
- 생성 완료 뒤 `codex-usage-profile.gif` 파일 저장
- 같은 카드 revision·theme·locale의 중복 생성을 막는 session 단위 Blob 재사용
- 선택 카드 PNG를 same-origin으로 읽고 브라우저 내부에서만 프레임 합성·GIF 인코딩
- 고정 Animated GIF 출력 계약
  - canvas: `998×612` (`499×306` logical card의 2배)
  - duration: `4.8s`
  - frame rate/count: `20fps`, `96 frames`
  - frame delay: `50ms`
  - loop: forever
  - background: 투명, 카드 외부 여백과 drop shadow 없음
  - motion: rotate·scale·이동 하이라이트 없음
  - effect: 현재 웹 카드의 `ocean`, `duration=4.8`, `brightness=1.05`,
    `size=md`, `strength=0.82` Border Beam만 사용
  - seam: frame `n`의 phase를 `n / 96`으로 계산해 0°부터 356.25°까지만
    기록하고 중복 360° frame을 넣지 않음
  - palette: 최대 256색 global palette, dithering 없음
- 생성 결과가 `image/gif`이고 `15,000,000 bytes` 미만인지 저장 전에 검증
- 순차 frame 처리, 한 번에 하나의 생성 job, Blob URL 회수, 취소와 component
  unmount 정리 등 브라우저 자원 상한
- GIF 선택 즉시 자동 생성하고 생성 중에는 카드 크기를 유지한 skeleton과 비활성
  `Save GIF`를 표시하며, ready 뒤 상단 preview를 GIF Blob으로 교체하는 정책
- `prefers-reduced-motion`에서는 생성은 유지하되 상단 preview는 static PNG로 유지
- 기존 PNG 저장, URL/README/image copy, social intent와 Make private 회귀 검증
- PNG 모드에서는 기존 5개 SNS를 유지하고 GIF 모드에서는 수동 GIF 첨부 품질을
  확인한 X와 Reddit만 공유 대상으로 노출
- ko/en 문구, keyboard/focus, desktop responsive/short viewport와 오류 복구 검증
- 사용자 문서의 웹 GIF 생성·저장 및 X·Reddit 수동 첨부 경계 안내

### 제외

- 모바일 앱과 모바일 웹의 GIF 생성·저장 UI
- Rotate, Pulse, card tilt, scale, 커서 위치·glare 하이라이트와 효과 선택 UI
- 서버·Cloudflare Worker GIF 생성, D1/R2 저장, stable `.gif` endpoint와 공개 GIF URL
- Web Share API, GIF clipboard 복사와 native share sheet
- X API 업로드, X 작성 화면 자동 입력, 자동 게시와 업로드 성공 보장
- social intent가 생성된 GIF 파일을 자동 첨부하는 동작
- GIF의 README embed, Open Graph/Twitter Card image 대체
- 현재 PNG·social PNG renderer, publication revision, media-store schema와 cache 계약 변경
- X 모바일 5MB 상한을 위한 저해상도·저fps 별도 preset

## 설계 방향

- GIF는 public PNG처럼 publish 시 미리 만들지 않는다. 데스크톱 Share Studio에서
  사용자가 GIF를 선택하면 즉시 생성하고, 완료 전에는 비활성 `Save GIF`, 완료 뒤
  같은 위치의 download link를 노출한다.
- 원본은 이미 decode된 로그인 사용자 카드의 same-origin source URL을 우선하고,
  없으면 현재 theme·locale이 반영된 same-origin `selectedImageUrl` PNG를 사용한다.
  이를 998×612 투명 canvas에 축소 합성하고, 카드 중심 기준 conic phase와
  rounded edge mask로 Border Beam을 프레임별로 그린다. 프로필 데이터·avatar를 별도 API로 다시
  조립하지 않아 PNG와 GIF 내용이 달라지지 않게 한다.
- Border Beam의 색·속도·밝기·강도 수치는 공통 export preset으로 정의한다.
  웹 preview가 사용하는 props와 GIF renderer가 같은 상수를 참조하게 하여
  이후 한쪽만 바뀌는 drift를 막는다. 실제 raster 결과는 최종 승인 시제품의
  시작·중간·끝 reference frame과 시각 비교한다.
- 프레임 phase는 시간 기반이 아니라 index 기반 순수 함수로 계산한다. 96번째와
  동일한 360° frame을 생략해 마지막 356.25°에서 첫 0°로 3.75°만 진행하도록
  하고, loop 경계에서 멈춤이나 역행이 생기지 않게 한다.
- 브라우저 main thread가 96프레임 인코딩으로 멈추지 않도록 module Web Worker를
  우선 사용한다. Worker는 한 프레임을 합성·양자화·인코딩한 뒤 다음 프레임으로
  넘어가고 전체 RGBA frame 묶음을 메모리에 쌓지 않는다.
- GIF encoder는 browser/Worker에서 실행 가능한 작은 pure JS dependency를
  후보로 두되, Stage 1에서 global palette, transparency, loop, frame delay,
  license와 production bundle 호환성을 검증한 뒤 하나만 채택한다. 채택 근거와
  exact version은 구현계획서·lockfile에 고정한다.
- 결과 Blob은 `selectedImageUrl + revision + theme + locale + export preset version`
  key로 현재 Share Studio session에서만 재사용한다. 카드 선택이 바뀌거나
  dialog가 종료되면 job을 취소하고 Blob URL을 revoke한다.
- 생성 중 `Save GIF`를 비활성화하고 카드 경계와 같은 skeleton 및 accessible
  progress status를 표시한다. 실패, 미지원 capability, 15MB 초과는 PNG 기능과
  social actions를 막지 않고 별도 `Retry` action으로 복구 가능하게 한다.
- 모바일 환경은 기존 `isMobileShareEnvironment()` 경계를 재사용해 GIF 형식
  선택 자체를 노출하지 않는다. desktop/compact viewport 판단을 CSS만으로
  숨겨 기능이 우연히 실행되는 방식은 사용하지 않는다.
- GIF 선택 즉시 생성하며 완료 전에는 카드 경계와 같은 skeleton을 표시한다. ready면
  상단 preview를 session GIF Blob으로 교체하되 `prefers-reduced-motion` 사용자는
  생성·저장은 그대로 이용하면서 static PNG를 계속 본다.
- X와 Reddit 버튼은 기존 URL-only composer intent로 유지한다. GIF 모드에서는
  이 두 대상만 노출하고 저장 완료 메시지는 “파일을 저장한 뒤 X 또는 Reddit에서
  직접 첨부” 경계를 명확히 안내하며 자동 첨부를 암시하지 않는다. PNG 모드로
  돌아오면 Threads·LinkedIn·Facebook을 포함한 기존 5개 대상을 복원한다.
- 원래 이슈의 `.gif` endpoint, Web Share, Rotate/Pulse 수용 기준은 이 결정으로
  이번 구현에서 대체한다. 수행계획 승인 후 이슈 본문도 같은 범위로 정렬해
  PR과 이슈의 완료 조건이 어긋나지 않게 한다.

## 잠정 단계

- **Stage 1 — Animated GIF 출력 계약과 encoder 검증**
  - 고정 dimension·frame·duration·phase·palette·transparency·loop·size 계약을
    순수 함수와 fixture 검사로 고정한다.
  - browser Worker 호환 encoder 후보의 license, bundle, global palette,
    transparency, 96-frame 결과와 15MB 상한을 검증하고 하나를 선택한다.
  - 최종 승인 시제품과 시작·중간·끝 frame 및 loop seam을 비교한다.
- **Stage 2 — client-side worker 생성 pipeline과 자원 경계**
  - same-origin PNG fetch, sequential frame composition, Worker message contract,
    진행률, 취소, 단일 실행, Blob cache/revoke와 오류 정리를 구현한다.
  - MIME, 998×612, 96 frames, 50ms delay, infinite loop와 15MB 미만을 binary
    parser/fixture로 검증한다.
- **Stage 3 — 데스크톱 Share Studio 생성·저장 UX**
  - 데스크톱에만 `PNG | GIF`, 선택 즉시 생성, 생성 중 skeleton·비활성 `Save GIF`,
    완료 뒤 활성 `Save GIF`와 ko/en 상태 문구를 연결한다.
  - PNG는 기존 5개 SNS, GIF는 X·Reddit만 노출하고 형식 전환 시 대상을 즉시
    복원·제한한다. 전환된 action row는 기존 자식 stagger 대신 짧은 단일 모션을
    적용해 X를 포함한 전체 대상이 일관된 타이밍으로 바뀐다.
  - 생성 완료 전에는 같은 카드 크기의 skeleton을 유지하고 ready 뒤 GIF Blob
    preview로 교체하며, reduced motion에서는 ready 뒤에도 static PNG를 유지한다.
  - mobile 미노출, keyboard/focus, short viewport, reduced motion, 중복 입력,
    실패·재시도와 기존 PNG/social/copy/privacy 회귀를 E2E로 검증한다.
- **Stage 4 — 공식 문서, 통합 시각 QA와 전체 회귀**
  - `docs/readme-card.md`에 데스크톱 웹 생성·저장, X·Reddit 수동 첨부, 미지원 범위를
    최소 반영한다.
  - dark/light, ko/en의 representative GIF와 loop seam을 수동 시각 확인하고
    전체 test/build/Sites artifact 검증을 완료한다.

### 통합 검증

- 데스크톱 Share Studio에서만 PNG와 GIF를 선택할 수 있고 mobile은 기존 PNG
  흐름을 그대로 유지한다.
- GIF는 998×612, 20fps, 4.8초, 96 frames, transparent background,
  infinite loop, 15,000,000 bytes 미만이다.
- 카드 자체는 회전·scale하지 않고 이동 하이라이트가 없으며 Ocean Border Beam만
  웹 카드와 같은 속도로 순환한다.
- 마지막 frame과 첫 frame 사이가 다른 인접 frame과 같은 3.75° 진행량을 가져
  loop에서 pause·jump·역행이 보이지 않는다.
- 생성은 사용자 명시 입력에서만 시작하고 main thread interaction, focus와
  Share Studio 닫기를 장시간 막지 않는다.
- 생성 중 중복 요청, dialog close, source PNG 실패, Worker 미지원, encoder 실패,
  15MB 초과가 안전하게 복구되고 기존 PNG·공유 기능은 계속 사용할 수 있다.
- 생성 Blob과 object URL은 브라우저 session 범위를 넘지 않고 server, D1, R2,
  external API로 업로드되지 않는다.
- UI와 문서는 X 작성 화면·Web Share·GIF clipboard·자동 업로드를 지원한다고
  오인시키지 않는다.
- production build와 Sites full-stack artifact 검증이 통과한다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **프로필별 압축률 차이**: avatar와 theme 색 복잡도로 시제품보다 커질 수 있다.
  shared global palette, dithering 제거와 static frame 재사용을 우선하고 여러
  fixture의 worst case를 검사한다. 결과가 15MB 이상이면 저장을 막고 명확한
  오류를 표시하며 승인 없이 품질 preset을 자동 하향하지 않는다.
- **웹 Border Beam과 raster drift**: package 내부 CSS와 Canvas 구현이 달라질 수
  있다. 공통 preset 수치와 CSS의 conic stop·Ocean radial gradient·edge fade를
  renderer 계약으로 옮기고, 5개 reference frame의 footprint·falloff·중심과 loop
  seam을 golden test로 둔다. 대표 theme 시각 QA와 export preset version도 유지한다.
- **main-thread jank와 메모리 압력**: 998×612 RGBA 한 frame은 약 2.3MiB다. Worker에서
  순차 처리하고 전체 96-frame RGBA 배열을 보관하지 않으며 한 job만 허용한다.
- **브라우저 capability 차이**: Worker, ImageBitmap, OffscreenCanvas 또는 encoder
  bundle 지원 차이가 있을 수 있다. Stage 1에서 production 대상 브라우저를
  검증하고 capability 부족 시 PNG 기능을 유지한 명시적 미지원 상태를 제공한다.
- **비동기 source 변경**: theme·locale·revision이 generation 중 바뀌면 잘못된
  파일을 저장할 수 있다. cache key와 job token을 source identity에 묶고 이전
  결과·Blob URL을 즉시 폐기한다.
- **X 정책 변화**: 외부 업로드 상한은 제품이 통제할 수 없다. 공식 도움말을
  사용자 문서에 링크하고 내부 hard cap은 15,000,000 bytes로 고정하되 정책
  변경 시 별도 task로 조정한다.
- **원래 이슈와 축소 범위 불일치**: 이슈 본문에는 endpoint, Rotate/Pulse와 Web
  Share가 남아 있다. 수행계획 승인 후 본문을 결정안에 맞춰 갱신하고 보류 기능은
  이번 PR의 수용 기준으로 사용하지 않는다.
