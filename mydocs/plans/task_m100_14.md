# Task M100 #14 수행계획서

GitHub Issue: [#14](https://github.com/postmelee/codex-usage-profile/issues/14)
마일스톤: M100

## 목적

로그인한 사용자가 프로필 화면 상단에서 현재 GitHub 계정을 확인하고, 계정 메뉴를 통해 settings와 logout에 접근할 수 있게 한다. 또한 API token/device 관리 기능이 붙기 전에도 `/settings` shell을 제공해 계정 정보와 동기화 상태를 확인할 수 있게 한다.

이번 task는 #17에서 구현된 device-code login API 이후, #5 CLI submit과 #15 API token/device 관리 UI가 붙기 전 필요한 계정 UI 기반을 마련한다.

## 배경

#12 이후 frontend는 session 상태를 조회하지만 화면에는 로그인 계정 상태, settings 진입점, logout action이 없다. 사용자는 Share 옆에서 현재 로그인한 GitHub 계정인지 확인해야 하고, profile page와 settings page 사이를 자연스럽게 이동할 수 있어야 한다.

M100 MVP 흐름에서는 GitHub 계정이 snapshot owner와 연결되는 핵심 기준이므로, 계정 식별 UI가 없으면 submit 이후 사용자가 어떤 계정으로 업데이트되는지 확인하기 어렵다.

## 범위

### 포함

- authenticated/anonymous/loading/unavailable 상태별 topbar account UI
- Share 옆 GitHub avatar 기반 계정 버튼
- account menu/popover
- settings 진입 action
- logout action과 logout 후 auth state 갱신
- `/settings` route 또는 동등한 settings shell route
- settings shell에서 GitHub display name, login, avatar 표시
- GitHub profile 정보가 동기화된 읽기 전용 정보임을 표시
- keyboard/accessibility와 모바일/좁은 화면 대응

### 제외

- API token create/revoke
- device list/rename
- CLI submit 구현
- README card share/export 구현
- production OAuth host adapter 구현
- 계정 정보 직접 편집 기능

## 설계 방향

- 기존 `ProfileShell`의 topbar 구조를 유지하면서 Share action 옆에 account control을 추가한다.
- account UI는 별도 컴포넌트로 분리해 profile page와 settings shell에서 재사용할 수 있게 한다.
- logout은 기존 `profileApiClient.logout()`을 사용하고, 성공 시 frontend auth state를 anonymous 상태로 갱신한다.
- settings shell은 실제 account/device/token 관리 기능을 포함하지 않고, account overview와 후속 기능을 붙일 수 있는 layout만 만든다.
- `/device` route와 public profile route는 유지하고, `/settings` route는 `App.jsx`에서 명확히 분기한다.
- anonymous 상태에서는 GitHub login 진입점을 제공하되, 자동 redirect는 하지 않는다.
- 기존 Codex-style dark profile visual tone과 현재 UI spacing/token을 따른다.

## 잠정 단계

- **Stage 1 — Account topbar and menu**
  - `ProfileShell`에 account control slot을 추가하고 `AccountMenu` 컴포넌트를 만든다.
  - authenticated/anonymous/loading/unavailable 상태별 표시와 settings/logout action contract를 고정한다.
  - API client logout 테스트와 account UI helper 테스트를 보강한다.
- **Stage 2 — Settings shell route**
  - `/settings` route와 `SettingsPage` shell을 추가한다.
  - GitHub avatar/display name/login/read-only sync 안내를 표시한다.
  - profile route, device route, settings route 간 충돌이 없는지 확인한다.
- **Stage 3 — Interaction and responsive QA**
  - logout 후 auth state 갱신, menu keyboard interaction, 좁은 화면 레이아웃을 정리한다.
  - 브라우저에서 anonymous/authenticated fixture 상태를 확인한다.
- **Stage 4 — 통합 검증과 최종 보고**
  - 전체 테스트/build/diff check를 실행하고 최종 보고서와 PR 준비를 수행한다.

## 리스크

- **실제 OAuth session 검증 한계**: 로컬 fixture와 mocked auth state로 UI를 검증하고, 실제 GitHub OAuth smoke는 환경 변수가 준비된 runtime에서 별도 확인한다.
- **menu interaction 복잡도 증가**: 우선 native button과 간단한 popover state로 구현하고, focus/escape/outside click은 Stage 3에서 필요한 범위만 고정한다.
- **settings 범위 확장**: API token/device 관리는 #15 범위로 명확히 제외하고 placeholder 또는 shell 이상의 기능을 넣지 않는다.
- **profile layout 회귀**: existing profile topbar spacing과 Codex-style visual tone을 유지하고 브라우저 screenshot/DOM 확인으로 검증한다.
