# Task #141 수행계획서 — 라이트 카드 소셜 썸네일의 플랫폼별 경계 대비 보정

GitHub Issue: [#141](https://github.com/postmelee/codex-usage-profile/issues/141)
마일스톤: M100

## 목적

라이트 테마의 소셜 썸네일이 X처럼 투명 픽셀을 흰색으로 합성하는 플랫폼에서도
카드 경계를 분명하게 유지하도록 한다. 소셜 캔버스의 라이트 테마 바깥 여백만
불투명 `#F3F5F7`로 채우고, 기존 카드 경계에 `#D0D7DE` 테두리를 추가한다.

카드 본체와 `computeSocialCanvasLayout()`은 변경하지 않는다. 다크·라이트 테마 모두
현재의 `1200×630` 논리 캔버스, `960×588.697` 카드, `x=120`, `y≈20.651` 배치를
유지하고, `2400×1260` 출력에서 같은 카드 경계와 `499:306` 종횡비를 보장한다.

## 배경

- 현재 `/u/{handle}/social.png`는 카드 바깥 안전 여백을 투명하게 출력한다.
- Threads의 검정 합성 배경에서는 흰 카드가 구분되지만, X의 흰 합성 배경에서는
  라이트 카드와 바깥 여백의 경계가 사라진다.
- 라이브 다크 소셜 이미지와 승인 시제품을 픽셀 스캔한 결과, 두 이미지의 카드
  비배경 경계는 `x=240–2159`, `y=41–1218`, `1920×1178`로 일치했다.
- 승인 시제품은 카드 크기·위치·종횡비와 내부 배치를 바꾸지 않고 전체 배경
  `#F3F5F7`, 출력 기준 `2px`의 `#D0D7DE` 테두리만 합성했다.
- #78에서 소셜 전용 1.91:1 렌더러와 안전 여백을 도입했고, #101에서 revision 공유
  경로의 플랫폼 캐시 동작을 보정했다. 이번 task는 URL·metadata·cache 계약이 아니라
  라이트 소셜 PNG의 픽셀 표현만 다룬다.

## 범위

### 포함

- 라이트 소셜 캔버스의 바깥 여백을 불투명 `#F3F5F7`로 렌더링
- 기존 카드 경계와 radius를 따르는 논리 `1px`, 출력 `2px`의 `#D0D7DE` 테두리
- `computeSocialCanvasLayout()` 결과와 카드 본체 markup/draw 순서를 재사용하는
  Node native renderer와 production Worker renderer의 동일 계약
- 라이트 출력의 canvas 크기, alpha, 배경색, 테두리, 카드 경계와 종횡비 픽셀 검증
- 다크 소셜 출력의 투명 여백과 `/u/{handle}/card.png` 렌더링 무회귀 검증
- renderer version과 기존 publication refresh 경로가 새 라이트 social bytes를
  안전하게 반영하는지 확인
- 사용자에게 공개되는 소셜 이미지 계약을 `docs/readme-card.md`에 최소 반영

### 제외

- `computeSocialCanvasLayout()`의 canvas, padding, card 좌표·크기·scale·종횡비 변경
- 카드 내부 여백, avatar, heatmap, 통계, typography 또는 theme palette 변경
- 다크 소셜 이미지의 배경색·테두리·투명도 변경
- README 카드 `/u/{handle}/card.png` 출력 변경
- 그림자, gradient, pattern, 신규 effect preset 또는 설정 UI 추가
- Share Studio UI, 공유 URL, Open Graph/Twitter metadata와 revision 경로 변경
- 외부 플랫폼 cache purge, 기존 게시물 소급 갱신과 production 배포
- #39 Animated GIF와 #87 card image resource cache lifecycle 범위

## 설계 방향

- 소셜 전용 배경·테두리 값과 적용 조건을 `social-canvas` 계층의 공유 계약으로 두고
  native/Worker renderer가 같은 값을 사용한다. 카드 theme palette에는 소셜 캔버스
  전용 표현을 섞지 않는다.
- 라이트 렌더링 순서는 `전체 캔버스 배경 → 기존 카드 body → 동일 경계 테두리`로
  고정한다. 카드 body의 translate·scale과 logical dimensions는 그대로 재사용한다.
- 테두리는 소셜 캔버스 좌표에서 기존 `cardX`, `cardY`, `cardWidth`, `cardHeight`와
  `32 × layout.scale` radius를 사용한다. stroke 정렬로 카드의 관찰 가능한 경계가
  넓어지거나 잘리지 않도록 픽셀 테스트에서 승인 시제품의 경계를 고정한다.
- 다크 테마는 배경 fill과 border를 모두 생략해 기존 투명 padding 계약을 유지한다.
- standalone 카드 renderer는 소셜 전용 표현 함수를 호출하지 않아 README 카드 bytes와
  dimensions가 바뀌지 않게 한다.
- renderer version 변경이 필요한 경우 native/Worker 값을 함께 올리고, publication
  refresh가 동일 owner·presentation에서 변경된 social revision/etag를 기록하는 기존
  경로를 회귀 테스트한다. 별도 media schema나 URL은 추가하지 않는다.

## 잠정 단계

- **Stage 1 — 소셜 surface 계약과 renderer parity**
  - 라이트 전용 배경·테두리 공유 계약을 정의하고 native/Worker social renderer에 같은
    geometry로 적용한다.
  - targeted unit/pixel 테스트로 라이트 opaque surface, border, card bounds와 다크·README
    무회귀를 검증한다.
- **Stage 2 — publication refresh와 공식 문서 정합화**
  - renderer version/source digest와 social publication refresh 경로를 검증·보정한다.
  - 공개 계약 변경에 필요한 경우 `docs/readme-card.md`를 최소 갱신하고 targeted media/runtime
    회귀를 수행한다.
- **Stage 3 — 통합 회귀와 시각 QA**
  - representative dark/light 출력의 dimensions·card bounds·alpha·색상을 교차 대조하고
    승인 시제품과 같은 라이트 경계를 수동 확인한다.
  - 전체 Node 테스트, production build·Sites artifact verifier와 diff 검증을 완료한다.

### 통합 검증

- 라이트 소셜 PNG만 `#F3F5F7` opaque canvas와 `#D0D7DE` border를 갖는다.
- dark/light의 canvas와 card geometry가 동일하고 `499:306` 카드 종횡비가 유지된다.
- 다크 social padding은 투명하고 README card 출력에는 소셜 surface가 추가되지 않는다.
- native/Worker renderer가 같은 surface·geometry 계약을 만족한다.
- publication refresh가 변경된 라이트 social bytes를 새 revision/etag로 기록한다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **stroke로 인한 경계 확장**: line width와 좌표 정렬이 카드 bounds를 넓힐 수 있다. 기존
  layout 값에서 inset을 계산하고 승인 시제품의 픽셀 경계를 테스트로 고정한다.
- **native/Worker anti-alias 차이**: Canvas와 SVG stroke rasterization이 corner에서 다를 수 있다.
  공유 수치와 대표 픽셀/영역 기반 검증을 사용하고 renderer별 exact byte equality는 요구하지 않는다.
- **다크·README 회귀**: 공통 body에 border를 넣으면 제외 범위를 침범한다. social light 조건을
  별도 surface 단계에 한정하고 다크 alpha와 standalone card corner를 검증한다.
- **기존 publication 미갱신**: code 변경만으로 저장된 social object가 즉시 바뀌지 않을 수 있다.
  renderer version과 기존 publish/settings/usage refresh 경로를 확인하며 새 배포·cache purge는
  이번 task에서 수행하지 않는다.
- **공식 문서 과잉 변경**: 사용자에게 필요한 공개 동작만 `docs/readme-card.md`에 반영하고
  구현 좌표·내부 테스트 세부는 작업 보고서에 남긴다.

## 승인 요청 사항

- 라이트 social에만 `#F3F5F7` opaque canvas와 logical `1px` `#D0D7DE` border를 적용하고,
  다크 social과 README card는 변경하지 않는 범위
- `computeSocialCanvasLayout()`과 카드 body geometry를 절대 변경하지 않는 설계
- native/Worker renderer parity, publication refresh, 공식 문서·통합 검증으로 나눈 3개 Stage
- 공식 사용자 문서는 기존 `docs/readme-card.md`만 필요 시 최소 수정하는 위치 판단

승인되면 `task_m100_141_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지를 구체화한다.
