# Task #74 수행계획서 — 카드 테마 커스터마이징과 light/dark R2 변형 저장

GitHub Issue: [#74](https://github.com/postmelee/codex-usage-profile/issues/74)
마일스톤: M100

## 목적

owner가 Profile의 `Your Codex card` 영역에서 light/dark 카드 변형을 직접 미리 보고 기본 카드 테마를 저장할 수 있게 한다. 저장된 기본값은 재로그인과 다른 기기에서도 유지하며, Share Studio와 README/URL 복사 흐름은 새 사용량 submit 없이 선택된 테마 query URL을 사용한다.

공개 media는 light/dark 변형을 각각 R2에 유지하되, 기존 `/u/{handle}/card.png` URL과 dark 카드 동작을 보존한다. publish/unpublish, 캐시·ETag, cleanup, export/restore가 테마 축을 포함해 fail-closed로 동작하도록 구조화한다.

## 배경

- #69에서 사이트 전역 `system | light | dark` Appearance와 semantic theme token을 도입했다.
- 카드 renderer와 owner private preview는 이미 `light | dark` palette 및 `theme` query를 지원하지만, owner 선호값 저장과 공개 media의 테마 변형은 지원하지 않는다.
- 현재 공개 media contract v3는 `en | ko` locale 표현 두 개와 dark stable PNG 하나를 전제로 한다. public route는 D1이나 on-demand renderer를 조회하지 않고 R2 stable object만 읽는다.
- 사용자가 요청한 공개 카드 테마 선택은 사이트 화면 테마와 분리된 owner 카드 설정이어야 한다. 정적 PNG가 브라우저 system theme을 감지하는 것은 범위에서 제외한다.
- 기준 문서는 [README](../../README.md), [README 카드 사용 문서](../../docs/readme-card.md), [production hosting architecture](../../docs/production-hosting.md), #69 결과와 Issue #74다.

## 설계 방향

- **저장 모델**: owner record에 `cardTheme: "light" | "dark"`를 추가하고 기본값은 `dark`로 둔다. D1은 ordered migration을 추가하며 memory/file/Postgres fallback도 같은 record contract를 유지한다.
- **설정 API**: visibility mutation과 분리된 owner-only `PATCH /api/profile/card-settings`를 추가한다. 요청은 `cardTheme`만 허용하고, 변경된 owner profile과 선택 테마 URL을 반환한다. 공개 owner의 테마 저장은 R2를 다시 생성하지 않고 복사 대상 URL만 바꾼다.
- **URL 호환성 권고안 A**: query 없는 `/u/{handle}/card.png`와 `?theme=dark`는 dark 객체를 반환한다. `?theme=light`만 light 객체를 선택한다. 저장 선호값은 Share Studio/복사 기본값에 반영하되 기존 query 없는 README의 bytes를 암묵적으로 바꾸지 않는다.
- **media 표현**: publish/refresh는 `en | ko` × `light | dark` 네 immutable PNG revision을 먼저 생성한다. 기존 dark stable key를 유지하고 light stable key를 추가한다. application ETag는 각 PNG bytes digest를 사용한다.
- **공개 커밋 기준점 권고안 A**: light stable object를 먼저 stage한 뒤 기존 dark stable object를 마지막 CAS commit으로 materialize한다. dark metadata에 같은 publication id의 모든 locale/theme pointer를 기록한다. light 요청도 dark authority metadata를 먼저 검증해 publication id가 일치할 때만 light body를 반환한다. 따라서 light stage가 남아도 dark commit 전에는 공개되지 않는다.
- **unpublish**: authority인 dark stable object를 먼저 tombstone 처리해 모든 테마 route를 즉시 404로 닫는다. light stable과 immutable revisions는 cleanup/export 대상이지만 authority 없이 공개하지 않는다.
- **부분 실패와 동시성**: publication id, expected storage ETag와 representation digest를 모든 adapter에서 검증한다. authority commit 전 실패는 이전 publication을 유지하고 staged object는 orphan candidate로 남긴다. authority commit 후 structured visibility 실패는 기존 보상 정책을 테마 전체로 확장한다.
- **UI**: 현재 private preview endpoint의 `theme` query를 재사용해 light/dark 선택을 즉시 미리 본다. 저장 전 draft와 서버 저장값을 구분하고 mutation 중 중복 저장을 막으며, 성공·오류·키보드 접근성 상태를 제공한다.
- **Share 계약**: profile response는 기존 `publicCardUrl`을 유지하고 additive한 `cardTheme`, 테마별 URL 또는 선택 URL 필드를 제공한다. `locale`과 `theme` query를 독립적으로 정규화해 기존 locale 복사 계약을 보존한다.
- **개인정보 경계**: prompts, responses, Codex/OpenAI credentials와 local session 파일은 추가로 수집·저장·전송하지 않는다.

### 통합 검증

- owner가 light/dark preview를 보고 기본값을 저장하면 재로그인과 다른 session에서도 유지된다.
- public 상태에서 기본값 저장만으로 submit 없이 Share/README 복사 URL의 `theme` query가 바뀐다.
- 네 locale/theme representation이 동일 publication id 아래 완성된 경우에만 공개되며 partial state는 fail-closed다.
- query 없는 기존 URL은 dark card와 기존 cache/ETag 계약을 유지한다.
- private/unpublished owner의 모든 변형은 404이고 provider 장애는 generic 503으로 닫힌다.
- cleanup/maintenance plan의 digest와 count가 달라지면 삭제 없이 중단한다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **R2 다중 객체 원자성 부재**: dark stable을 authoritative commit object로 사용하고 light serving이 authority publication id를 검증하도록 해 staged partial object의 공개 노출을 막는다.
- **기존 README 캐시 회귀**: query 없는 URL과 dark stable key를 유지하고 application ETag를 bytes digest로 계속 사용한다.
- **schema rollback 호환성**: 신규 column은 default dark로 additive하게 추가하고 이전 saved version이 해당 column을 무시할 수 있는지 Stage 1에서 검증한다.
- **adapter 계약 확장 폭**: memory, D1, Postgres, native R2, S3 fallback을 같은 contract matrix로 검증하고 구현계획서에서 단계별 변경을 분리한다.
- **cleanup 오삭제**: authority metadata가 참조하는 모든 theme/locale revision을 보호하고 apply 직전 stable metadata를 재검증한다.
- **UI theme 혼동**: 사이트 Appearance와 카드 기본 테마를 별도 명칭·상태로 제공하고, 카드 미리보기만 draft 설정을 따른다.
- **MVP 범위 증가**: font/layout/custom color와 system-aware PNG는 제외하고 light/dark 저장·공개·복사 계약에 한정한다.

## 승인 요청 사항

- 권고안 A: query 없는 기존 URL은 계속 dark를 반환하고, 저장 선호값은 Share Studio/복사 기본 URL에만 `?theme=light|dark`로 반영한다.
- 권고안 A: 기존 dark stable object를 publication authority/commit point로 유지하고 light stable object는 같은 publication id 검증 후에만 serving한다.
- owner별 기본값 `dark`, 별도 `PATCH /api/profile/card-settings`, additive profile response 계약을 승인한다.
- D1뿐 아니라 tested Postgres/S3 fallback, maintenance·cleanup·공식 문서까지 같은 task 범위로 유지한다.
- static PNG의 system theme 자동 감지와 light/dark 외 시각 편집은 제외 범위로 유지한다.

승인되면 `task_m100_74_impl.md`에서 단계별 산출물, 검증 명령, media key/metadata schema와 커밋 메시지를 구체화한다.
