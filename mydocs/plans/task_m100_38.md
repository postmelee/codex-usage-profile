# Task M100 #38 수행계획서

GitHub Issue: [#38](https://github.com/postmelee/codex-usage-profile/issues/38)
마일스톤: M100

## 목적

기존의 기술 정보 중심 `ShareDialog`를, 현재 랜딩의 사용량 카드가 화면
중앙으로 이동하고 나머지 페이지가 어두운 dim·backdrop blur 아래로
물러나는 전체화면 Share Studio로 교체한다. 작업지시자가 2026-07-29에
제공한 참조 화면의 구도, 어두운 깊이감, 중앙 카드 비율, 상단 제목, 우측
닫기와 원형 공유 명령을 현재 제품의 Home 카드에 맞게 재현한다.

Share Studio는 시각적 재현에 그치지 않고 현재 stable image URL, README
Markdown 복사와 PNG 저장을 유지한다. 참조 화면의 X, LinkedIn, Reddit
명령은 외부 API나 이미지 자동 업로드 없이 공개 URL만 넘기는 share intent로
제한한다. desktop, mobile, keyboard와 reduced-motion 환경에서 같은 기능과
privacy 경계를 보장한다.

## 설계 방향

- 기존 `ShareDialog`는 전체화면 `ShareStudio`로 교체한다. Home은 card source
  element 또는 geometry를 전달하고, Studio는 `document.body` portal의 fixed
  layer에서 stacking context와 app 내부 scroll의 영향을 받지 않게 렌더링한다.
- source card는 layout 자리를 유지한 채 전환 중 시각·pointer interaction만
  숨긴다. overlay preview는 같은 `src`, alt, aspect ratio와 rounded geometry를
  사용하고 닫을 때 source rect로 돌아간 뒤 source를 다시 노출한다.
- shared-card motion은 FLIP 계열 transform으로 구현한다. open 시점 source
  `DOMRect`와 responsive target rect를 한 번 측정하고 `transform`과
  `opacity`만 animation한다. viewport resize나 image load로 rect가
  불안정하면 target 위치에서 fade하는 안전한 fallback을 사용한다.
- card 이동이 viewport의 1/3을 넘는 경우 중간 keyframe으로 속도와 거리감을
  나누고, mobile에서는 큰 이동 대신 target card의 fade/scale만 사용한다.
- motion personality는 Premium/Corporate로 고정한다.
  - signature easing: `cubic-bezier(0.2, 0, 0, 1)`
  - quick: 120~160ms, standard: 300~360ms, slow: 420~480ms
  - primary: card의 위치/크기 전환
  - secondary: title과 action row의 50~100ms 후행 fade/translate
  - ambient: overlay dim과 blur의 저강도 settle
  - exit은 entrance의 약 70% duration과 accelerate easing 사용
- reduced-motion에서는 card transfer, stagger와 scale을 제거하고 120~180ms
  opacity transition 또는 즉시 배치를 사용한다. 정보와 focus 순서는
  motion 설정과 무관하게 같다.
- desktop target은 참조 화면처럼 title → card → 원형 action row의 세로축을
  중앙에 놓고 card 너비는 기존 최대 600px와 499:306 비율을 유지한다.
  mobile은 viewport 안에서 card와 action이 겹치지 않게 card를 축소하고 네
  명령을 2×2 또는 가로 scroll 없는 compact grid로 바꾼다.
- X/LinkedIn/Reddit/저장을 큰 원형 primary share row로 배치한다. issue가
  요구하는 Image URL/README Markdown 복사는 같은 화면의 compact secondary
  action으로 보존한다. 따라서 참조 화면의 중심 구도는 유지하되 필수 copy
  기능을 숨기거나 제거하지 않는다.
- share intent helper는 URL과 제목만 encode하는 순수 함수로 두고 provider
  endpoint와 query를 단위 테스트한다. popup blocker 환경에서는 일반
  `<a target="_blank">` navigation으로 동작한다.
- `ko`/`en` copy는 Share Studio 전용 작은 contract로 모으고 stable card
  locale은 기존 `resolveShareLocale()`과 일치시킨다. 별도 i18n framework는
  도입하지 않는다.
- 기존 dialog의 focus trap/restore, Escape, backdrop close와 scroll lock을
  보존하고, 닫기 완료 뒤 최초 Share trigger로 focus를 복원한다. 화면 뒤
  content는 modal open 동안 pointer와 assistive-technology 탐색 대상에서
  제외한다.
- `Make private`는 destructive-looking primary share row와 분리된 secondary
  privacy action으로 유지한다. mutation 성공 시 Studio를 닫고 기존 Home
  private state로 복귀한다.
- 새 dependency를 추가하지 않고 현재 React, CSS와 Playwright 경계에서
  구현한다. animation은 layout-triggering width/height/top/left가 아니라
  transform/opacity를 사용한다.

## 리스크

- **참조 화면과 현재 제품 배경 차이**: 원본 설정 sidebar를 복제하지 않고
  현재 landing을 dim/blur한다. card/title/action의 상대 구도와 어두운
  깊이감을 시각 일치 기준으로 삼는다.
- **같은 카드가 아닌 복제본처럼 보이는 전환**: source rect와 동일한
  preview를 portal에서 시작하고 source는 layout 자리를 유지한 채 숨긴다.
  load/resize race에서는 잘못 이동하는 대신 target fade fallback을 사용한다.
- **긴 이동과 멀미**: 1/3 viewport를 넘는 이동은 중간 keyframe으로 나누고
  mobile/reduced-motion에서는 공간 이동을 제거한다.
- **backdrop blur 지원 차이**: blur가 없는 browser에서도 충분한 dark
  opacity로 읽기·focus 대비를 유지한다.
- **외부 share provider 변화와 popup 제한**: API SDK 대신 일반 HTTPS
  intent link를 사용하고 URL builder를 단위 테스트한다. provider 실패가
  copy/save 기능을 막지 않는다.
- **참조 화면에 없는 copy/privacy 명령**: issue 수용 기준을 지키기 위해
  primary 원형 share row 아래 compact secondary action으로 남긴다. 중심
  구도를 해치지 않는 spacing을 screenshot QA에서 조정한다.
- **mobile 과밀화**: 원형 명령을 축소하거나 2×2 grid로 바꾸되 44px 이상의
  hit target, label과 가로 overflow 부재를 우선한다.
- **focus와 exit animation 경쟁**: exiting state가 끝난 뒤 unmount하고
  source visibility와 trigger focus를 한 순서로 복구한다.
- **#45 release QA 기준 변화**: #38 branch에서만 구현·검증하고 #45 완료 전
  production Site에 배포하지 않는다. #38을 먼저 `devel`에 merge해야 한다면
  #45 전체 회귀 기준 갱신 여부를 작업지시자에게 별도 승인받는다.
- **오늘할일 add/add 충돌**: #45 branch에도 `mydocs/orders/20260729.md`가
  있으므로 후속 branch 통합 시 두 행을 보존하는 수동 merge가 필요하다.
