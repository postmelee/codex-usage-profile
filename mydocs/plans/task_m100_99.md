# Task #99 수행계획서 — Home과 Profile에 최근 업데이트 시각 표시

GitHub Issue: [#99](https://github.com/postmelee/codex-usage-profile/issues/99)
마일스톤: M100

## 목적

Home의 사용량 카드와 소유자·공개 Profile의 사용량이 언제 최종 제출됐는지를
낮은 시각적 위계로 표시한다. 사용자는 카드의 신선도를 바로 판단할 수 있고,
로딩 중이거나 표시할 수 없는 시각을 오해하지 않아야 한다.

기존 owner/public profile 응답의 `usage.uploadedAt`만 사용해 API·DB·migration 계약을
바꾸지 않는다. 표시는 현재 UI locale과 브라우저 시간대를 따르며, 접근성과
기계 해석을 위해 유효한 `<time datetime>` 마크업을 제공한다.

## 배경

- 현재 Home·owner Profile·public Profile은 사용량과 카드는 표시하지만 사용량
  제출 시각은 노출하지 않는다.
- 이미 owner/public profile 응답과 E2E fixture에 `usage.uploadedAt` ISO 시각이 있어
  backend 계약 변경 없이 프론트엔드에서 해결할 수 있다.
- Task #96과 PR #98은 테마 전환·Skeleton 품질 보정으로 마무리됐으며, 최근
  업데이트 표시는 제품 기능이므로 이 이슈로 분리됐다.
- #100·#101이 각각 별도 worktree에서 진행 중이다. #99는 독립 제품 코드와
  자체 문서만 변경하고, 병합 시 공유 테스트·오늘할일 파일 충돌을 재검토한다.

## 범위

### 포함

- `usage.uploadedAt`을 유효성 검사하고 ko/en locale·현지 시간대로 포맷하는 공통 formatter
- `최근 업데이트 · 8월 13일 오전 5:20`, `Last updated · Aug 13, 5:20 AM` 형태의
  locale 문구와 시각 표시
- 유효한 ISO 원문을 `dateTime` 속성으로 유지하는 공통 `<time>` 표시 컴포넌트
- Home의 카드 아래·계정 identity 위 중앙 정렬 표시
- 소유자 Profile과 공개 Profile의 이름·handle 아래 세 번째 정보 행 표시
- loading·사용량 없음·잘못된 timestamp의 비표시 처리와 Profile Skeleton 자리 예약
- mobile, light/dark, reduced motion, ko/en의 표시·레이아웃·전환 회귀 검증
- formatter 단위 테스트와 Home·owner Profile·public Profile Playwright 테스트
- production build·Sites full-stack artifact 검증

### 제외

- “3분 전” 같은 상대 시간 및 주기적 타이머·재렌더링
- API·DB schema·migration·Sites backend 응답 계약 변경
- `capturedAt`을 새 표시 기준으로 사용하거나 `uploadedAt`과 혼합하는 정책 변경
- 공유 카드 PNG, social image, OG metadata의 문구·렌더링 변경
- 기존 테마 transition·Skeleton·share handoff motion의 전면 재설계
- #100 README 카드 URL 설정 자동화와 #101 소셜 미리보기 캐시 실험

## 설계 방향

- `usage.uploadedAt`은 서버가 해당 사용량 제출을 수신한 시각으로 해석하고 모든
  표면에서 동일한 기준을 사용한다.
- 날짜·시각 생성은 `src/profile-ui/formatters.js`의 순수 함수로 두고, 기존 locale
  해석과 `Intl.DateTimeFormat`을 사용한다. timezone은 기본적으로 브라우저 현지값을
  따르되, 단위 테스트가 결정적이도록 formatter option으로 시간대를 주입할 수 있게
  설계한다.
- 포맷터는 null·빈 문자열·무효 날짜·무효 timezone을 안전하게 처리해 오해할
  시각을 노출하지 않는다. 정확한 fallback 계약은 구현계획서에서 테스트 케이스와
  함께 고정한다.
- 표시 컴포넌트는 포맷된 문자열과 원본 ISO 시각을 함께 소유하고, 표시할
  수 없으면 DOM을 만들지 않는다. Home과 Profile은 이 컴포넌트를 공유하여
  문구·시각대·접근성 표현이 달라지지 않게 한다.
- `AccountUsageProfile`이 `usage.uploadedAt`을 Profile identity에 전달하고, owner/public/
  private-owner-preview 모두 같은 `ProfileHeader` 경로를 재사용한다. Home은 인증된
  owner usage가 ready인 경우에만 표시한다.
- Home에서는 업데이트 행을 카드 하단과 identity 사이의 독립된 낮은 위계 행으로
  둔다. Profile Skeleton은 실제 세 번째 identity 행과 같은 높이를 예약하고, Home은
  실제 사용량이 ready가 되기 전에 업데이트 행을 노출하지 않는다.
- 스타일은 기존 `--text-tertiary`와 site theme token을 사용하고, 테마 전환 대상을
  필요한 selector에만 제한한다. 새 위치·불투명도 motion은 추가하지 않고 reduced
  motion에서도 동일한 레이아웃을 유지한다.

## 잠정 단계

- **Stage 1 — timestamp 표시 계약과 formatter 고정**
  - `uploadedAt`의 유효성·locale·timezone·문구 계약을 순수 formatter와 단위
    테스트로 고정한다.
  - 공통 `<time>` 컴포넌트의 유효·무효 렌더링과 locale 문구를 검증한다.
- **Stage 2 — Home 최근 업데이트 표시**
  - Home의 인증 owner usage ready 경로에 카드–identity 사이 표시를 연결한다.
  - anonymous·loading·empty·error에서 시각이 노출되지 않고 mobile·theme·reduced
    motion 레이아웃이 유지되는지 검증한다.
- **Stage 3 — owner/public Profile과 Skeleton 정합**
  - `AccountUsageProfile` 공유 경로로 owner·public·private-owner-preview Profile에 표시한다.
  - Profile identity의 세 번째 행과 Skeleton 자리를 일치시켜 loading→ready 레이아웃
    이동을 방지한다.
- **Stage 4 — 통합 회귀·production artifact 검증**
  - Home·owner/public Profile의 desktop/mobile, ko/en, light/dark, reduced motion 핵심 조합을
    통합 검증한다.
  - 전체 Node·Playwright·production build·Sites artifact 검증과 로컬/모바일 확인 handoff를
    완료한다.

## 리스크

- **timestamp 의미 혼선**: `capturedAt`과 `uploadedAt`이 다른 개념이다. 문구는 사용량
  제출 수신 시각인 `uploadedAt`만 사용하고 상대 시간을 혼합하지 않는다.
- **timezone 비결정성**: 브라우저 시간대에 따라 표시가 달라진다. 포맷터에
  timezone option을 두고 테스트는 명시적 시간대로 고정한다.
- **레이아웃 이동**: Profile identity에 세 번째 행이 추가된다. Skeleton과 ready DOM의
  기하를 동일하게 유지하고 Playwright로 경계 박스를 비교한다.
- **테마 transition 회귀**: 새 tertiary text를 포괄 selector로 넣으면 상태색까지
  과잉 전환될 수 있다. 의미 selector에만 색상 소유권과 transition을 부여한다.
- **병렬 task 충돌**: #100·#101은 각자 독립 worktree에서 진행 중이다. source 직접
  충돌은 낮지만 `mydocs/orders/20260813.md`와 공유 E2E 파일은 병합 순서에서
  열 단위로 재합칠 수 있도록 변경을 최소화한다.
