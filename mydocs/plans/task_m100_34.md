# Task M100 #34 수행계획서

GitHub Issue: [#34](https://github.com/postmelee/codex-usage-profile/issues/34)
마일스톤: M100

## 목적

기존 `/` Home을 Codex usage profile의 실제 랜딩페이지이자 Quickstart 진입점으로 확장한다. 익명 사용자는 서비스의 결과물인 usage card를 확인하고 GitHub 로그인을 시작할 수 있어야 하며, 로그인 사용자는 별도 문서를 찾지 않고 CLI submit, profile 확인, card publish와 README 공유까지 이어지는 다음 행동을 이해할 수 있어야 한다.

별도 `/onboarding` route는 만들지 않는다. GitHub 로그인을 Home에서 시작한 경우 callback 이후 `/`로 돌아와 session-aware Quickstart를 이어가고, 기존 `/profile`, `/settings`, `/device`, `/u/:handle`의 책임과 사용자 흐름은 보존한다.

## 배경

#5에서 packed CLI의 login·submit·status 흐름과 기본 `npx codex-usage-profile@latest submit` 명령을 확정했고, #17에서 device-code login API, #14에서 account menu와 Settings shell, #6에서 stable README card, #32에서 Account Usage Contract v1 기반 공개 profile 경계를 완성했다.

현재 `HomePage`는 sample 또는 owner card와 로그인/Profile 버튼만 표시한다. 익명 사용자는 로그인 뒤 바로 `/profile`로 이동하고, 로그인 사용자는 CLI submit과 card 공유까지의 순서를 Home에서 확인할 수 없다. M100 사용자 흐름을 제품 안에서 연결하려면 기존 card 중심 시각 언어를 유지하면서 로그인 상태별 Quickstart와 복사 가능한 기본 명령을 제공해야 한다.

## 범위

### 포함

- `/`의 `HomePage`를 서비스 결과물과 Quickstart가 함께 보이는 landing 경험으로 재구성
- 실제 sample 또는 로그인 owner card를 첫 viewport의 주요 시각 요소로 유지
- 익명, loading, unavailable, authenticated auth state별 CTA와 안내 상태 정의
- Home에서 시작한 GitHub login의 `redirect_to=/` 적용
- 로그인 사용자의 GitHub identity, Profile과 Settings 진입 경로 제공
- `npx codex-usage-profile@latest submit` 기본 명령과 icon 기반 copy action, 접근 가능한 성공·실패 상태 제공
- device approval, submit, `/profile` 확인, publish, README 삽입 순서를 간결한 Quickstart로 연결
- English copy를 한곳에서 관리하고 향후 locale 추가 시 layout을 깨지 않도록 wrapping·고정 영역 제약 적용
- desktop, mobile, short viewport와 keyboard/focus 동작 검증
- 익명·로그인·copy·navigation·login redirect Playwright 회귀 추가

### 제외

- production 배포, custom domain, storage persistence와 reverse proxy 구성
- npm registry publish, package version과 `private` 설정 변경
- analyzer의 Account Usage 추출 또는 contract 변경
- card PNG renderer, public profile JSON/PNG API와 visibility 계약 변경
- device login backend protocol 또는 credential 저장 정책 변경
- legacy UsageSnapshot v2와 compatibility UI 제거
- 별도 `/onboarding` route 추가
- 새로운 branding logo, illustration 또는 외부 이미지 제작

## 설계 방향

- 기존 `HomePage`, `ProfileShell`, `AccountMenu`, profile API client와 card asset을 우선 재사용한다. landing을 별도 application이나 route로 분리하지 않는다.
- 첫 화면은 실제 card와 문자 그대로의 제품명, 짧은 가치 설명, 현재 auth state에 맞는 단일 primary action을 중심으로 구성한다. Quickstart의 다음 section이 일반 desktop·mobile viewport에서 일부 보이도록 높이와 간격을 제약한다.
- 익명 Home CTA는 `/`로 돌아오는 GitHub login URL을 사용한다. `/profile`에서 시작한 로그인은 기존처럼 `/profile`로 돌아가므로 route별 return intent를 섞지 않는다.
- authenticated 상태에서는 GitHub identity를 표시하되 account menu와 중복되는 장식 card를 만들지 않는다. Profile은 명시적 command link, Settings는 기존 account menu를 통해 접근 가능하게 유지한다.
- Quickstart는 `submit`이 credential 부재 시 device approval을 시작한다는 현재 CLI 동작을 기준으로 한다. 기본 명령에서 `--yes`를 사용하지 않으며 CI·자동화 명령은 이번 landing 범위에서 강조하지 않는다.
- copy action은 familiar copy icon과 tooltip/accessible label을 사용하고, clipboard 성공·실패는 `aria-live` 상태로 전달한다. command text와 status가 버튼 크기나 page layout을 이동시키지 않도록 안정적인 영역을 둔다.
- onboarding copy와 step metadata는 component markup에 흩뿌리지 않고 단일 model/constant 경계로 모은다. 이번 task에서 다국어 selector나 번역 framework는 도입하지 않는다.
- 기존 app frame 내부 scrolling 계약을 유지하고 document-level horizontal overflow를 만들지 않는다. page section을 중첩 card로 구성하지 않으며 card preview 자체만 실제 공유 card로 강조한다.
- 사용자 identity와 command 외 credential, token, device 내부 식별자 또는 storage metadata를 Home DOM에 포함하지 않는다.

## 문서 위치 판단

이번 task는 제품 UI 안의 onboarding copy를 구현하며 별도 공식 사용자 문서를 새로 만들지 않는다. CLI 상세 진실 원천은 기존 `docs/cli-submit.md`로 유지한다. 구현 중 현재 CLI 동작과 문서가 충돌하는 경우에만 동일 파일을 최소 수정하고, landing 전용 중복 문서는 만들지 않는다.

## 리스크

- **미배포 CLI 명령 노출**: 현재 package release는 별도 task 범위다. landing은 M100의 확정 명령을 표시하되 실제 registry publish가 완료됐다고 오인시키는 상태 문구를 추가하지 않는다.
- **로그인 redirect 회귀**: Home CTA만 `/` 복귀를 사용하고 Profile·Settings의 current-path return 동작을 단위·E2E로 고정한다.
- **첫 viewport 과밀화**: card, CTA와 Quickstart 전체를 한 화면에 강제로 압축하지 않고 다음 section의 시작만 보이도록 responsive constraints를 사용한다.
- **copy와 layout 결합**: English 문자열 길이에 맞춘 고정 폭을 피하고 wrapping, `min-width: 0`, stable control dimensions로 향후 locale 확장을 준비한다.
- **Clipboard API 제한**: unavailable/rejected 상태를 처리하고 명령 text 자체는 항상 선택 가능한 fallback으로 남긴다.
- **기존 app shell 회귀**: Home 변경을 `HomePage` 소유 범위에 제한하고 shared `ProfileShell` 변경은 필요한 navigation/accessibility 보강만 허용한다.

## 승인 요청 사항

- 별도 `/onboarding` route 없이 `/`을 landing과 Quickstart의 단일 진입점으로 사용하는 방향
- Home에서 시작한 GitHub login만 `/`로 복귀하고 기존 route별 login return intent를 유지하는 방향
- 기본 명령은 `npx codex-usage-profile@latest submit`이며 `--yes`를 포함하지 않는 범위
- 신규 공식 문서를 만들지 않고 `docs/cli-submit.md`는 충돌이 확인될 때만 최소 수정하는 문서 위치 판단
- production deployment, npm publish, persistence와 analyzer 변경을 제외하는 범위

승인되면 `task_m100_34_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지를 구체화한다.
