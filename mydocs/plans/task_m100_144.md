## 목적

현재 `devel`에 병합됐지만 canonical production에는 반영되지 않은 Task #141의 라이트
소셜 썸네일 경계 대비 보정과 Task #39의 웹 전용 Animated GIF 생성·저장 기능을 하나의
exact release source로 `main`, stage5, production에 순서대로 승격한다. Task #137의 npm
`0.1.4` release handoff 기록도 같은 `devel` 누적 범위에 포함하되 이미 게시된 npm version과
tag는 변경하거나 재게시하지 않는다.

배포 후보는 PR #140, #142, #143을 포함하는 `devel`
`aaf997720f296265c8b306840f0eb8af67b08dfb`로 고정한다. Local certification과
`devel → main` release PR을 통과한 exact main commit을 stage5 owner-only에서 먼저 검증하고,
동일 source와 migration manifest만 기존 public production에 temporary application
maintenance를 사용해 배포한다.

- 승인된 candidate는 `aaf997720f296265c8b306840f0eb8af67b08dfb`다. Stage 1 시작 전에

  병합되어 있으므로 별도 checkpoint PR 없이 검증된 `devel`을 release PR로 `main`에 승격한다.
- release PR은 `devel → main`, merge commit 방식으로 처리하고 merge된 main tree가 승인 후보 tree와
  정확히 같은지 비교한다. task branch 문서 commit은 production artifact source에 섞지 않는다.
- GitHub/npm tag 또는 package version은 새로 만들지 않는다. 현재 npm `0.1.4`의 production origin
  compatibility만 검증한다.

### Target 분리와 원격 Gate

- production project는 `appgprj_6a83ecc3c4c08191bda7f14d7c26c974`, stage5 project는
  `appgprj_6a62f58721788191a7cd82f37320f244`다. target role, project, origin, D1/R2 logical
  binding과 exact source 중 하나라도 다르면 save 전에 중단한다.
- **Gate A — candidate certification**: local 검증과 focused image/GIF 회귀를 통과해야 한다.
- **Gate B — main release**: release PR checks와 exact tree 대조 뒤 main source를 고정한다.
- **Gate C — stage5 owner-only**: 별도 승인 뒤 saved version, owner-only deployment,

- **Gate D — production save**: production baseline과 rollback 후보를 읽기 전용으로 기록하고 동일

- **Gate F — production smoke/handoff**: public access를 유지하며 비파괴 사용자 흐름과

## 리스크

- **후보 drift**: `devel`에 새 merge가 생기면 범위를 자동 확장하지 않고 merge 목록과 새 SHA를 제시해 재승인받는다.
- **release tree 불일치**: main merge tree가 후보와 다르면 tag·save·deploy를 하지 않고 release PR 상태를 조사한다.
- **cross-target 배포**: target role, project, origin, binding 또는 source mismatch는 archive save 전 fail closed한다.
- **public production write 경쟁**: access policy를 변경하지 않고 application maintenance만 사용하며, readiness와 safe baseline 복원 전 공개 smoke를 하지 않는다.
- **durable data 손상**: 신규 migration·data disposal을 금지하고 drift를 임의 보정하지 않는다. active deletion operation이 있으면 deployment/rollback을 중단한다.
- **브라우저 GIF 자원 사용**: synthetic 또는 비파괴 사용자 흐름에서 완료·오류·취소 경계를 확인하고 외부 게시나 대용량 반복 생성을 하지 않는다.
- **외부 crawler 배경 차이**: application pixel/metadata와 플랫폼 UI 결과를 분리하며 provider cache의 즉시 갱신을 성공 조건으로 두지 않는다.
- **Sites public 배포 권한**: 기존 Site가 public이므로 exact URL과 public access를 제시하고 작업지시자의 명시적 승인을 받은 뒤에만 live deployment를 실행한다.
- **rollback 호환성**: additive migration 1..6과 active operation을 확인한 뒤에만 이전 application version을 사용하며 schema/data rollback은 별도 승인 없이는 하지 않는다.
