# Task M100 #12 수행계획서

GitHub Issue: [#12](https://github.com/postmelee/codex-usage-profile/issues/12)
마일스톤: M100

## 목적

GitHub 계정으로 로그인한 사용자가 로컬 CLI submit 흐름을 승인하고, 서버가 owner/account, CLI token digest, latest snapshot을 durable store에 유지할 수 있는 runtime 기반을 만든다.

이번 task는 M100 MVP 흐름 중 `GitHub login -> CLI auth 승인 -> snapshot 저장/조회 runtime` 구간을 담당한다. 후속 #5 CLI와 #6 README 카드 endpoint가 실제 사용자 계정에 연결될 수 있도록 session, persistence, runtime 보안 경계를 고정한다.

## 배경

#4에서 GitHub identity 기반 owner/account, CLI login challenge, API token, snapshot submit/public lookup의 backend contract와 in-memory store가 구현됐다. 다만 #4는 domain/API contract 중심이었고, 실사용 MVP에 필요한 GitHub OAuth start/callback, browser session, durable persistence, runtime adapter, 보안 hardening은 제외됐다.

M100 milestone에는 "누구나 GitHub 계정으로 로그인하고, 로컬 터미널에서 `npx codex-usage-profile@latest submit`으로 사용량 snapshot을 업데이트하며, 웹 프로필과 README 카드 이미지가 최신 snapshot을 반영한다"는 사용자 흐름이 명시됐다. #12는 이 흐름의 계정/runtime 기반을 먼저 완성한다.

## 범위

### 포함

- GitHub OAuth start/callback route 또는 동등한 runtime handler
- OAuth state/CSRF 검증과 callback error handling
- session cookie 생성, 검증, logout 처리
- authenticated `/me` 또는 동등한 session/account API
- 로그인한 owner가 pending CLI login challenge를 승인하는 화면/API 연결
- durable store interface와 최소 adapter 구현
- owner, CLI challenge, CLI token digest, latest snapshot persistence 검증
- 환경 변수/config 경계: GitHub OAuth client id/secret, session secret, public base URL
- runtime 보안 점검: token 원문 장기 저장 금지, cookie option, visibility boundary

### 제외

- npm CLI package와 `npx ... submit` 구현: #5
- README 카드 PNG renderer와 Share snippet UI: #6
- plugin/skill icon metadata enrichment: #8
- GitHub README 파일 자동 commit/push 기능
- OpenAI 계정 OAuth 로그인
- 결제, 팀/조직, 장기 히스토리 분석
- production hosting provider 선택과 배포 자동화 전체

## 설계 방향

- #4의 `profile-backend` domain service를 유지하고, runtime adapter를 얇게 추가한다.
- OAuth provider network 호출은 injectable client 경계를 유지해 테스트에서 fake client로 검증한다.
- session은 raw OAuth token을 장기 저장하지 않고, service-owned session id 또는 signed cookie 중심으로 설계한다.
- CLI token은 원문 1회 반환, 서버 저장은 digest-only 원칙을 유지한다.
- durable store는 기존 memory store interface와 의미가 맞도록 구현하고, restart simulation 테스트가 가능한 형태를 우선한다.
- profile 공개 조회와 card 후속 소비자는 visibility가 public인 latest snapshot만 접근할 수 있어야 한다.
- 외부 사용자가 직접 따라야 하는 문서는 이번 task에서 README의 최소 개발 설정 보강까지만 검토하고, 정식 API 문서 루트는 별도 task 전까지 선택하지 않는다.

## 잠정 단계

- **Stage 1 — Session/OAuth runtime contract**
  - GitHub OAuth start/callback, state 검증, session cookie 정책의 service 경계를 설계/구현한다.
  - fake GitHub client 기반으로 callback success/failure, state mismatch, logout을 검증한다.
- **Stage 2 — Durable store adapter**
  - owner, challenge, CLI token digest, latest snapshot을 restart 이후에도 유지하는 최소 durable adapter를 구현한다.
  - 기존 memory store contract와 동일한 동작을 테스트하고 restart simulation을 추가한다.
- **Stage 3 — Authenticated account와 CLI challenge 승인 연결**
  - `/me` 또는 동등한 account API와 로그인 사용자 기반 challenge approve flow를 runtime에 연결한다.
  - unauthenticated/expired/private visibility 경계를 검증한다.
- **Stage 4 — Web/runtime integration과 설정 문서**
  - frontend 또는 API client가 session/account 상태를 확인할 수 있는 경계를 연결한다.
  - README에 OAuth/session/durable store 실행 설정과 보안 주의점을 최소 범위로 정리한다.
- **Stage 5 — 통합 보안 검증과 MVP handoff**
  - #5/#6이 사용할 runtime contract를 확인하고, secret 저장 방지 grep과 전체 테스트/build를 실행한다.
  - 남은 배포/운영 리스크를 최종 보고서에 기록한다.

### 통합 검증

- GitHub OAuth login 이후 owner/account가 생성 또는 조회된다.
- session 확인 API가 로그인 상태를 반환하고 logout 후에는 인증 실패한다.
- 로그인 사용자가 CLI login challenge를 승인할 수 있다.
- CLI token 원문은 1회 반환되고 저장소에는 digest만 남는다.
- durable store adapter에서 owner/token/snapshot이 restart 이후에도 유지된다.
- public profile lookup은 public latest snapshot만 반환하고 private profile은 노출되지 않는다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **OAuth/session 보안 범위 확대**: state/CSRF, cookie option, callback error handling이 누락되면 MVP 신뢰성이 떨어진다. Stage 1에서 보안 test를 먼저 고정한다.
- **durable store 과설계**: production DB까지 확정하려 하면 task가 커진다. 최소 adapter와 interface 안정화를 우선하고 hosting/provider 선택은 제외한다.
- **CLI와 runtime 경계 불일치**: #5가 필요한 token exchange contract와 #12 구현이 어긋날 수 있다. Stage 5에서 #5 handoff 항목을 명시한다.
- **문서 공식화 과잉**: 정식 API 문서 루트를 이번 task에서 만들지 않는다. README에는 로컬 실행/보안 설정 최소 안내만 둔다.

## 승인 요청 사항

- #12 범위를 GitHub OAuth/session/durable runtime으로 한정하고, CLI package 구현은 #5, README card endpoint는 #6으로 유지하는 것을 승인해 달라.
- durable store는 production hosting/provider를 확정하지 않고 최소 adapter와 restart 검증 중심으로 진행하는 것을 승인해 달라.
- README는 OAuth/session env와 보안 주의점의 최소 개발 안내만 갱신하고, 정식 API 문서 루트는 이번 task에서 만들지 않는 것을 승인해 달라.

승인되면 `task_m100_12_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지를 구체화한다.
