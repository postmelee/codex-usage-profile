# Task M100 #13 수행계획서

GitHub Issue: [#13](https://github.com/postmelee/codex-usage-profile/issues/13)
마일스톤: M100

## 목적

이 task의 목적은 #12에서 구현한 framework-neutral backend HTTP handler를 실제 로컬 개발 서버에 연결해 GitHub OAuth login/callback/session 흐름을 브라우저에서 직접 검증할 수 있게 만드는 것이다.

완료 후에는 frontend preview와 `/api/*` runtime이 같은 origin에서 동작하거나 명확한 proxy 구조로 연결되어야 한다. 사용자는 로컬 GitHub OAuth App 설정을 넣고 `/api/auth/github/login`에서 GitHub authorization page로 이동한 뒤 callback, session cookie, `/api/auth/me` 조회까지 smoke test할 수 있어야 한다.

## 배경

- #12는 GitHub OAuth state, session cookie, durable store, authenticated CLI challenge approve contract를 구현했다.
- 현재 `npm run dev`는 Vite frontend preview만 실행한다. 따라서 `/api/auth/github/login`, `/api/auth/github/callback`, `/api/auth/me`를 실제 브라우저에서 처리할 host adapter가 없다.
- M100 후속 #14 로그인 계정 UI, #5 CLI submit, #15 token/device 관리, #6 README card endpoint는 실제 local runtime에서 auth/session이 검증된 뒤 진행하는 것이 안전하다.

## 범위

### 포함

- 로컬 host adapter/server 또는 Vite proxy 구조 선택 및 구현
- `createProfileBackendHttpHandler()`를 `/api/*` 요청에 연결
- GitHub OAuth code exchange client wiring
- runtime env 설정 연결
  - `GITHUB_CLIENT_ID`
  - `GITHUB_CLIENT_SECRET`
  - `PUBLIC_BASE_URL`
  - `PROFILE_STORE_FILE`
  - `SESSION_SECURE_COOKIES`
- local 개발 실행 script 또는 dev server 구성 보강
- 직접 로그인 smoke test 절차 문서화
- 가능한 범위에서 fake OAuth client 기반 자동 테스트와 실제 GitHub OAuth 수동 검증 경로 분리

### 제외

- 로그인 계정 버튼, account menu, settings 화면 UI 구현
- CLI `npx ... submit` 구현
- API token create/revoke와 device list/rename 구현
- README card PNG endpoint와 GitHub README cache 갱신 전략 구현
- production hosting, production DB, rate limit 최종 선택

## 설계 방향

- 기존 `createProfileBackendHttpHandler()` contract를 유지한다. host adapter는 `Request`를 받아 `Response`를 반환하는 backend handler를 감싸는 얇은 layer로 둔다.
- local dev에서는 frontend와 API가 같은 origin으로 보이는 구성을 우선한다. cookie 검증과 OAuth callback URL이 단순해지기 때문이다.
- 실제 GitHub OAuth secret은 source에 저장하지 않는다. env 기반으로만 주입하고 `.env.example` 또는 README에는 placeholder와 설정 방법만 기록한다.
- OAuth code exchange client는 host adapter 영역에서 구현하고, test에서는 fake GitHub client를 주입해 네트워크 없이 callback/session contract를 검증한다.
- durable store는 #12의 `createFileProfileBackendStore()`를 재사용한다. local 개발용 기본 경로는 git ignore 대상 또는 임시 디렉터리 정책을 함께 확인한다.
- 직접 GitHub OAuth smoke test는 사용자 환경의 GitHub OAuth App 설정이 필요하므로 자동 검증과 분리해 수동 검증 절차로 기록한다.

## 잠정 단계

- **Stage 1 — Host adapter 구조 확정과 fake runtime test**
  - host adapter/server 구조를 선택하고 backend handler를 local Request/Response 흐름에 연결한다.
  - fake GitHub client로 `/api/auth/github/login`, callback, `/api/auth/me` route를 자동 테스트한다.
- **Stage 2 — 실제 GitHub OAuth client wiring과 env 문서**
  - GitHub OAuth token exchange/user lookup client를 env 기반으로 연결한다.
  - README와 env 예시에 local OAuth App 설정, callback URL, secret 보관 정책을 기록한다.
- **Stage 3 — Local dev 통합과 browser smoke path**
  - local dev script 또는 proxy 구성을 정리해 frontend profile preview와 `/api/*`가 함께 동작하게 한다.
  - 가능한 경우 브라우저에서 login URL redirect/session 상태를 확인하고, 실제 OAuth App secret이 없으면 수동 검증 절차와 한계를 기록한다.
- **Stage 4 — 통합 검증과 handoff**
  - full test/build, secret scan, diff check를 실행한다.
  - #14/#5/#15/#6이 이어받을 local runtime contract와 남은 운영 리스크를 정리한다.

### 통합 검증

- 로컬에서 `/api/auth/github/login`이 GitHub authorization URL로 redirect된다.
- GitHub callback 이후 session cookie가 설정되고 `/api/auth/me`가 owner/session을 반환한다.
- OAuth access token 원문과 GitHub client secret이 source, docs, durable store에 저장되지 않는다.
- frontend profile preview는 `/u/meleeisdeveloping` 기존 동작을 유지한다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **실제 OAuth App 설정 의존**: GitHub OAuth client id/secret과 callback URL은 사용자 환경 설정이 필요하다. fake client 자동 테스트와 수동 smoke test를 분리한다.
- **cookie same-origin 문제**: frontend/API origin이 분리되면 session cookie 검증이 복잡해진다. local dev는 같은 origin 또는 명확한 proxy를 우선한다.
- **secret 노출 위험**: `.env`는 git ignore 대상이어야 하며 문서에는 placeholder만 둔다. PR 전 credential-like scan을 실행한다.
- **host adapter 과설계**: production hosting 최종 선택은 제외하고 local runtime 검증에 필요한 최소 adapter로 제한한다.
- **기존 Vite preview 회귀**: `/u/meleeisdeveloping` fixture preview와 public snapshot fallback이 깨지지 않도록 build/test와 브라우저 확인을 유지한다.
